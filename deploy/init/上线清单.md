# DevStudio 上线清单（deploy/init 初始化包）

适用场景：**全新环境上线**。已有环境的日常升级不走本包，仍按 `deploy/deploy.sh` 流程使用 `sql/` 增量脚本。

## 包内容

| 文件 | 作用 | 是否必选 |
|---|---|---|
| `01_schema_full.sql` | 完整基线 DDL（35 张表，等于 `sql/01-30` 增量链整体重放，可重复执行） | 必选 |
| `02_seed_yunying.sql` | 「运营研发部」初始化种子数据（9 项目 / 11 分类 / 174 需求 / 324 工作项 / 10 版本 / 7 成员账号） | 可选 |
| `上线清单.md` | 本文档 | — |

种子数据由 `tools/gen_seed_yunying.py` 从《运营研发项目看板.xlsx》生成，映射口径与已知缺口（29 个工作项无项目归属、43 个无分类、部门日报不导入）见生成脚本头部注释。

## 一、前置条件

- [ ] 服务器已装 JDK 8、MySQL 8、Nginx；不需要 Redis（单实例部署）
- [ ] 时区为北京时间（日期判定、周回顾、每日推送都依赖）：`sudo timedatectl set-timezone Asia/Shanghai`
- [ ] 本地可打包：项目根目录 `mvn -e -DskipTests package`，产出 `target/devstudio-server.jar`

## 二、数据库初始化

```bash
# 1) 建表（全新部署只需这一个文件）
mysql -uroot -p --default-character-set=utf8mb4 < deploy/init/01_schema_full.sql

# 2) 建专用数据库账号（密码换成强密码，应用只从 localhost 连）
mysql -uroot -p -e "CREATE USER 'devstudio'@'localhost' IDENTIFIED BY '更换为强密码'; GRANT ALL PRIVILEGES ON devstudio.* TO 'devstudio'@'localhost'; FLUSH PRIVILEGES;"
```

- [ ] `mysql -uroot -p -e "SHOW TABLES FROM devstudio;"` 返回 35 张表

## 三、应用部署与环境变量

按 `deploy/README.md` 第 1-4 节执行（运行用户、上传 jar、`/etc/devstudio.env`、systemd 起服务）。要点：

- [ ] `/etc/devstudio.env` 至少包含 `DB_PASSWORD`、`AUTH_USER`、`AUTH_PASSWORD`（仅首次启动引导管理员用）
- [ ] `sudo systemctl enable --now devstudio` 后 `systemctl status` 为 active
- [ ] **启动一次让应用引导创建管理员账号**（库中无用户时自动创建；`AUTH_PASSWORD` 未配置则临时密码打印在控制台，登录后重置）

## 四、导入种子数据（可选）

> 前提：库中已存在 `role='admin'` 的账号（种子成员沿用管理员密码哈希）。因此必须**先完成第三节首次启动**，再执行本节。

```bash
mysql -u<用户> -p --default-character-set=utf8mb4 devstudio < deploy/init/02_seed_yunying.sql
```

- [ ] 导入命令执行无报错（脚本幂等，重复执行会先删 Yy/SYy 前缀旧数据再重灌，不影响其他数据）
- [ ] **安全项**：7 个成员账号（程洪昌/施亚彬/马远/张亮/孔祥劲/肖威/周劲松）初始密码与管理员相同，上线后由成员登录自行改密，或管理员在「用户管理」重置
- [ ] 若不需要这批演示数据，跳过本节不影响系统功能

## 五、Nginx 与暴露面

- [ ] `sudo cp deploy/nginx-devstudio.conf /etc/nginx/conf.d/devstudio.conf` 后改 `server_name`，`nginx -t && systemctl reload nginx`
- [ ] `ss -tlnp | grep -E ':(8080|3306)'` 仅监听 127.0.0.1；云防火墙只放行 22/80/443
- [ ] 有域名时配 HTTPS（PWA「添加到主屏幕」的前提）：`sudo certbot --nginx -d 你的域名`

## 六、备份

- [ ] 按 `deploy/README.md` 第 8 节安装 `backup.sh` + crontab（每天 03:00）
- [ ] 手动跑一次并验证备份文件可恢复到空库

## 七、上线验收

基础功能走 `deploy/README.md` 第 11 节验收清单，以下为初始化包专项：

- [ ] `curl -s http://127.0.0.1:8080/api/health` 返回 `"db":"up"`
- [ ] 管理员登录 → 侧栏空间切换器出现「运营研发部」
- [ ] 「运营研发部」内：9 个项目、需求池 174 条、看板/列表 324 个工作项（含 47 个缺陷）、流程引擎项目下 10 个版本
- [ ] 「用户管理」可见 7 个成员账号；任一成员账号可登录（初始密码同管理员，登录后改密）
- [ ] 成员登录后默认落在「运营研发部」空间，能看到本人负责的工作项
- [ ] 管理端报表页有数据（版本归属 117 条、完成快照 237 条）

## 八、后续升级与回滚

- 升级：看发布说明，涉及表结构的在服务器执行对应 `sql/` 增量脚本（幂等），再换 jar 重启；或直接 `bash deploy/deploy.sh`（自动判断）。
- 回滚：`bash deploy/deploy.sh --rollback` 回到最近一次 jar 备份；数据库用第六节的每日备份恢复。
- 种子数据如需按新口径重新生成：改 `tools/gen_seed_yunying.py` 后重跑生成器，产物回填本目录。
