## 1. 你将运维的系统长什么样

沙漏是面向小型项目制研发团队的自托管研发交付工作台，当前采用单实例部署。减少运行组件有助于控制复杂度，不代表免维护或自动满足合规要求：

![沙漏·技术架构](diagrams/tech-architecture.png)

- **一个 jar + MySQL 8**，没有 Redis、MQ、对象存储——少一个组件就少一类故障。
- **前后端分离但同源**：前端零构建，Nginx 直接托管 `frontend/`；后端只提供 `/hourglass/api/**`。同源保证会话 Cookie、CSRF 与 SSE 行为不变。
- **进程内缓存**（成员关系 60 秒 TTL、空间 meta 版本号失效）是「不用 Redis」的代价——因此**定位单实例**，多副本部署需改造缓存层，不要直接横向扩。

运维要点：

- **每日备份建议**：`deploy/backup.sh` + crontab（03:00）；生产每日 cron 尚未确认安装，不称已配置。只按行读取 env 文件的 `DB_NAME`/`ATTACH_DIR`，不会执行其中的值；附件目录打包失败会**非零退出**（cron 日志可见），不会假成功。

- **升级到「成员公司与项目角色标注」版本**：先全库备份，执行 `sql/68_member_company_project_role.sql`，**再**替换 jar（新 jar 会读取 `workspace_member.company_name` 与 `project_member_role` 表，缺结构会让成员列表和项目花名册报错）。68 幂等、只增列建表，不回填、不改权限；执行后全库 55 张表，备份与恢复范围需包含新表。
- **升级到「成员职能与项目兼岗」版本**：先全库备份，执行 `sql/69_member_job_title_role_options.sql`，**再**替换 jar。69 幂等、只增列建表，不回填、不改权限；执行后全库 56 张表，备份与恢复范围需包含新表。
- **升级到「版本终态、承诺基线、项目里程碑」版本**：先全库备份，按 `sql/78_version_end_state.sql`、`sql/79_version_commitment.sql`、`sql/80_project_milestone.sql` 顺序执行，**再**替换 jar。78 只增列；79 新增承诺基线表；80 新增三张里程碑表，并把存量 `task.is_milestone=1` 一次性映射为人工确认型里程碑（保留旧列兼容）。执行后全库 61 张表；执行 `sql/81_delivery_note.sql` 后为 64 张表。备份与恢复范围需包含这七张新表；JSON 任务备份不含里程碑与交付说明，迁移后需重建。

### 3.2 JSON 任务备份的需求排期兼容

- JSON 只搬运工作数据，保留任务 versionIds 数组、version.startDate、需求日期与 canceled；版本 / 任务引用按目标项目重新映射，不转移正式发布证据。demands[].plannedStart / plannedEnd 是可空的 yyyy-MM-dd 字符串，旧备份缺字段 / null / 空白为空，允许单边日期，不从任务或版本日期推导。
- 导入区分两种情况：原始无目标的 `plan` 需求保留 `plan` 状态与计划起止；原始显式非空目标 ID 重映射后必须有效且属于需求所在项目，目标丢失 / 映射无效时置空，仅此类 `plan` 需求按原规则回到 `pass` 并清计划起止。`canceled` 状态保持，不自动恢复已取消需求或重排关联任务。
- 所有非空计划日期的格式与起止顺序在任何覆盖删除前校验，非法日期或开始晚于结束返回 400，原数据不被删除；即使目标映射失败也不能跳过日期校验。
- 发布记录页面可导出不可变条目快照 CSV；发布历史日志可查询，但没有发布历史 JSON 导出。任务 JSON 不能覆盖已有成功发布或其他计划 / 历史证据，仍应导入新空间；正式证据恢复使用 MySQL 全库备份。

### 3.3 成员公司与项目角色标注（SQL 68）

- `sql/68_member_company_project_role.sql` 为 `workspace_member` 增 `company_name varchar(64) NULL`，并创建 `project_member_role`（主键 `workspace_id + project_id + user_id`，`role_title` ≤32 字）。脚本可重复执行，只增结构，不回填历史；执行后全库 55 张表。
- 公司是空间级自由文本，项目角色是「成员 × 项目」的唯一主角色。两者只用于展示、筛选与负责人分组，**不进入任何鉴权 SQL/Java**，不改变既有可见范围、任务与工时权限。
- 成员移出空间或项目、项目删除、空间删除时，同事务清理对应角色行；全库备份须包含 `project_member_role`。JSON 任务备份不搬运公司与项目角色，迁移后需重新标注。
- `sql/69_member_job_title_role_options.sql` 为 `workspace_member` 增 `job_title`、为 `project_member_role` 增 `secondary_role_titles`，并创建 `workspace_member_label_option` 标签字典；只增结构、不回填历史，执行后全库 56 张表。
- 旧 jar 不读取新增列与表，软件回退可保留结构；但新 jar 不能在未执行 68 / 69 的库上运行。

### 3.4 需求人工交付判定（SQL 76）

- `sql/76_demand_delivery_judgement.sql` 幂等创建 `demand_delivery_judgement`，只增表、不回填、不修改 `demand` 派生字段；执行后全库 57 张表；随后的 `sql/79_version_commitment.sql` 与 `sql/80_project_milestone.sql` 分别创建承诺基线表与三张里程碑表，`sql/81_delivery_note.sql` 再创建三张交付说明表，完整基线为 64 张表。
- 判定为追加式记录：每条含生效阶段（`donePending` / `delivered`）、生效日期、原因、判定人、判定时间与目标版本快照；每需求最多一条生效记录，由生成列 `active_demand_id` 与唯一索引保证。修改判定先撤销旧记录再追加新记录，撤销字段与原因完整保留。
- 真实生产发布证据始终优先；仅在没有真实发布时才采用人工「已交付」的生效日期。判定绑定当时的目标版本，需求换版本后旧判定不参与派生；撤销后立即恢复自动派生。
- 只有空间主、管理员或项目负责人可以写入，写操作使用项目锁、需求当前读与 `revision` CAS；普通成员只读。接口见《接口契约》需求池端点。
- 需求删除、项目删除、空间清空与备份覆盖导入会在同一事务清理该表；JSON 备份不包含人工判定，导入后不会复活旧判定。
- 升级顺序：先全库备份，执行 `sql/76_demand_delivery_judgement.sql`，再替换 jar。历史交付证据仍优先用 `sql/73` 按真实发布时间补录，不批量制造人工判定；没有 `released_at` 的条目由管理者核对后在详情中人工判定。

## 4. 统计方式与日常运维责任

统计数字的产生方式决定了运维负担：

![沙漏·数据流转](diagrams/data-flow.png)

- 工时、燃尽、负载**直读事实表**（`time_log` / `task_log`），减少第二套汇总数据的同步漂移；仍应检查筛选、日期范围和当前指标 / 历史快照的差异，不能保证永不出现统计缺陷。
- 补记、作废后按规则重算，完成快照按实现同步刷新；已确认发布快照不随当前任务变化而改写。
- 查询开销随记录规模、并发与时间范围变化。50 人 / 2C4G 是部署参考，本轮未重新压测，实际容量要用自己的数据验证。

巡检至少包括：**磁盘与附件增长、备份成功及恢复可用性、数据库连接和慢查询、SSE 连接、服务错误、证书到期、依赖漏洞与账户权限**。软件回滚不等于数据库回滚，升级前需检查结构兼容与完整恢复方案。

系统已有最小安全审计：管理员可检索登录、权限变更、导出 / 恢复及删除等事件并导出 CSV；默认保留 90 天，可配置。审计写入失败记录错误但不阻断业务，不是外部防篡改或完整合规保证。应核对事件覆盖、保存期限与备份策略；不要把工作项时间线当作系统安全审计。

## 5. 通知与 AI 配置

**提醒推送**（可选）按空间配置：环境变量只保留渠道与开关（`NOTIFY_TYPE=webhook|serverchan|pushplus`、`NOTIFY_CRON`），具体地址由空间主在「空间设置」里维护。安全边界：地址校验仅 http/https 且拒绝内网；pushplus 渠道下 token 只发往官方端点。

**AI 助手**（可选）：每个用户在个人设置里自配模型地址、密钥与额度，密钥加密保存。出站地址限制拒绝内网与云元数据等目标，用于降低 SSRF 风险，**不是阻止业务内容发送给外部模型**。启用外部 AI、邮件或机器人时，应明确可能发送的数据、服务商与允许范围；敏感环境可禁用相应能力，并验证实际出站与第三方组件行为。企业微信 webhook 是通知渠道，不等于已具备企微免登。

## 6. 常见故障速查

| 症状 | 先查 |
| --- | --- |
| 登录后空白 / 接口 404 | Nginx 反代前缀是否 `/hourglass/api/`；前端与 API 是否同源 |
| 权限变更不生效 | 进程内缓存 TTL（最长 60 秒 + meta 300 秒兜底）；**重启即清** |
| 推送收不到 | `/api/notify/test`；空间 webhook 是否已填；渠道环境变量 |
| 定时推送时间不对 | 服务器时区（`timedatectl`，日期判定/周回顾都依赖它） |
| 备份失败 | `/var/log/hourglass-backup.log`；附件目录存在且可写 |
| 升级后接口报错 | 对应增量 SQL 是否已执行（按发布说明） |
