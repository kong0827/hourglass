## 4. 推荐执行方式

优先走 `deploy/deploy.sh`：脚本按「文件修改时间晚于上次部署」识别增量 SQL，并在第 3 步先备份整库与附件、再按编号顺序执行，最后切换 jar 与前端。

部署前先 dry-run 确认清单：

```bash
bash deploy/deploy.sh --dry-run --host <目标主机>
```

在“数据库脚本”一行必须看到 `sql/105... sql/106... sql/107... sql/108...`。若只列出部分或为空：

1. **停止部署**，不要带 `--sql-all` 绕过；
2. 按第 5 节手工执行缺失脚本，或确认文件时间后重新 dry-run；
3. 重新确认 4 个脚本齐全后再正式部署。

若选择手工执行 SQL，顺序为：全库备份 → 执行 105 → 106 → 107 → 108 → 再替换 jar 与前端（旧 jar 能读新结构，但无法正确展示 `done` 状态，窗口应尽量短）。

```sql

  JOIN project_split_map m ON m.new_project_id=d.req_id AND m.action='split'
```

## 6. 应用层验证

1. 需求池状态筛选出现「已完成」；已完成需求可下钻，交付阶段仍是只读派生（完成 ≠ 交付）。
2. 项目列表出现「流程引擎」项目集：7 个子项目 + 容器「流程引擎-公共」；「其他项目」承接原先未分组项目。
3. 版本、发布、文档仍在容器下；子项目版本页「首版开发」不再被继承日期挤成 0。
4. 工作项 / 需求 / 看板 / 甘特 / 工作列的分类筛选：未选项目时不出现分类维度；选中单个项目后才出现；跨项目旧条件可清除。
5. 项目驾驶舱「分类」面板与设置页分类配置：项目写成员能看到「添加分类」并可改名、排序；删除按钮仅空间主、管理员或项目负责人可用，其余角色有权限提示。
6. 用例导入旧模板（表头「模块」）仍可导入；新导出表头为「分类」。
