# 项目集（项目分组）方案

> 状态：待评审 · 2026-11-17
> 关联原型：[简化版](preview/project-group-redesign-2026-11-17.html) ／ [初版](preview/project-group-preview-2026-11-17.html)
> 说明：当前未提交实现按本方案整体回退后重做；已提交的原型与截图保留。

## 1. 问题与目标

现在一个「项目」同时承担项目边界和模块边界：大项目里各一级模块没法独立排期、独立看发布、独立统计，版本内容只能混在一起，按模块看进度要靠筛选。

目标：

- 引入**项目集**做项目归组，只影响浏览，不改版本、统计、权限的既有口径；
- 把**一级模块升为项目**，让模块能独立排版本、独立看发布；
- 历史数据一次性平滑迁移，工作项、需求、用例、版本、发布记录都不丢、不重、不悬空。

非目标：不新增权限层级；不把二级及以下模块升为项目；不做项目集级发布对象；项目集不是迭代/冲刺。

## 2. 方案对比

| 方案 | 做法 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| A 项目集 + 一级模块升项目 | 空间级哑容器归组；模块变项目 | 版本/统计/权限全部沿用现有项目口径，改动集中 | 需要一次数据迁移 | **采用** |
| B 父子项目树 | 项目支持子项目，权限与版本向下继承 | 层级表达更自然 | 权限、版本、统计都要改继承语义，回归面大 | 暂不采用 |
| C 只做标签分组 | 不迁移数据，仅给项目打分组标签 | 零迁移 | 解决不了模块独立排版本、独立发布 | 不采用 |

选 A 的核心判断：**用户要的是「模块能自己排版本、自己看发布」，不是「多一层管理对象」**。容器方案不动现有领域模型，失败面最小。

## 3. 概念与边界

| 对象 | 定义 | 边界 |
|---|---|---|
| 项目集 | 空间级容器：名称、颜色、排序 | 最多归组项目；空串=未分组；删除只解除归属 |
| 项目 | 沿用现有项目对象，新增「所属项目集」 | 成员、权限、版本、统计口径完全不变 |
| 模块 | 项目内的分类树；仅一级模块可升格 | 排除默认「其他」；二级及以下仍是模块 |
| 版本 / 发布 | 仍以项目为宿主 | 项目集不产生新的发布对象，也不合并发布记录 |
| 用例集 / 文档 / 仓库 / 分支 | 项目级资源 | 不随模块拆分，留在原项目 |

项目集不授予任何权限：集内项目按各自成员可见，看不到的项目不出现在分组里。

## 4. 使用流程

1. **配置**：管理员在项目页打开「管理项目集」，可增、改、删、调整顺序与标识色；删除时提示「集内项目回落未分组，项目本身、版本与统计不受影响」。
2. **归属**：新建/编辑项目时选择一个项目集，默认「未分组」；已有项目不自动改变归属。
3. **浏览**：项目列表顶部按项目集筛选（含「未分组」），列表按集分组展示，项目名旁显示集标签。
4. **版本与发布**：操作仍在项目内完成；需要跨模块查看时，用项目集筛选后分别进入各项目。
5. **迁移**：上线时由管理员在维护窗口执行一次，先预览再执行。

## 5. 历史数据迁移

### 5.1 判定规则

- 项目存在真实一级模块（`parent_id` 为空且名称不是「其他」）→ 拆分；
- 没有真实一级模块 → 项目保持原样、归为未分组，即「项目本身就是模块」。

### 5.2 拆分模型

例：项目「结算平台」有一级模块「清分」「对账」：

- 新建项目集「结算平台」；
- 新建项目「清分」「对账」，各自带原模块子树；
- 原项目保留并改名为「结算平台（未分模块）」，同样归入该集，承载未挂模块的数据与项目级资源。

### 5.3 数据处置

| 数据 | 处置 | 口径 |
|---|---|---|
| 挂模块的工作项 / 需求 / 用例 | 迁到对应新项目 | 模块子树整体迁移，内容不变 |
| 未挂模块的工作项 / 需求 / 用例 | 留原项目 | 仍可从容器进入 |
| 版本 | 复制到有新内容的新项目 | 只带本模块内容；无内容不复制 |
| 版本-工作项关联 | 随工作项迁移 | 不额外复制 |
| 发布记录 | 按快照复制 | 只含本模块工作项，明细数可能少于原记录；不改写历史事实 |
| 发布计划 | 留原项目 | 已迁出的任务从计划范围移除，避免计划编辑校验失败 |
| 版本型里程碑 | 复制 | 人工创建的里程碑不复制 |
| 测试计划 | 随被复制版本复制 | 只带本模块用例，保留计划内执行结果与必测标记 |
| 测试模块 / 用例集 | 留原项目 | 通过容器继续访问 |
| 文档、仓库、分支、交付说明、版本日志 | 留原项目 | 不复制 |
| 需求人工交付判定 | 随需求改指新版本 | 保留判定结论 |
| 编号序列 | 按迁入内容回填 | 避免重新取号撞唯一键 |
| 引用关系（工作项→文档、用例集等） | 不改写 | 仍指向原项目资源，靠容器可见 |

### 5.4 迁移留痕

容器原版本写一条「按模块拆分」操作日志，注明拆到了哪个项目。容器版本内容被拆空时，版本详情页据此提示去向，避免用户以为「工作项凭空消失」。

### 5.5 执行与回退

1. 先执行只读预览，核对将要新建的项目集/项目名单与计数；
2. 备份数据库；
3. 维护窗口内执行数据迁移（单事务，任一步失败整体回滚）；
4. 校验通过后再启动应用。

幂等口径：只处理「未分组」项目，原项目迁移后已归属项目集，重复执行不会二次拆分。

回退口径：迁移完成后仅回退应用无法恢复数据，必须用数据库备份恢复；结构与数据分两个脚本，数据脚本不含结构变更。

### 5.6 迁移后三个关键口径

- **发布检查**：子项目版本必须有自己的测试计划证据，否则「必测」为空——所以计划要随版本复制；
- **用例集计数**：计数、列表、用例详情回显统一按项目过滤，避免「列表里没有、计数里还有」；
- **发布记录**：是历史快照，条目数与原始记录可能不同，不做二次修正。

## 6. 影响面

| 范围 | 影响 | 口径 |
|---|---|---|
| 项目列表 | 增加项目集筛选、分组与标签 | 只改展示，不改数据 |
| 版本 / 发布 | 拆分后各项目独立 | 工作区级统计按项目求和，不重复计数 |
| 测试计划 | 复制后各有独立计划 | 只含本模块用例，执行结果保留 |
| 用例集 | 留在容器项目 | 计数按项目过滤 |
| 统计报表 | 按项目维度不变 | 项目集不是统计维度 |
| 权限 | 不新增层级 | 集不授权；看不到的项目不显示 |
| 交付说明 | 留在容器项目 | 子项目不生成迁移交付说明 |
| 提醒 / 通知 | 不变 | 仍按项目订阅 |
| 移动端 | 可看即可 | 不做专门优化 |

## 7. 风险与对策

| 风险 | 触发场景 | 对策 |
|---|---|---|
| 误拆项目 | 模块命名不规范 | 预览名单 + 人工确认后再执行 |
| 拆分后找不到内容 | 用户习惯在原项目找 | 容器保留 + 拆分日志 + 手册说明 |
| 发布检查断链 | 子项目版本无测试计划 | 计划随版本复制 |
| 计数与列表不一致 | 用例迁移后旧计数未过滤 | 统一按项目过滤 |
| 迁移不可逆 | 执行后发现问题 | 备份 + 单事务 + 先演练 |
| 重复迁移 | 多次执行脚本 | 只处理未分组项目，天然幂等 |
| 大空间耗时长 | 项目/模块数量多 | 维护窗口执行，先预览估时 |

## 8. 验收清单

- [ ] 无一级模块的项目保持未分组，数据和界面都不变；
- [ ] 有模块的项目拆分后：集名、新项目名、容器名正确，模块子树完整；
- [ ] 工作项/需求/用例按模块归属正确，未挂模块数据留在容器；
- [ ] 版本只出现在有内容的项目，发布记录与里程碑按模块复制；
- [ ] 子项目版本发布检查能取到测试计划与必测项；
- [ ] 用例集列表、计数、用例详情回显三者一致；
- [ ] 容器空版本详情提示拆分去向，操作记录有「按模块拆分」；
- [ ] 交付说明、文档、仓库、分支、用例集仍在容器；
- [ ] 脚本重复执行不产生新数据；
- [ ] 迁移前后各项目权限不变，集内不可见项目不泄露；
- [ ] 删除项目集后项目回落未分组，项目本身与版本不受影响。

## 9. 分期

| 阶段 | 范围 |
|---|---|
| 一期 | 项目集增删改与排序、项目归属、列表筛选/分组、历史迁移（含计划复制与拆分日志）、手册与契约同步 |
| 二期 | 项目集聚合视图（版本/发布/进度汇总）、集内共享测试计划、迁移审计报表、批量调整归属 |
