# 对外 API 与 MCP · P0 实施设计（2026-11-28）

> 状态：**P0-1 后端与 P0-2 只读侧车 MCP 均已实施（2026-11-28）**：令牌表、鉴权过滤器、CSRF 边界、限流、审计、受控 OpenAPI、14 个只读工具与真实链路 E2E 均已落地；前端令牌管理页未实施。实施结果见第 11 节。
> 关联：[多产品接入方案（企微、飞书与 Qoder）](多产品接入方案-企微飞书Qoder-2026-11-28.md)、[接口契约](接口契约.md)。
> 结论：可行。工作量主要集中在身份与安全边界，底座一次做对，P1 的写工具不需要改结构。

## 1. 范围

P0 只解决一件事：外部客户端能安全地以某个人的身份读数据。P1 再接写操作（建任务、需求、用例，导入文档），但令牌、审计、限流在 P0 就按读写预留。

验收标准：Qoder 通过 MCP 或 OpenAPI 完成「列出空间 → 查我本周任务 → 打开需求文档」，越权访问返回 404 / 403，令牌可撤销且随账号变更失效。

## 2. 现状与约束

- 接口面：60 余个 Controller、484 个 Mapping，统一 `{code,message,data}` 返回与 `X-Trace-Id`；但都是前端内部契约，[接口契约](接口契约.md) 明确不是对外 Token 承诺。
- 认证：Spring Security 表单登录，30 天会话 Cookie，写操作要求 `X-XSRF-TOKEN`（`SecurityConfig.java:44`、`:103`）。没有 Bearer 或访问令牌。
- 权限：空间与项目权限在服务层复核，跨空间 404、越权 403。令牌只需还原「是谁」，不复制权限逻辑。
- 已有工具层：AI 助手已有 8 个只读工具与 4 个写意图，可作为 MCP 工具集的命名与裁剪参考（`AiAssistantInsightService.java:65`、`AiAssistantService.java:62`）。
- 技术栈：JDK 8 加 Spring Boot 2.7.18（`pom.xml:21`）。官方 MCP Java SDK 要求 JDK 17，不引入。
- 部署：单实例、只绑回环、nginx 反代、进程内缓存，无横向扩展（`application.yml:4`）。

## 3. 总体链路

```
Qoder (MCP client)
  │  Authorization: Bearer hg_xxx
  ▼
nginx ──► Spring Boot
           ├─ CsrfFilter          Bearer 且无会话 Cookie 时跳过
           ├─ SessionEpochFilter  令牌请求无会话，直接放行
           ├─ ApiTokenAuthFilter  校验令牌，组装 LoginUser 进 SecurityContext
           ├─ ApiTokenRateLimitFilter  按令牌滑动窗口限流
           ├─ FilterSecurityInterceptor  /api/** 需登录
           ▼
         既有 Controller → Service（空间 / 项目权限复核，零改动）
           ├─ 审计：令牌事件写 audit_log
           └─ 限流：按令牌滑动窗口
```

## 4. 数据模型

新增脚本 `sql/141_api_token.sql`（撰写时最新为 140，本脚本编号顺延为 141）。本脚本新增 1 张表，基线表数与增量清单需同步 `sql/README`、`sql/baseline`、表数与 ER 图，并跑 `check-docs.py` 与基线漂移检查；并行批次若另有增量，以基线头注释为准。

```sql
CREATE TABLE IF NOT EXISTS `api_token` (
  `id` varchar(32) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '令牌ID',
  `user_id` varchar(32) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '所属账号ID',
  `name` varchar(64) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '用户起的名字',
  `prefix` varchar(16) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '展示前缀，如 hg_9f3a2c1b',
  `token_hash` char(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL COMMENT 'SHA-256(完整令牌) 十六进制',
  `scope` varchar(16) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'read' COMMENT 'read|write',
  `epoch` bigint NOT NULL COMMENT '签发时 app_user.session_version',
  `expires_at` datetime NULL COMMENT '为空表示不过期',
  `last_used_at` datetime NULL COMMENT '最近使用，按 5 分钟节流回写',
  `revoked_at` datetime NULL COMMENT '撤销时间',
  `created_at` datetime NOT NULL COMMENT '创建时间',
  `created_ip` varchar(64) NULL COMMENT '创建来源 IP',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_api_token_hash` (`token_hash`),
  KEY `idx_api_token_user` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='对外 API 个人访问令牌';
```

## 5. 令牌设计与生命周期

- 格式：`hg_` 加 32 字节随机数的 base64url，共 46 字符；只在创建响应里出现一次。
- 存储：全量 SHA-256 哈希，索引直查；`prefix` 仅用于列表展示。高熵随机串不需要 bcrypt。
- 默认有效期 90 天，可配置；`expires_at` 为空表示不过期。
- `last_used_at` 同一令牌 5 分钟内只回写一次，避免每次请求写库。
- 失效条件（任一命中返回 401）：哈希不存在、已撤销、已过期、账号已停用、`app_user.session_version` 与签发时 `epoch` 不一致。最后一条复用 `SessionEpochService`：改密码、管理员重置、角色变更后旧令牌自动失效。

管理接口（仅会话登录可用，令牌不可调用）：

| 接口 | 说明 |
| --- | --- |
| `POST /api/auth/tokens` | 创建；body 含 `name`、`scope`、`expiresInDays`，并校验当前密码 |
| `GET /api/auth/tokens` | 本人令牌列表，不返回令牌本身 |
| `DELETE /api/auth/tokens/{id}` | 撤销本人令牌，重复撤销幂等 |
| `GET /api/admin/tokens?userId=` | 管理员检索全部令牌，可按账号过滤，不返回令牌本身 |
| `DELETE /api/admin/tokens/{id}` | 管理员强制撤销任意令牌，用于处置泄漏，不代发令牌 |

P0 只签发 `read`；`write` 枚举保留，创建接口拒绝。

## 6. 认证过滤器与 CSRF 边界

**过滤器位置**：`ApiTokenAuthFilter` 与 `ApiTokenRateLimitFilter` 都用 `addFilterBefore(..., FilterSecurityInterceptor.class)` 串在 CSRF 与 `SessionEpochFilter` 之后，不改动 `SessionEpochFilter` 的既有逻辑。

- 无 `Authorization: Bearer` 直接放行，会话链路保持原样。
- 有 Bearer：校验哈希、过期、撤销、账号停用、epoch；成功后用 `LoginUser` 构造认证并附加 `API_TOKEN` 权限，在请求上打标记；失败返回 401，不回落匿名。
- 路径护栏：令牌请求访问 `/api/admin/**`、`/api/auth/tokens/**`、`/api/auth/password` 一律 403；只读取令牌对非安全方法直接返回 403「只读令牌不能执行写操作」。

**不给令牌请求建会话**：默认的 `HttpSessionSecurityContextRepository` 会把新认证写进会话。实施时发现仅重写 `saveContext` 不够——Spring Security 的 `SaveToSessionResponseWrapper` 会在响应提交时自动保存。最终在 `BearerAwareSecurityContextRepository.loadContext` 里对 Bearer 请求把 holder 的响应替换成普通 `HttpServletResponseWrapper`，并让 `saveContext` 直接返回，彻底避免生成 `JSESSIONID`。

**CSRF 匹配器**：安全方法放行；只有「Bearer 且无会话 Cookie」跳过；带会话 Cookie 的请求始终要求 CSRF。这样跨站表单仍被拦截，浏览器会话照旧受保护，纯 API 客户端无需 CSRF。

```java
request -> {
    if (isSafeMethod(request.getMethod())) return false;
    boolean bearer = startsWithBearer(request.getHeader("Authorization"));
    boolean hasSession = 存在 JSESSIONID Cookie;
    return !(bearer && !hasSession);
}
```

**授权规则微调**（已按此实施）：

```java
.antMatchers("/api/admin/**").access("hasRole('ADMIN') and !hasAuthority('API_TOKEN')")
.antMatchers("/api/auth/tokens", "/api/auth/tokens/**")
    .access("isAuthenticated() and !hasAuthority('API_TOKEN')")
.antMatchers("/v3/api-docs", "/v3/api-docs/**", "/v3/api-docs.yaml",
        "/swagger-ui.html", "/swagger-ui/**").authenticated()
```

最后一条是关键：`/v3/api-docs` 不在 `/api/**` 下，当前会被 `anyRequest().permitAll()` 公开；未登录访问它会返回 JSON 401，而不是跳转缺失的登录页。

## 7. 限流与审计

- 限流：新增 `ApiTokenRateLimitFilter`，按令牌滑动窗口，只对 Bearer 请求生效。P0 读 120 次 / 分钟，写位留给 P1（30 次 / 分钟）。单实例内存实现与现有 AI 限流一致，超限返回 429；nginx 再加一层 `limit_req` 兜底。
- 审计（沿用 `AuditService.record`）：记录 `api_token.create`、`api_token.revoke` 与管理员 `api_token.admin_revoke`，actor 为本人或管理员，detail 含令牌名与前缀，不落完整令牌；校验失败不写审计，只打 debug 日志（方法、路径、来源 IP），避免被刷爆审计表。
- 日志：`Authorization` 头与令牌禁止进日志和 MDC，沿用「出站日志不落 Key」的口径。

## 8. 受控 OpenAPI

- 依赖 `springdoc-openapi-ui 1.7.0`（javax / Boot 2.7 的最后一条线），兼容 Boot 2.7；不引入 MCP Java SDK。
- 实施时改为**全局白名单**而不是 group：`OpenApiCustomiser` 对 group 不生效，分组方案会把非白名单 GET（含管理端）暴露在默认文档里。现在只保留一个默认端点 `/v3/api-docs`，`paths-to-match` 收窄范围，customiser 再裁掉全部非 GET 操作并删除只剩空操作的路径。
- 实测默认文档含 34 个 GET 路径，`/api/admin/**` 与写接口均不在其中；`swagger-ui` 关闭。
- springdoc 认不出 `@CurrentWorkspace` / `@BoardFilter` 自定义解析器，会把它们摊成必填 query 参数 `ctx` / `query`，同时漏掉真正生效的 `workspace`。customiser 里按参数名还原：删掉 `ctx` / `query`，补 `workspace` 与 `q / owners / pris / ...` 等真实筛选项，否则外部按文档传参会 400（`OpenApiConfigTest` 覆盖）。

```yaml
springdoc:
  api-docs.enabled: true
  swagger-ui.enabled: false
  paths-to-match:
    - /api/workspaces
    - /api/projects
    - /api/projects/*
    - /api/tasks/list
    - /api/task/*
    - /api/tasks/*/logs
    - /api/demands
    - /api/demands/*
    - /api/demands/*/tasks
    - /api/req-docs
    - /api/req-docs/*
    - /api/test-cases
    - /api/test-cases/*
    - /api/versions
    - /api/my-tasks
    - /api/search
    - /api/auth/me
```

声明 Bearer 安全方案。文档本身标注「只读、P0 非稳定契约」，与接口契约的「内部契约」表述区分开。

### 9.1 侧车实现（P0-2）

- 目录 `tools/mcp/hourglass-mcp/`：Node ≥20 + `@modelcontextprotocol/sdk`（Streamable HTTP、无状态），不引入额外框架；后端仍是唯一权限判定方。
- 传输：默认 `http://127.0.0.1:8788/mcp`，路径与端口可配；`/health` 只回服务名、版本与工具数。
- 鉴权：后端令牌只放在侧车进程环境变量里，不经过 MCP 客户端。未设 `HG_MCP_KEY` 时只接受回环来源；设置后所有调用方必须带 `Authorization: Bearer <key>` 或 `X-HG-MCP-KEY`。经 nginx 反代时源地址也是回环，**对外暴露必须设 key**，监听非回环又没设 key 时进程直接拒绝启动。
- 令牌与入参不写日志；后端错误统一转成可读文本（401 令牌失效、403 越权、404 不存在或无权、429 限流、业务 code 非 0），工具错误用 `isError` 返回，不断开 MCP 连接。
- `limit` 在工具层封顶 100；`get_doc` 原样返回 HTML 正文（表格类文档正文是工作簿快照 JSON 字符串）。

5. 侧车不把令牌交给 MCP 客户端：已实施，令牌只在侧车进程内；对外暴露靠 `HG_MCP_KEY`，未设 key 时只接受本机回环，避免 nginx 反代后变成「人人可读」。
