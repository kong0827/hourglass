# 对外 API 与 MCP · P0 实施设计（2026-11-28）

> 状态：设计稿，未实施；不改产品代码、不改数据库。
> 关联：[多产品接入方案（企微、飞书与 Qoder）](多产品接入方案-企微飞书Qoder-2026-11-28.md)、[接口契约](接口契约.md)。
> 结论：可行。工作量主要集中在身份与安全边界，底座一次做对，P1 的写工具不需要改结构。

## 1. 范围

P0 只解决一件事：外部客户端能安全地以某个人的身份读数据。P1 再接写操作（建任务、需求、用例，导入文档），但令牌、审计、限流在 P0 就按读写预留。

验收标准：Qoder 通过 MCP 或 OpenAPI 完成「列出空间 → 查我本周任务 → 打开需求文档」，越权访问返回 404 / 403，令牌可撤销且随账号变更失效。

## 2. 现状与约束

- 接口面：60 余个 Controller、484 个 Mapping，统一 `{code,message,data}` 返回与 `X-Trace-Id`；但都是前端内部契约，[接口契约](接口契约.md) 明确不是对外 Token 承诺。
- 认证：Spring Security 表单登录，30 天会话 Cookie，写操作要求 `X-XSRF-TOKEN`（`SecurityConfig.java:44`、`:103`）。没有 Bearer 或访问令牌。
- 权限：空间与项目权限在服务层复核，跨空间 404、越权 403。令牌只需还原「是谁」，不复制权限逻辑。
- 已有工具层：AI 助手已有 8 个只读工具与 4 个写意图，可作为 MCP 工具集的命名与裁剪参考（`AiAssistantInsightService.java:65`、`AiAssistantService.java:62`）。
- 技术栈：JDK 8 加 Spring Boot 2.7.18（`pom.xml:21`）。官方 MCP Java SDK 要求 JDK 17，不引入。
- 部署：单实例、只绑回环、nginx 反代、进程内缓存，无横向扩展（`application.yml:4`）。

## 3. 总体链路

```
Qoder (MCP client)
  │  Authorization: Bearer hg_xxx
  ▼
nginx ──► Spring Boot
           ├─ CsrfFilter          Bearer 且无会话 Cookie 时跳过
           ├─ ApiTokenAuthFilter  校验令牌，组装 LoginUser 进 SecurityContext
           ├─ SessionEpochFilter  令牌请求无会话，直接放行
           ├─ FilterSecurityInterceptor  /api/** 需登录
           ▼
         既有 Controller → Service（空间 / 项目权限复核，零改动）
           ├─ 审计：令牌事件写 audit_log
           └─ 限流：按令牌滑动窗口
```

## 4. 数据模型

新增脚本 `sql/140_api_token.sql`（当前最新为 139）。基线表数 99 增至 100，实施后同步 `sql/README`、`sql/baseline`、表数与 ER 图，并跑 `check-docs.py` 与基线漂移检查。

```sql
CREATE TABLE IF NOT EXISTS `api_token` (
  `id` varchar(32) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '令牌ID',
  `user_id` varchar(32) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '所属账号ID',
  `name` varchar(64) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '用户起的名字',
  `prefix` varchar(16) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '展示前缀，如 hg_9f3a2c1b',
  `token_hash` char(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL COMMENT 'SHA-256(完整令牌) 十六进制',
  `scope` varchar(16) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'read' COMMENT 'read|write',
  `epoch` bigint NOT NULL COMMENT '签发时 app_user.session_version',
  `expires_at` datetime NULL COMMENT '为空表示不过期',
  `last_used_at` datetime NULL COMMENT '最近使用，按 5 分钟节流回写',
  `revoked_at` datetime NULL COMMENT '撤销时间',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `created_ip` varchar(64) NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_token_hash` (`token_hash`),
  KEY `idx_user` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='对外 API 个人访问令牌';
```

## 5. 令牌设计与生命周期

- 格式：`hg_` 加 32 字节随机数的 base64url，共 46 字符；只在创建响应里出现一次。
- 存储：全量 SHA-256 哈希，索引直查；`prefix` 仅用于列表展示。高熵随机串不需要 bcrypt。
- 默认有效期 90 天，可配置；`expires_at` 为空表示不过期。
- `last_used_at` 同一令牌 5 分钟内只回写一次，避免每次请求写库。
- 失效条件（任一命中返回 401）：哈希不存在、已撤销、已过期、账号已停用、`app_user.session_version` 与签发时 `epoch` 不一致。最后一条复用 `SessionEpochService`：改密码、管理员重置、角色变更后旧令牌自动失效。

管理接口（仅会话登录可用，令牌不可调用）：

| 接口 | 说明 |
| --- | --- |
| `POST /api/auth/tokens` | 创建；body 含 `name`、`scope`、`expiresInDays`，并校验当前密码 |
| `GET /api/auth/tokens` | 本人令牌列表，不返回令牌本身 |
| `DELETE /api/auth/tokens/{id}` | 撤销本人令牌 |

P0 只签发 `read`；`write` 枚举保留，创建接口拒绝。管理员不代发令牌，但保留强制撤销任意令牌的入口用于处置泄漏。

## 6. 认证过滤器与 CSRF 边界

**过滤器位置**：`addFilterBefore(new ApiTokenAuthFilter(...), FilterSecurityInterceptor.class)`，排在 CSRF 与会话代次校验之后，不改动 `SessionEpochFilter` 的既有逻辑。

- 无 `Authorization: Bearer` 直接放行，会话链路保持原样。
- 有 Bearer：校验哈希、过期、撤销、账号停用、epoch；成功后用 `LoginUser` 构造认证并附加 `API_TOKEN` 权限，在请求上打标记；失败返回 401，不回落匿名。
- 路径护栏：令牌请求访问 `/api/admin/**`、`/api/auth/tokens/**`、`/api/auth/password` 一律 403。

**不给令牌请求建会话**：默认的 `HttpSessionSecurityContextRepository` 会把新认证写进会话。改为自定义仓库，见到 Bearer 标记就不保存，避免每次 API 调用生成会话、也避免 CSRF 判定含混。

**CSRF 匹配器**：安全方法放行；只有「Bearer 且无会话 Cookie」跳过；带会话 Cookie 的请求始终要求 CSRF。这样跨站表单仍被拦截，浏览器会话照旧受保护，纯 API 客户端无需 CSRF。

```java
request -> {
    if (isSafeMethod(request.getMethod())) return false;
    boolean bearer = startsWithBearer(request.getHeader("Authorization"));
    boolean hasSession = 存在 JSESSIONID Cookie;
    return !(bearer && !hasSession);
}
```

**授权规则微调**：

```java
.antMatchers("/api/admin/**").access("hasRole('ADMIN') and !hasAuthority('API_TOKEN')")
.antMatchers("/api/auth/tokens/**").access("!hasAuthority('API_TOKEN')")
.antMatchers("/v3/api-docs/**").authenticated()
```

最后一条是关键：`/v3/api-docs` 不在 `/api/**` 下，当前会被 `anyRequest().permitAll()` 公开。

## 7. 限流与审计

- 限流：新增 `ApiRateLimitFilter`，按令牌滑动窗口，只对 Bearer 请求生效。P0 读 120 次 / 分钟，写位留给 P1（30 次 / 分钟）。单实例内存实现与现有 AI 限流一致，nginx 再加一层 `limit_req` 兜底。
- 审计（沿用 `AuditService.record`）：记录 `api_token.create` 与 `api_token.revoke`，actor 为本人，detail 含令牌名与前缀，不落完整令牌；令牌校验失败按抽样记录，避免刷爆审计表。
- 日志：`Authorization` 头与令牌禁止进日志和 MDC，沿用「出站日志不落 Key」的口径。

## 8. 受控 OpenAPI

- 依赖 `springdoc-openapi-ui 1.7.x`，兼容 Boot 2.7；不引入 MCP Java SDK。
- 只开一个白名单分组，不整体暴露 484 个端点；`swagger-ui` 关闭。

```yaml
springdoc:
  api-docs.enabled: true
  swagger-ui.enabled: false
  group-configs:
    - group: openapi
      paths-to-match:
        - /api/workspaces
        - /api/projects
        - /api/tasks/list
        - /api/task/{id}
        - /api/tasks/{id}/logs
        - /api/demands
        - /api/demands/{id}
        - /api/demands/{id}/tasks
        - /api/req-docs
        - /api/req-docs/{id}
        - /api/test-cases
        - /api/versions
        - /api/my-tasks
        - /api/search
        - /api/auth/me
```

声明 Bearer 安全方案。文档本身标注「只读、P0 非稳定契约」，与接口契约的「内部契约」表述区分开。

所有工具除 `list_workspaces` 外必须显式传 `workspaceId`；不传会落到「上次使用的空间」，对 Agent 是隐患。`limit` 在工具层封顶 100。

| `get_task` | GET /api/task/{id} | id |
| `task_logs` | GET /api/tasks/{id}/logs | id |

## 11. 测试计划

1. 签发后列表不含令牌；撤销后 401。
2. 过期令牌、停用账号、`session_version` 递增后的旧令牌均 401。
3. `scope=read` 令牌调写接口 403。
4. 令牌调管理员接口与令牌管理接口 403。
5. CSRF 三态：会话 POST 无头 403；纯 Bearer POST 无 CSRF 通过；Bearer 加会话 Cookie 无 CSRF 403。
6. 令牌请求不生成 JSESSIONID。
7. 超过限流阈值返回 429，窗口后恢复。
8. `/v3/api-docs` 匿名 401、Bearer 200，且只含白名单路径。
9. 现有后端测试全量回归通过。

手工验收：Qoder 接入侧车 MCP，跑「列空间 → 查本周任务 → 打开需求文档」，再验证一个跨空间越权用例返回 404。

## 13. 待确认

1. 创建令牌时校验当前密码：建议要，防止浏览器会话被劫持后静默铸造长期令牌。
2. 密码与角色变更后令牌自动失效：建议是，复用账号代次，代价是改密后需重发令牌。
3. P0 只发只读令牌：建议是，写令牌字段保留但接口拒绝。
4. OpenAPI 文档不匿名：建议必须登录或 Bearer，否则会被现有兜底规则公开。
