# 工作台（DevStudio）前端重构规范 v1.0

> **本文档的用途**：这是一份**面向 AI 编码工具的开发蓝本**。阅读者（AI 或工程师）应当**只依据本文档**完成 `devstudio-server/src/main/resources/static/` 下前端（HTML/CSS/JS）的重构，**不得改变任何后端接口的路径、入参、出参与语义**。
>
> **阅读顺序**：先读 §0 使用说明与 §1 重构目标 → 按 §2 落地 CSS 令牌 → 按 §3 重建 Shell → 按 §4 建组件 → 按 §6/§7 逐页实现 → 按 §8 补交互 → 按 §9/§10 对齐架构与接口 → 按 §11 顺序实施 → 用 §12 验收。
>
> **硬约束**：
> 1. 后端接口契约以 `docs/api.md` 为准，本文档 §10 是**映射表**，冲突时以 `api.md` 为准。
> 2. 本文档描述的是**布局、视觉、交互、组件**的重构；**功能只增不减**——现有每一个功能点（含筛选、保存视图、工时计时、循环任务、附件、邀请链接、导入导出、回收站、SSE）都必须在新界面中保留可用入口。
> 3. 目标终端：**仅桌面端 Web，设计基准宽度 1440px，最小支持 1280px**。不需要设计移动端布局，但需保证 1280～2560 区间不破版。

**术语统一**（全文一致，避免歧义）：

- **面板（Panel）**：白底、1px 边框、圆角 12 的容器块。
- **抽屉（Drawer）**：从右侧滑入的详情面板，宽 680px。
- **弹窗（Modal）**：屏幕居中的模态框，用于确认与轻量表单。
- **视图（View）**：内容区的一个可切换页面单元（看板/列表/日历/项目/回顾/报表/回收站/设置/用户管理）。
- **空间（Workspace）**：数据隔离单元，分「个人空间」与「共享空间」。
- **项目（Req）**：需求/项目实体，接口里的 `requirement`，界面上统一叫「项目」。

## 1. 重构目标与设计原则

### 1.1 现状问题清单（本次重构要解决的）

| # | 问题 | 现状表现 | 本次对策 |
|---|---|---|---|
| P1 | 顶部操作区职责混杂 | 快速录入、搜索、新增任务、提醒铃铛平铺在一行，主次不分 | §3.3 重排顶栏：搜索独立为全局入口，新建为主按钮+下拉，快速录入降级为快捷键唤起 |
| P2 | 筛选栏横向铺开易换行 | 6 组筛选 chip 全部平铺，窄屏换行、占垂直空间 | §4.4 + §6.3 改为「常用筛选 + 更多筛选 Popover」，已选条件折叠为可清除摘要 |
| P3 | 任务详情用居中弹窗 | 字段多达 12 个（子任务/附件/工时/时间线），弹窗内滚动体验差且遮挡看板上下文 | §7.1 改为右侧抽屉 680px |
| P4 | 卡片信息层级弱 | 优先级、进度、逾期、子任务进度、标签并列堆叠，无视觉优先级 | §4.7 重定义卡片：左侧优先级色条 + 顶部标题 + 中部元信息 + 底部进度与角标 |
| P5 | 看板列缺少列内操作 | 新增任务只能走顶栏或列尾，列头无计数与折叠 | §6.3 列头加计数/折叠/列内快速添加 |
| P6 | 视觉装饰偏重 | 侧栏渐变背景、品牌块大投影、暖色大面积铺陈，B 端专业感不足 | §1.3 改为中性灰白 + 蓝色主色，去渐变、去重投影 |
| P7 | 状态反馈不统一 | 空态、加载、错误三态在各视图表现不一 | §8.4 统一四态规范 + §4.11/§4.12 组件化 |
| P8 | 危险操作与普通操作按钮同级 | 「清空数据」「删除空间」与普通按钮同一视觉重量 | §4.1 引入 `danger-ghost` / `danger-solid`，危险区独立分区 + 二次确认 |

### 1.2 设计原则

1. **信息优先于装饰**：用边框、明度、间距建立层级，而不是用阴影和渐变。
2. **主路径零阻力**：最常用的三件事——*看今天要做什么*、*记一个新任务*、*拖动状态*——各自不超过 1 次操作。
3. **上下文不丢失**：详情、编辑、筛选都不得遮挡或销毁用户当前的工作视图（抽屉优于弹窗，Popover 优于跳转）。
4. **状态始终可见**：加载、空、错误、离线、同步中，任何时刻界面都要能回答"现在发生了什么"。
5. **危险操作有摩擦**：破坏性操作必须视觉降权 + 文字确认 + 二次点击。

### 1.3 视觉方向：现代浅色 · B 端专业

参考气质：Linear / Notion / Jira（新版）——克制、密实、无装饰噪声。

- **底色**：冷调中性灰白（`#F7F8FA`），内容承载面纯白。
- **主色**：品牌蓝 `#2563EB`，只用于主操作、选中态、焦点环、进度强调。
- **辅助色**：语义色（成功绿 / 警告琥珀 / 危险红 / 信息蓝）仅用于状态语义，不做装饰。
- **文字**：三级灰阶（`#101828` / `#475467` / `#98A2B3`），标题靠字重与字号拉开，不靠颜色。
- **边框**：1px 细线是主要分隔手段，阴影只在浮层（下拉/抽屉/弹窗）使用。
- **密度**：行高 22px、控件高 32/36px，一屏内尽可能多承载信息。
- **圆角**：卡片 12、控件 8、标签 999。整体比现状（18px）收紧 30%。
- **动效**：只做 120～240ms 的位置/透明度过渡，不做弹跳、不做旋转入场。

**明确禁止**：

- ❌ 大面积渐变背景、玻璃拟态、发光边框
- ❌ emoji 充当图标（必须用 SVG）
- ❌ 同一屏幕出现两个同权重主按钮
- ❌ 用颜色区分无状态语义的装饰元素

## 2. 设计令牌（Design Tokens）

### 2.1 色彩

#### 2.1.1 中性色（背景 / 表面 / 边框 / 文字）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg-app` | `#F7F8FA` | 页面最底层背景 |
| `--surface` | `#FFFFFF` | 卡片、面板、抽屉、弹窗底色 |
| `--surface-sunken` | `#F2F4F7` | 输入框底色、次级填充块、表头 |
| `--surface-hover` | `#F2F4F7` | 行/列表项 hover |
| `--surface-active` | `#E9ECF1` | 行/列表项 按下、选中底色 |
| `--border` | `#E4E7EC` | 常规分隔线、控件边框 |
| `--border-strong` | `#D0D5DD` | 输入框聚焦前边框、强调分隔 |
| `--text` | `#101828` | 主文本、标题 |
| `--text-2` | `#475467` | 次级文本、说明 |
| `--text-3` | `#98A2B3` | 占位符、禁用文本、时间戳 |
| `--text-inverse` | `#FFFFFF` | 主色按钮上的文字 |

#### 2.1.2 品牌色

| 令牌 | 值 | 用途 |
|---|---|---|
| `--primary` | `#2563EB` | 主按钮、选中态、进度条 |
| `--primary-hover` | `#1D4ED8` | 主按钮 hover |
| `--primary-active` | `#1E40AF` | 主按钮 按下 |
| `--primary-soft` | `#EFF4FF` | 选中行底色、导航选中底色、浅色标签底 |
| `--primary-border` | `#BFD3FE` | 选中态边框、Focus 强调 |
| `--primary-fg` | `#1D4ED8` | 浅色底上的主色文字（对比度达标） |

#### 2.1.3 语义色

| 语义 | 主色 | 浅底 | 边框 | 用途 |
|---|---|---|---|---|
| 成功 success | `#12B76A` | `#ECFDF3` | `#A6F4C5` | 已完成、按期完成、保存成功 |
| 警告 warning | `#F79009` | `#FFFAEB` | `#FEDF89` | 临期（3 天内）、延期完成、容量提醒 |
| 危险 danger | `#F04438` | `#FEF3F2` | `#FDA29B` | 逾期、删除、错误 |
| 信息 info | `#2E90FA` | `#EFF8FF` | `#B2DDFF` | 中性提示、进行中 |
| 紫 plum | `#7A5AF8` | `#F4F3FF` | `#D9D6FE` | 自定义分类/列的调色板选项 |

#### 2.1.4 优先级专色（P0–P3，全局一致）

| 优先级 | 色值 | 浅底 | 语义 |
|---|---|---|---|
| P0 | `#F04438` | `#FEF3F2` | 最高，必须今天处理 |
| P1 | `#F79009` | `#FFFAEB` | 高 |
| P2 | `#2E90FA` | `#EFF8FF` | 中 |
| P3 | `#98A2B3` | `#F2F4F7` | 低 |

> 优先级标签的呈现：`6px` 圆点 + 文字，或卡片左侧 `3px` 竖色条。**不要**用大面积色块。

#### 2.1.5 分类/看板列颜色

后端存 `#RRGGBB` 自由色值。新建设置面板时，取色器默认值统一为 `#98A2B3`，预设色板按顺序给出：
`#2563EB` `#12B76A` `#F79009` `#F04438` `#7A5AF8` `#0E9384` `#DD2590` `#98A2B3`

### 2.2 字体与排版

**字体族**

```css
--font-sans: "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI",
             "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei",
             "Helvetica Neue", Arial, sans-serif;
--font-mono: "SFMono-Regular", Consolas, "Liberation Mono", Menlo, monospace;
```

> 数字场景（计数、工时、百分比、日期）加 `font-variant-numeric: tabular-nums;`，避免跳动。

**字号阶梯**

| 令牌 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| `display` | 24 / 32 | 700 | 登录页标题、空态大标题 |
| `h1` | 20 / 28 | 650 | 页面标题（顶栏 `#viewTitle`） |
| `h2` | 16 / 24 | 650 | 面板标题、抽屉标题、弹窗标题 |
| `h3` | 14 / 22 | 600 | 分组小标题（如「成员贡献」） |
| `body` | 14 / 22 | 400 | 正文、卡片标题 |
| `body-sm` | 13 / 20 | 400 | 次级信息、表单说明 |
| `caption` | 12 / 18 | 500 | 元信息、计数、时间戳 |
| `micro` | 11 / 16 | 700 | 分组标签（大写字母间距 0.06em） |

- 标题统一 `letter-spacing: -0.01em`；`micro` 用 `+0.06em`。
- 中文正文**最小 12px**，不使用 11px 承载可读内容。

| 面板内边距 | 16 / 20 |

### 4.11 EmptyState

```

│              [ 64×64 线性图标 ]       │  ← --text-3，1.5px 描边
│                                      │

- 容器：最小高度 240px，居中，`padding:40px`。
- **区分两类空态**：
  - **真空态**（数据为空）→ 提供创建入口。
  - **筛完为空**（有数据但被筛选隐藏）→ 图标换为「筛选」图标，文案「没有符合当前筛选的任务」，操作按钮为「清空筛选」。

### 4.12 Skeleton（骨架屏）

- 底色 `--surface-sunken`，`--r-xs`，`animation: shimmer 1.4s ease-in-out infinite`。

### 4.13 Tooltip / ProgressBar / Spinner

**Tooltip**：深色底 `--text`，白字 12px，内边距 `5px 8px`，`--r-xs`，延迟 400ms 出现，间距 6px。纯 CSS 或轻量 JS，不做第三方依赖。

**ProgressBar**：
- 轨道高 6px，`--surface-sunken`，`--r-pill`。
- 填充 `--primary`，`--r-pill`，`transition: width var(--dur-base)`。
- 状态色：≥100% → `--success`；逾期且 <100% → `--danger`。
- 右侧百分比：12px/600，`tabular-nums`。

**Spinner**：14/16/20px，2px 描边圆环，`border-color: var(--primary) transparent transparent transparent`，`rotate 720ms linear infinite`。

**实现要求**：

- 统一在 `document` 上挂一个 `keydown` 监听，先判断 `e.target` 是否为 `input/textarea/select` 或 `contenteditable`，是则除 `Esc` 与 `⌘+Enter` 外全部忽略。
- 输入法组合期（`e.isComposing === true`）一律忽略，避免拼音输入误触。
- 所有快捷键在 UI 上要有**可发现性**：搜索框右侧显示 `<kbd>` 提示；空态文案里写「或用 N 快速录入」；设置页放一个「快捷键」折叠面板列出全表。

### 8.2 拖拽规范

**技术**：使用 HTML5 Drag and Drop（`draggable="true"` + `dragstart/dragover/drop/dragend`），沿用现有实现基础，补齐视觉反馈。**不引入拖拽库**。

| 阶段 | 表现 |
|---|---|
| 拾起（`dragstart`） | 原卡片 `opacity:.4`；设置 `dataTransfer.effectAllowed="move"`；在 `dragImage` 位置创建幽灵卡片 |
| 移动中（`dragover`） | 1. 计算落点：比较指针 Y 与列内各卡片中线，插到最近卡片的**上/下**侧<br>2. 显示 2px `--primary` 插入指示线（`--r-pill`，`margin:2px 0`）<br>3. 目标列底色 → `--primary-soft`，边框 → `--primary-border`<br>4. `preventDefault()` 以允许 drop |
| 空列 | 显示整列高 96px 的虚线投放框，居中文字「拖到这里」（12px `--primary-fg`） |
| 边缘自动滚动 | 指针距 `.board` 或列体边缘 <40px 时，以 `requestAnimationFrame` 逐帧 `scrollBy(0, ±8)`（横向 ±12） |
| 落下（`drop`） | **乐观更新**：立即把卡片插入目标位置并保持可视；同时发 `POST /api/tasks/{id}/move {column, beforeId}` |
| 失败 | 回滚到原位置 + Toast 错误 + 恢复原列高亮 |
| 结束（`dragend`） | 清除全部临时类名与指示线 |

**跨列移动的完成日期联动**（保持现有语义，UI 要给强反馈）：

- 移入「已完成」→ Toast「已完成任务「xxx」」；若原截止日期晚于今天 → 「已完成任务「xxx」，按期完成」；早于今天 → 「已完成任务「xxx」，延期 N 天完成」（`warn` 语义）。
- 移出「已完成」→ Toast「已清除完成时间」（`warn` 语义）。
- 同列内调整顺序 → 无 Toast（静默成功）。

**可拖拽区域限制**：卡片上的按钮、进度条、标签输入等交互元素需 `draggable="false"` 且阻止事件冒泡，避免误拖。

### 8.3 实时同步与轮询兜底

- 主通道：`GET /api/events`（EventSource，SSE）。收到 `changed` 事件 → 重新拉取当前视图数据。
- **收敛策略**（关键，防止事件风暴打爆接口）：
  1. 收到事件后启动 300ms 防抖计时，窗口内的多次事件合并为一次刷新。
  2. 刷新中再收到事件 → 标记 `pending`，当前刷新结束后再执行一次。
  3. 单次刷新超过 3 秒未返回 → 放弃本次并以 3 秒间隔重试，最多 3 次。
- 心跳：服务端 25s 一次 `ping`；客户端 **60s 未收到任何消息**判定断连，进入重连（指数退避：1s → 2s → 4s → 8s，上限 30s）。
- 轮询兜底：SSE 不可用或断连期间，每 30s 轮询一次当前视图接口。
- **用户提示**：
  - 顶部显示 2px 进度条表示「同步中」，不闪骨架。
  - 断连超过 60s → 顶栏出现黄色提示条「实时连接已断开，正在重连…」，恢复后自动消失。
  - **本地有未保存编辑时，SSE 刷新不得覆盖抽屉内的表单**（抽屉打开且脏时，延迟刷新直到关闭或保存）。
- 事件按空间过滤由服务端负责；客户端仍需校验当前空间 ID 是否匹配，不匹配则忽略。

### 8.4 加载 / 空 / 错误 / 乐观更新

**四态规范矩阵**（每个视图必须实现全部四态）

| 态 | 表现 | 组件 |
|---|---|---|
| 首次加载 | 骨架屏（§4.12），高度与真实内容一致，避免布局跳动 | Skeleton |
| 空（真实无数据） | EmptyState + 创建入口（§4.11） | EmptyState |
| 空（筛选后无结果） | EmptyState 变体「没有符合当前筛选的任务」+ 「清空筛选」 | EmptyState |
| 错误 | 居中卡片：图标 + 「加载失败」+ 具体原因（12px `--text-3`）+ 「重试」次按钮 | ErrorState |
| 刷新中 | 顶部 2px  indeterminate 进度条，内容保持可见 | ProgressBar |

**乐观更新适用范围**：

| 操作 | 是否乐观 | 说明 |
|---|---|---|
| 拖拽移动任务 | ✅ | 立即移动，失败回滚 |
| 勾选/取消子任务 | ✅ | 立即切换，失败回滚 |
| 删除任务 | ✅ | 立即从列表移除（配合 Toast 撤销入口） |
| 恢复任务 | ✅ | 立即从回收站移除 |
| 保存任务表单 | ❌ | 等接口返回后再关闭抽屉 |

**删除撤销**：删除任务后 Toast 内提供「撤销」按钮（保留 6 秒），点击调用 `POST /api/tasks/{id}/restore`。

    └── app.js               # 入口：初始化、Shell 绑定、SSE、快捷键、视图路由
```

> **实施建议**：允许分阶段拆文件。第一阶段可先只做 `tokens.css` + `app.css` 重写 + `index.html` 结构微调，把「视觉与布局」落地；第二阶段再拆 JS 模块。**拆模块不得改变接口调用方式**。

### 9.3 状态管理

单一全局对象，避免散落的模块级变量：

```js
window.DS = {
  me: null,                    // GET /api/auth/me
  workspace: { id, name, type, myRole },
  workspaces: [],
  view: "board",               // board|list|calendar|projects|review|stats|trash|settings|users
  filter: {                    // 与 api.md 通用查询参数一一对应
    q: "", owners: [], pris: [], cats: [], reqs: [], tags: [],
    due: "", focus: false, doneScope: "week"
  },
  meta: { owners: [], pris: [], cats: [], reqs: [], tags: [], unassigned: 0 },
  columns: [],                 // GET /api/columns
  categories: [],              // GET /api/categories
  members: [],
  views: [],                   // 保存的筛选视图
  board: null,                 // 最近一次 /api/board 响应
  editingTaskId: null,
  sse: { conn: null, lastPing: 0, retry: 0 }
};
```

- 状态变更后由各视图的 `render()` 全量重绘该视图内部内容（数据量不大，不做虚拟 DOM）。
- 切换空间 → 重置 `filter`、清空 `board`、重新拉取 `meta/columns/categories/members`。
- 筛选变化 → 300ms 防抖后请求，避免连续点击打爆接口。

### 9.4 API 封装

保持 `api.js` 的形态，补齐三点：

1. **统一错误处理**：非 0 `code` 一律 `throw new Error(message)`，`message` 直接取自响应体（后端已是中文），调用方只负责 Toast。
2. **CSRF 自动注入**：写操作自动带 `X-XSRF-TOKEN`（取 Cookie `XSRF-TOKEN`）——沿用现有实现，不要回退。
3. **空间参数自动附带**：所有业务请求自动追加 `?workspace=<当前空间ID>`（沿用现状），避免逐个手写。

```js
// 目标形态（示意，保持与现状兼容）
const API = {
  get(path, params) { /* 自动拼 workspace */ },
  post(path, body) { /* 自动带 CSRF */ },
  put(path, body) { },
  del(path) { },
  upload(path, file, onProgress) { },
  csv(path) { /* 触发下载 */ }
};
```

**统一错误文案兜底**：`网络异常，请稍后重试`；HTTP 401 时统一跳转 `/login.html`。

### E.3 为什么「一周后」按工作日

用户要求：一周 = 5 个工作日，不能把周末算进去。实现口径：从今天起向后累计 5 个**工作日**（跳过周六 / 周日）。

如实说明差别（不夸大）：起点是周一～周五时，「5 个工作日」与「+7 自然日」其实落在同一天（周一 +5 工作日 = 下周一 = +7 自然日）。真正的差别出现在起点是**周末**时 —— 周六 / 周日点「一周后」，旧实现会落到下周六 / 周日（休息日），新实现落到下周五（最后一个工作日）。另外这一口径让「一周」的工作量含义与排期一致，不再让人以为周末也被计入了工期。

### G.2 新视图 · 任务清单（§6.10）

- 导航位置：「洞察」分组，周回顾之后（`data-view="completions"`，图标为清单样式）。
- 工具栏：`‹ 2026 年 10 月 ›` 月份切换 + 「导出 CSV」。
- 统计卡 4 个：完成任务 / 总耗时 / 平均每项 / 参与成员（附「最多：XXX N 项」小字）。
- 表格列：完成日 · 任务（名称 + 详情两行）· 项目 · 负责人 · 分类 · 优先级 · 开始 · 首次计时 · 最后计时 · 总耗时。表头 `position:sticky`，横向可滚（`.comp-scroll`）。

### G.3 口径

- 归档是**快照**：项目名、负责人、分类、优先级都取完成那一刻的值。项目后来改名，历史记录仍是当时的名字。
- 总耗时 = `time_log.minutes` 之和，也就是**已经按「每天 8 小时 / 跳过周末」裁剪过**的工时，不是墙钟时间。
- 没有计时的任务也能完成（`total_minutes = 0`，首次/最后计时为空），不算异常。

### G.5 接力计时（v2.0）

完成任务把表停掉后，如果「进行中」列还有别的任务，自动接上**第一个**（按 `sort_order`）开始计时，toast 提示「已完成任务「A」· 已接着开始「B」的计时」。

**三条护栏**（都在 `TimeLogService.resumeInColumn` 里）：

1. 只有"我当前**没有任何**运行中计时"时才接力 —— 否则会把别的空间正在计的任务抢掉；
2. 原列是「待处理」/「已完成」不接力；
3. 排除刚完成的那个任务。

**取舍**：接力不区分负责人。列里第一个任务即使挂在别人名下，也会给"我"开始计时（因为计时记的是我的工时，而需求是"进行中必须有一个在计时"）。如果要改成"只接力我负责的任务"，改 `resumeInColumn` 的筛选条件即可。

### H.4 为什么不用现成的编辑器库

项目前端是**零框架、零构建、可离线**（Service Worker 缓存静态文件）。引入 Quill / TinyMCE 意味着额外的 JS + CSS 资源、版本管理和离线缓存策略，与整体风格不符。`contenteditable` + `execCommand` 虽被标记废弃，但所有主流浏览器仍稳定支持，够用且零成本。
内容安全靠**服务端 jsoup 白名单**兜底（前端另有一层同样的清洗），所以编辑器本身不需要为 XSS 负责。

### G.7 修订（v2.3）：行内居中、导航气泡、编辑器换 Quill、任务清单需求列

**Quill 集成要点**：

1. **本地托管**：`static/vendor/quill/quill.js`（209KB）+ `quill.snow.css`（25KB），并加入 `sw.js` 的 `SHELL` 预缓存 —— 保持"零 CDN、可离线"。
2. **工具栏**：标题 / B I U S / 有序无序列表 / 缩进 / 对齐 / 颜色背景 / 引用代码块 / 链接 / 清除格式。
3. **HTML → Delta**：载入时 `quill.clipboard.convert({html})` + `setContents(delta, "silent")`，silent 避免立刻标脏。
4. **保存**：取 `quill.root.innerHTML`（不再用前端 DOM 清洗 —— 那会删掉 Quill 的 class/style，格式就丢了）；安全由服务端 jsoup 兜底。

### H.5 重做（v2.4）：需求页改成「列表树 → 新增弹窗 → 独立编辑页」

原来的左右分栏（左列表 + 右编辑器）被推翻，改成更贴近日常使用的三段式：

   ↓ 点一行 / 点「新增需求」

**列表页**

- 点「新增需求」→ 弹窗：**所属项目（下拉）+ 需求名称**，回车即提交。
- 确认后 `POST /api/req-docs`（正文留空）→ 关闭弹窗 → **直接进入编辑页**写正文。
- 没有项目时下拉给提示，不发请求；名称为空时也不发。

**编辑页**

- 顶部：返回按钮 + 面包屑（`项目 / 需求名`）+ 保存状态 + 字数 + 复制 / 删除 / 保存。

- **交互**：点条目平滑跳转（`scrollIntoView` 会带来偏移，改用「容器 scrollTop + 相对 rect - 顶栏高度」）；滚动时用「视口 96px 判定线以上最后一个标题」做 scroll spy，只切 class 不重绘（避免目录自己跳）；有子项的分组带箭头可折叠，父项收起时后代一起隐藏。
- **开关**：工具条「大纲」按钮 + 面板标题栏箭头，状态存 `localStorage.ds.reqToc`；窄屏（≤1080px）自动隐藏。
- **编辑联动**：`onChange` 防抖 400ms 重建；换文档时清空高亮后重建。
- **⚠️ 滚动容器不是 window**：视图区滚动发生在 `#view-requirements`（`.view{overflow-y:auto}`）上，`window.scrollY` 恒为 0。跳转必须找最近的 `overflow-y:auto` 祖先（`reqScrollRoot()`），否则「点了没反应」。

## 附录 J：v3.1 工作时段（计时口径修订）

**问题**：计时按**自然日 00:00** 切段，忘停表过夜时，凌晨一过当天额度重置 → 工时从 0 点又开始涨（用户实测："过了凌晨就开始计时了"）。

### L. 新增（v3.4）：预计耗时、估时系数与超支预警

**为什么加预估耗时**：`start_date` 是"接到任务的那天"，不是"动手的那天"。任务可能今天建、下周才开工，
用 `[开始, 完成]` 算工期会把排队时间也算进去。只有「人填的预估」vs「计时记录的实际」这一对可比。

| 位置 | 元素 | 要点 |
| --- | --- | --- |
| 任务抽屉 | 「预计耗时」数字输入（小时，0.5 步进）+ 「实际投入」只读 | 改预估时**实时**刷新比例，不用保存后才看到；超预估标红、≥80% 标黄 |
| 看板卡片 | meta 行 `8h40m/8h` | 有预估才显示；**计时中的任务也要显示**（那正是最该知道快超了的时候），此时实际值只含已结束的段，title 里注明 |
| 流程体检 · 估时准不准 | 系数大数字 + 三段分布条 + 分类系数 + 预警清单 | 预警（进行中，还来得及）与复盘（已完成，超支了）**分两组**，不要混在一起 |

计算口径（细节见 `docs/api.md` §32 与 `EstimateService` 类注释）：

1. 系数 = **Σ实际/Σ预估**，不是平均比值（小任务会把后者带偏）；
2. **只统计已完成任务**，进行中的实际值不完整；
3. 预警只对**进行中且非 backlog**、`实际/预估 ≥ 0.8` 的任务；
4. `estimate_minutes` 为 `null`/`0` 一律当"没估"，不参与统计。

配色与语义要对齐：系数偏乐观（≥1.15）与偏保守（≤0.87）都算"需要留意"，用警告色；
只有落在中间才是绿色。分布条三段：高估(绿) / 准确(蓝) / 低估(红) —— 红色永远对应"实际超了"。

v3.4 修掉的一个 bug：**分类累计里首个任务的预估与实际被重复加了一次**（初始化 `new long[]{est, act, 0}`
之后又 `+=` 一遍）。单样本分类因为分子分母同倍放大看不出来，多任务时首个任务权重会翻倍 ——
测试里 `前端 est=340` 而不是 `220` 才暴露出来。**教训：既做"新建"又做"累加"的累加器，初始值必须置 0。**

验证：`node tools/shot-estimate.mjs`（CDP 真 Chrome，22 项：卡片 `实际/预估` 与标色、抽屉回填小时、
改预估实时更新比例、清空后提示、系数与分布条、预警/复盘分组、无横向溢出）。

## 附录 K：v3.2 分支管理（2026-10-26）

### 1. 信息层级：先看「卡在哪」，再看「具体是谁」

一条分支从拉出来到上线，真正要回答的是两个问题：**现在卡在哪一步**、**卡了多久**。
所以视图不是一整张表格，而是「顶部计数 → 四列分组 → 卡片停留时长」三层漏斗：

```
[ 1 开发中 ] [ 1 待测试 ] [ 1 待合并 ] [ 1 已发布 ] [ 8.4 平均发布周期（天） ]   ← 点格子只看这一档
   ─────────────────────────────────────────────────────────────
   开发中 ① 代码还在写      待测试 ① 开发完成，等测试验证     …          ← 四列，列头带状态点
   ┌ feature/permission-… ┐  ┌ feature/export-csv… ┐
   │ [开发中 ⌄]       (我) │  │ [待测试 ⌄]      (我) │                    ← 徽章本身就是切换入口
   │ → main                │  │ → main              │
   │ 权限校验中间件改造…    │  │ 导出补工时列，提测中 │
   │ ☰ 1/3 任务      已 3 天│  │ ☰ 1/2 任务    已 1 天│                    ← 右下 = 当前状态停留多久
   └───────────────────────┘  └─────────────────────┘
```

- **状态色只用在状态上**，四处（统计格圆点、列头圆点、卡片徽章、浮层选项）严格同色同义，不另造颜色：
  开发中 = `--primary`（蓝）、待测试 = `--warning`（橙）、待合并 = `--plum`（紫）、已发布 = `--success`（绿）。
- 分支名用 `--font-mono`：它是代码里的标识符，等宽更好认、上下对齐。
- **停留时长是这张卡的 KPI**：进行中的分支显示「已 N 天」（当前状态待了多久），已发布的分支改显示「周期 N 天」
  （创建 → 发布）。同一个位置两种口径，但都是"多久"，不引入第二块面板。

### 2. 状态徽章即入口

卡片上的状态徽章是可点的（右侧带 `⌄`），点开 `.menu` 浮层选另外三档，末尾分隔线后是「编辑分支信息 / 删除分支」。
这样「看一眼 → 推一步」在同一处完成，不用先开详情再找按钮。

> 反例（不要做）：把状态做成卡片上的 `<select>`。原生下拉在卡片里高度、字体、边框都跟设计系统对不上，
> 而且没法在里面塞「当前」标记与编辑/删除入口。

### 3. 详情用抽屉，不用新页面

抽屉承载「状态时间 + 操作记录 + 关联任务」三块，与任务抽屉同一套 `.drawer` 骨架（同宽度、同头部高、同关闭手势）：

| 区块 | 内容 | 为什么这么排 |
| --- | --- | --- |
| 状态分段 | 四档 `seg grid4` | 与卡片徽章同一组状态，操作一致 |
| 停留说明 | 一行灰字：`已 3 天 · 开发中自 10-23 10:00` | 把数字还原成时间点，省一次心算 |
| 键值区 | 目标分支 / 负责人 / 创建时间 / 任务进度 | 两列 `.br-kv`，浅底块，不再逐行加分割线 |
| 状态时间 | 四行，未进入的置灰写「未进入」 | **四行永远都在**，不要只显示已发生的 —— 缺哪一步才是有用信息 |
| 关联任务 | 点一行打开任务抽屉 | 未完成在前，已完成的标题加删除线 |
| 操作记录 | 时间线（复用 `.tl-item`） | 与任务抽屉的「操作记录」同款，不新造时间线 |

关闭顺序有讲究：从抽屉里点任务时**先收起分支抽屉再开任务抽屉**，避免两层遮罩叠在一起（页面变暗两层、Esc 要按两次）。

### 4. 编辑弹窗

复用需求模块的 `.reqdoc-dlg`（左对齐标题 + 右对齐按钮组）：
分支名 / 目标分支 / 负责人 / 初始状态 / 备注。**编辑时隐藏「初始状态」** ——
状态只能走 `POST /api/branches/{id}/status`，否则会出现"改了状态但没进时间线"的数据。
弹窗文案也直说这一点：「状态不在这里改 —— 点分支卡片上的状态标签切换，那样才会记进时间线。」

## 附录 L：v3.3 备案页脚（2026-10-27）

### 1. 问题：fixed 页脚把底部的功能压住了

备案号最早是直接往页面上盖一条 `position:fixed;left:0;right:0;bottom:0` 的横条（32px，`z-index:9999`）。
它是**脱离文档流**的，所以谁在底部谁就倒霉：

- 侧栏 `.side-foot`（头像 + 退出登录，48px）被压掉大半，退出按钮点不到；
- 内容区 `.view` 底部 32px 被盖住，任务清单最后一行、看板列底部的「添加任务」都露不出来；
- 内容区的横向/纵向滚动条同样被盖住，滚到底也看不清。

根因不是颜色或位置，是**没有参与布局**。任何贴在窗口底部的信息，要么占位，要么就得给底下所有容器补 padding——
后者每加一个视图就要记得补一次，迟早漏。

### 2. 做法：页脚进布局，占一行 26px

```
body (flex column, height:100dvh)
├── .app (flex:1 1 auto; min-height:0)      ← 原来 height:100dvh，现在改由 flex 分配
│    ├── .sidebar …… .side-foot            ← 头像/退出完整露出
│    └── .main …… .views …… .view          ← 内容区底边 = 页脚顶边
└── footer.app-foot (flex:0 0 auto; height:var(--app-foot-h))   ← 备案号，居中一行
```

- 新增令牌 `--app-foot-h:26px`（`tokens.css`），页脚高度、`toast-layer` 的 `bottom` 都用它，改一处齐活。
- `body` 由「一块整高度」变成「`.app` + 页脚」的竖向 flex；`.app` 去掉 `height:100dvh`，改 `flex:1 1 auto;min-height:0`。
- 页脚只放一行灰字：`个人自由工具开发 · 赣ICP备2026026881号-1`，11.5px / `--text-3`，
  备案号是 `<a>` 指向 `beian.miit.gov.cn`（工信部要求可点），悬停变 `--primary-fg`。
- 预留 `<span class="af-ga" id="ga-record">` 给公安备案（`#ga-record:empty` 自动隐藏，不占位）。
- `toast-layer` 的 `bottom` 从 `24px` 改为 `calc(24px + var(--app-foot-h))`，提示条不再压备案号。

> 不要做：`position:fixed` + 给 `.view` 加 `padding-bottom`。
> 看板视图 `.view-flush` 是 `overflow:hidden` 的自定义滚动，补 padding 只会把列底切掉。

### 3. 自检

`node tools/shot-foot.mjs`（CDP 真 Chrome + `docs/ui-preview.html`，14 项）：页脚 `position=static`、
底边贴视口、高度 26px、内容区底边 = 页脚顶边、侧栏 `.side-foot` 底边不越过页脚、
退出按钮与头像用 `elementFromPoint` 命中自身（无遮挡）、任务清单视图底边对齐，外加 1280 收起态复验一遍。

## 附录 M：v3.4 周回顾 · AI 周报（2026-10-29）

### 1. 为什么要它

回顾页已经有「自动总结」，但那段话是**事实罗列**（"共交付 3 项，按期率 100%，完成的工作：…"），
能看不能用 —— 要发给 leader / 粘进周会纪要，还得自己重写一遍。AI 周报补的就是这一步：
**同一批数字，换成人话，四节成文，一键复制。**

### 2. 位置：紧紧跟「自动总结」后面

```
[自动总结]        ← 程序算的事实（蓝底，带左侧色条）
[AI 周报]         ← 同一批数据的改写版（白底，可生成/复制）
[统计格 / 工时 / 待确认 / 成员 / ...]
```

放在这里而不是塞进工具栏：它和「自动总结」是**同一件事的两种表述**，上下相邻才能一眼对比
"数字对不上没有"。工具栏只留「复制总结」，避免两个复制按钮并排分不清。

### 3. 交互：一次点击，四段结构

| 状态 | 界面 |
| --- | --- |
| 空态 | 一句说明 + 补充说明输入框（可留空）+ 「生成周报」 |
| 生成中 | 按钮置灰改「生成中…」，标题行写"正在写…（10–30 秒）"，正文位置出骨架屏 |
| 成功 | 正文四节（`## 本周完成 / ## 进行中 / ## 风险与阻塞 / ## 下周计划`），标题行显示周期，底部给「复制周报」 |
| 失败 | 回到空态，`toast` 说人话（AI 没配会顺带指路「个人设置 → AI 设置」） |

- **补充说明**是故意留的口子：任务里看不到"周三线上排查""跟客户对了口径"，
  与其让模型瞎编，不如让用户补一句（≤200 字）。
- **按「空间 + 周」缓存**在内存里（`aiReportCache["空间id#周偏移"]`）：来回翻周不会把写好的周报弄丢，
  也不会把上周的周报当成这周的；键里带空间 id 是因为换空间后同一个 `weekOffset` 是完全不同的一批任务。
  刷新页面即清空（周报是随手产物，不做持久化）。
- **正文只做一层 Markdown 渲染**：识别 `## 小节` 加重、其余原样 + `white-space:pre-wrap`。
  不引 Markdown 库、不解析整篇 —— 输出全程 `esc()`，模型说什么都不会变成标签执行。

### 4. 数字的归属：模型只负责措辞

提示词里明确「只能用给定事实」「数字必须与给定统计一致，不要自行加总」，
喂进去的事实清单（周期、统计、已完成、进行中、待确认、项目进展、成员、工时）全部来自 `ReviewService`。
这和附录 C 里拆需求/体检的原则是同一条：**AI 做语义，程序做判定**。

底部一行 `基于 3 项完成 / 2 项进行中 · 本次 1900 tokens（…）` 就是给用户核对用的：
数字和上面的统计格对不上，一眼能看见。

### 5. 自检

`node tools/check-ai-report.mjs`（CDP 真 Chrome + 演示数据，23 项）：面板位置、空态、
生成中置灰与骨架、四节标题与顺序、输出转义、用量行、按周缓存（翻走再翻回）、
与其它面板等宽、无横向溢出、标题字重对比、复制提示。
截图：`docs/ai-report.png`。预览稿的 mock 里给 `/api/ai/review/polish` 加了 400ms 延迟，
否则"生成中"一帧就闪过去了，测不到。

### 6. 顺手修的一个副作用

`ChangeBroadcastFilter` 把「非 GET 且成功」当变更广播，于是**只读**的 AI 交互
（拆需求出草稿 / 完成度体检 / 周报润色 / 改自己的 AI 配置）也会让空间里其他人白刷新一次。
现在豁免 `/api/ai/**`，但**精确放过 `/api/ai/reqdoc/{id}/tasks`** —— 那是真建任务的写操作，必须照常广播。

## 附录 N：v3.5 甘特图 V1.1 产品化与实底化（2026-10-30）

> 对应 `docs/gantt-product-development-spec-2026-10-30.md` G-01～G-05 与
> `docs/gantt-ui-optimization-2026-10-30.md` §2.1～§2.6。接口无变化，`docs/api.md` 不动。

### 1. 筛选与分组

- 甘特图请求沿用全局筛选状态，`loadGantt()` 使用 `ganttTaskParams()` 取
  `q/owners/pris/cats/reqs/tags/due/focus/blocked/sort`；**不传 `doneScope`**（那是看板分页参数）。
- 工具栏第二行提供筛选浮层（负责人/优先级/项目）、已应用数量、清除入口；
  筛选与看板/列表共用同一份 `state`，不另建第二套筛选状态。
- `groupBy = none | project | owner`：项目名走 `reqNameById()`，空值归「未关联项目」；
  负责人空值归「未分配」。分组头显示名称、任务数、折叠图标，本身不生成甘特条。
- 组内按 `(startDate||dueDate, dueDate||startDate, id)` 稳定排序；折叠只影响显示，
  不改变时间范围与顶部计数计算结果。

### 2. 时间窗口

- `rangeMode = auto | month`。auto 覆盖全部可见已排期任务并始终包含今天，前后留白；
  month 取 `anchorMonth` 的自然月，不持久化。
- 月交集统一为 `effectiveStart <= monthEnd && effectiveEnd >= monthStart`，
  其中 `effectiveStart = startDate||dueDate`、`effectiveEnd = dueDate||startDate`；
  跨月条按月份边界裁切，不越出网格。
- 「适配全部」回 auto；「上一月/下一月」在 auto 下会先切到月视图再翻月；
  「今天」auto 下滚到今天，month 下回到当前自然月并滚到今天。
- 月视图无交集任务时显示「本月没有排期任务」，时间轴仍保留以便翻月；
  今天线只在今天位于范围内时渲染。
- auto 范围超过 740 天（约 2 年）时自动切月视图并给出黄色提示，避免一次生成数千个日期表头。

### 3. 状态语义（done > blocked > overdue > 优先级色）

- `done = boardColumn==="done"`；`overdue = !done && dueDate < TODAY`；`blocked = !!blocked`。
- 阻塞且逾期：底色/虚线走 blocked，文字同时保留「逾期 N 天」。
- 条内：宽条显示任务名；`>=72px` 显示状态或百分比，`>=150px` 且为风险状态时状态与百分比并存；
  窄条用 `!`/`✓` 角标，状态同时写入左列 meta、原生 `title` 与 `aria-label`。
- 甘特条 `tabindex=0`、`role=button`、`aria-label`（任务、起止、进度、状态），
  Enter/Space 打开详情；focus 用独立 `:focus-visible` 描边，不依赖 hover。
- 底部图例：进行中 / 逾期 / 阻塞 / 已完成，不占工具栏主操作。

### 4. 拖拽闭环

- 拖动条/左右把手：按 `.gantt-axis` 实际 rect 与 `dayW` 换算日期，忽略 sticky 左列与 scrollLeft 偏差；
  保存仍走 `taskPayloadWith()`，不丢需求、分支、预估工时等字段。
- 指针进入时间轴左右 32px 内启动 `requestAnimationFrame` 横滚，速度随距离增加、封顶 18px/帧；
  横滚时按最新 pointer 坐标重算日期；`pointerup/pointercancel/Esc/重绘前` 取消 RAF。
- Esc 取消：不发请求、恢复原位置、清理 tooltip / dragging / 监听与横滚。
- 未排期行拖入时间轴：默认 `startDate = dueDate = 目标日期`；点击与拖动阈值 5px，
  小位移仍按点击打开详情；失败保留未排期状态并提示原因。
- 撤销通过 `toastAction()`：只恢复旧起止日期；撤销前比对最新缓存，任务已被再次修改时提示
  「任务已再次变更，未撤销」。未排期拖入也提供撤销（回到未排期）。

### 5. 偏好与显示口径

- `localStorage` key `ds.gantt.prefs.<workspaceId>`，保存 `showDone/dayW/groupBy/collapsed`；
  无 workspaceId 时只用内存状态；工作空间确定后会补读一次偏好（深链直达甘特图不丢设置）。
- 「显示已完成」仍是甘特图本地显示开关，不与全局状态筛选混用。
- 继续使用 track 背景网格，不按行按天生成 DOM；分组/折叠只重绘甘特图，不请求项目列表。
