「已发布」怎么操作

发布挂在「已完成」之下，不改状态、不改工时、不改完成时间；所有入口共用同一条服务端校验。

四步操作

3–4 次点击
1

完成任务

拖入「已完成」或点「标记完成」。写入完成时间、停表、生成完成快照。

completed_at / task_completion_record
2

标记发布

在已完成卡片或抽屉点「标记发布」，选择发布日期。必填，默认今天；可补录过去，不能未来。

POST /api/tasks/{id}/publish
3

查看与筛选

卡片出现「已发布」徽标；列表可按已发布/未发布筛选；看板仍在「已完成」列。

published_at
4

撤回或重开

点「撤回发布」清空日期与来源；撤回后才能取消完成。任何成员都可以撤回自己的任务。

POST /api/tasks/{id}/unpublish

版本发布不再直接沿用项目写权限：只有空间主/管理员、项目负责人，或该版本内至少负责一项任务的成员可以发布。普通成员可以标注自己的任务；如果该版本内没有自己负责的任务，即使是项目成员也不能发布版本。已知副作用：普通成员只要在该版本内有一项自己负责的任务，就会获得整个版本的发布权，本期接受。

「项目负责人」本期只认 requirement.owner_user_id；为空时项目级发布权不开放，由空间主/管理员代操作，不按创建人/任务负责人/显示名推断。所有写权限按用户 ID 严格判断，不用显示名兜底；未绑定账号时提示「未绑定账号，无法操作」。

已确认的边界

本期范围
  • 「项目负责人」只认 requirement.owner_user_id；为空时由管理员代操作，多负责人放到二期。
  • 版本发布后才完成的任务不补标，也不提供批量「补标发布」入口；版本页显示「未随本版本发布」，热修复走新的补丁版本。
  • 写权限严格按 owner_user_id，不用显示名兜底；上线前回填为空的历史负责人数据。
  • 版本归属以 version_task 为准；task.version_id 若保留，绑定/解绑同事务同步。发布、自动标记、日志同事务，按影响行写日志。
  • 版本通知改为「你负责的 N 项任务在该版本中」，不暗示都已发布；历史版本显示「历史版本未记录发布状态」。

本期不做：历史已发布版本不回填、批量补标入口、项目多负责人/独立发布角色。排期 7 人日，另留 0.5–1 人日缓冲。
