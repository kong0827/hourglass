模块明细

模块行可展开看阶段：开发（预估 + 普通计时）、测试（测试窗口内计时）、完成、未开始。评审 / 排期 / 设计 / 发布在驾驶舱不拆。

这一层的口径与实施落点

阶段不是新数据，只是同一批工作项的另一种分组。所有数字都能沿用现有查询推导，只读聚合，不加表和录入字段。

层级三层汇总

  • 工作项：预估 estimate_minutes、计时 time_log.minutes，是所有工时的原子来源。
  • 版本 / 模块 / 负责人：同一批工作项换个字段分组，合计始终回到同一组原子数据。
  • 跨版本：版本之间只比较总量与偏差，不做逐项对齐。

工时归集规则

  • 预估：Σ task.estimate_minutes，全部计入开发行；工作项没有阶段预估字段。
  • 实际：测试窗口（test_started_at → test_finished_at）内的计时 → 测试，其余 → 开发。
  • 边界：测试窗口只保留最近一轮，重开后的早期轮次计时会落回开发。

口径维度来源

  • 模块：task.category_id，未归类单列「未指定」，合计仍等于项目。
  • 负责人：task.assignee_id，未指派单列；换负责人后历史工时随工作项走。
  • 需求：目标版本需求（demand.version_id），只给条数、覆盖与停留；关联工时来自其工作项，避免与工时口径混算。

落点接口与查询

  • 聚合器：StageEffort 输出 { devMinutes, testMinutes }，再由现有分组字段二次汇总，一次查询产出多维度。
  • 版本：/api/phase/stats 每行加 devMinutes / testMinutes；版本对比复用同一快照。
  • 驾驶舱：/api/manager/projects/{id} 模块行加同字段；新增 /api/phase/rollup?dimension=stage|module|owner。
实施前确认：版本页默认维度放「阶段」（原型默认）还是「模块」；驾驶舱模块行默认收起（原型默认）还是展开；需求维度是否保留——它只给条数与覆盖，不产生工时。
