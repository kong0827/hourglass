# 版本页聚焦版改版（2026-11-17）

原型：`docs/preview/version-page-focus-2026-11-17.html`（单文件、可离线打开）

## 一、问题：三类数据同时铺开，页面没有主线

现网「流程引擎 · 按版本」把三块内容上下堆在一起，各自带一套工具栏和筛选：

1. 「198 个工作项还没有排版本」提示条
2. 阶段工时汇总（窗口外 / 窗口内 / 完成 / 未开始 四张卡）
3. 工作项明细表（295 行，带版本标签）

结果是：用户进页面想回答的「下一版是什么、进展如何、什么时候发」，被埋在 198 和 295 这两个大数字后面；页面上出现了 4 个搜索/筛选入口、2 套表格表头、1 个横跨顶部的提示条，视线没有落点。

## 二、设计原则：一屏一个主线，其余按需下钻

- **主线**：当前该关注的版本（下一版）+ 其他版本的健康队列。
- **降噪**：未排版本的 198 项只保留一条轻提示，不再抢占正文。
- **分层**：阶段工时汇总保留在列表页，但降为列表下方的次要区（默认折叠 6 行）；工作项明细、需求、发布记录收进「版本详情」子页签。
- **唯一主按钮**：整页只有一个实心主色按钮（当前场景下是「排入工作项」），「新建版本」降为描边按钮，避免三个蓝按钮打架。

## 三、改动对照

| 区域 | 现网 | 新设计 | 被移走的功能去向 |
| --- | --- | --- | --- |
| 页面头部 | 标题 + 多个操作按钮 + 未排版本横幅 | 标题 + 范围 chip + 一行统计（17 个版本 · 1 个计划中 · 16 个已发布 · 198 未排） | 未排版本数字并入统计，横幅降为一条轻提示 |
| 焦点区 | 无 | 「下一版」大卡：版本号、状态、排入需求/工作项/预估、进度条、发布计划、主按钮「排入工作项」 | 直接支撑「下一版要干什么」 |
| 版本列表 | 平铺 17 行，含状态列 | 「其他版本 16」分组队列：已发布组默认只露最近 3 个，按需展开；状态由分组标题承载，去掉状态列 | 搜索（按版本名）、只看需关注、排序保留在列表工具条 |
| 阶段工时汇总 | 四张零值卡 + 表格常驻正文，与列表、明细互相抢位 | **保留在列表页底部**：默认「跨版本对比」表，只露 6 行可展开 18 行；切到单版本后展示 6 个指标、窗口内外占比条与阶段/模块/负责人/需求四维表 | 口径与维度切换全部保留；位置后移、默认收起 |
| 工作项明细 | 295 行常驻正文底部 | 移入详情 →「工作项」页签，分页 + 单次最多 100 条 | 无丢失；列表页不再承载明细 |
| 发布日程 | 无独立入口 | 页签「发布日程 3」，按时间排计划，明确「计划只是排期，不代表实际发布」 | 新增轻量视图，不新增页面 |
| 版本详情 | 抽屉/跳页混用 | 同页子视图（hash 路由 `#/version/<id>`），概览 / 工作项 / 需求 / 投入分析 / 发布记录五个页签 | 返回列表保留滚动位置 |

## 四、关键交互

- 版本行整行可点（含键盘 Enter / 空格），进入详情；ESC 或「‹ 版本」返回列表。
- 列表默认折叠已发布组；「展开其余 13 个已发布版本」就地展开，搜索时自动显示全部命中项。
- 「只看需关注」= 进度落后或有阻塞的版本；与搜索、排序可叠加。
- 阶段工时汇总默认跨版本对比（版本 / 状态 / 工作项 / 预估 / 实际 / 窗口外 / 窗口内 / 偏差），点任意行进入该版本详情的「投入分析」。
- 汇总切到单版本后出现维度切换（阶段 / 模块 / 负责人 / 需求）；指标、占比条、表格行都可下钻到该版本的工作项。
- 详情页「概览」把发布拆成「计划 / 实际」两栏，并注明「计划 ≠ 事实」；交付链路用标签展示。
- 空状态分两种：V1.2.0 还没有工作项（引导排入），以及已发布版本没有计时数据（说明首次计时后出现）。

## 五、数据口径（原型内）

- 17 个版本 = 1 个计划中（V1.2.0）+ 16 个已发布（2026-11-10 批次 … V0.5）。
- 198 个未排版本工作项中 155 项已完成——所以提示条用中性图标而非警告色，避免"待办 198"的错觉。
- 阶段汇总的「未绑定版本」行按 198 项 / 155 完成、预估 1080h、实际 1020h 演示；真实页面读汇总接口，不在这里拼数。
- 进度 = 看板完成数 / 工作项总数，随看板自动计算，不在本页人工维护。

## 六、验证

- 45 项自动化检查全部通过（焦点卡内容、折叠 3 行、搜索、路由、页签、分页与 100 条上限、ESC 返回、阶段汇总 6/18 行与维度切换、深色主题、移动端无横向溢出、图标按钮均有可读名称）。
- 表头与行五列左边界完全对齐（277 / 674 / 830 / 1115 / 1267）。
- 移动端（390px）：隐藏侧栏与次要面包屑，焦点卡纵向堆叠；详情页签单行可横滑，表格横向滚动，不再逐字竖排。

## 八、待确认

1. 「按阶段查看 →」目前是占位入口，是否保留为独立视图，还是彻底并入详情的「投入分析」。
2. 「发布日程」是否一期就做，还是先只保留版本列表 + 详情。
3. 详情页签默认进「概览」，是否对「计划中」版本默认落到「工作项」（更贴近排入动作）。
4. 列表阶段汇总与详情「投入分析」有部分重叠：前者负责跨版本对比与多维拆分，后者负责单版本上下文；是否接受这种分工，还是详情页签只保留阶段表。
