## 0. 结论

**1）是否符合既定要求：核心交互要求已满足，规则接线仍有缺口。**

列表简化、详情子页面、多版本发布计划三项已经闭环；进行中版本的发布与日程关系在界面口径上已经讲清，但关闭动作的计划门禁没有接线；功能不丢失、一页式证据与全链路这两项，原型保住了入口和摘要，但没有复刻完整工作区。原型不能当作功能已实现。

**2）交互是否简单、流畅、学习成本低：v2 比 v1 明显更顺，但仍不是零学习成本。**

v2 修掉了 8 个具体摩擦点，核心动作收敛为“一行一个主操作 + `⋯` 兜底”。记录发布从“三个入口三种行为”变成“三个入口同一张确认单”；多版本计划从“藏在全部项目勾选里”变成“日程页可直接从版本创建”；计划与事实从“分散在两个 Tab”变成“概览一张卡对照”。核心路径 1–3 次点击可到达，新用户只需要理解三个词：版本状态、计划、记录。

**3）还能不能优化：能，但剩下的主要是“接真实能力”和“补边界”，不是继续加页面。**

下一步优先级最高的不是再画界面，而是把记录发布表单与后端字段对齐、把计划完成与关闭版本的规则真正接上、补权限只读。原型侧还可以加“记录后的下一步引导”和日程按版本搜索。

### 1.1 发布与日程的流转（原型已按此表达）

1. 日程里先有**计划**：环境、时间、覆盖范围、覆盖版本，状态草稿/就绪。
2. 版本里写**事实**：环境、结果、范围、是否引用计划；写入后不可改。
3. 成功 + 生产 + 非回滚才锁定内容；版本仍是**进行中**，工作项不会自动完成。
4. 计划只有在被引用、且覆盖的每个版本都完成成功生产发布时才自动完成；测试、预发、回滚、部分成功都不算。
5. 发布完成不等于版本完成。规则上，关闭版本前若有草稿/就绪计划会被拒绝，必须先完成或取消计划；原型关闭动作未接这道门禁，只在文案中说明。

对应后端证据：`VersionReleaseService` 第 853–866 行、`ProjectVersionService` 第 108–110 行与第 286 行。

### 2.2 关键路径步数

| 任务 | 路径 | 操作次数 |
|---|---|---|
| 从列表记录一次发布 | 点行 → 记录发布 → 确认保存 | 3 次点击（默认值可直接保存） |
| 在详情记录一次发布 | 记录发布 → 确认保存 | 2 次点击 |
| 从版本创建多版本计划 | 发布日程 → 从版本创建计划 → 勾选 N 个 → 下一步 → 填写 → 创建 | 5 步，其中只有一次表单 |
| 查看多版本计划覆盖了谁 | 日程点该行 | 1 次点击 |
| 搞清“计划 vs 实际” | 打开版本概览 | 0 次点击（首屏可见） |
| 看某版本的发布记录 | 概览“查看记录”或发布记录 Tab | 1 次点击 |

### 2.3 学习成本

**只引入三个概念：**

- **版本状态**：计划中 / 进行中 / 已发布 / 已关闭；记录成功生产发布不会把进行中改成已发布。
- **计划**：日程里排的环境、时间、覆盖范围；可以覆盖多个版本。
- **记录**：某个版本实际发生了什么；一次一条，写入不可改。

**降低学习成本的做法：**

- 每个版本行只有一个主操作：计划中“开始开发”，进行中“记录发布 / 再记录一次”，已发布“查看发布记录”，终态“查看历史”。
- 危险动作统一收进 `⋯`，并且删除单独分隔。
- “计划 ≠ 事实”在同一套界面的三个决策点重复：概览发布卡、发布记录页、记录确认单。
- 记录单的默认值是安全且常见的：生产 / 成功 / 全量 / 不引用计划；只有改环境或结果时才出现黄色风险提示。
- 记录失败、回滚、预发不会新增锁定，文案直接告诉用户“这次不锁定”。

**仍然存在的学习成本：**

- “计划完成”不是用户点完成，而是系统按覆盖版本自动判断；这条规则必须读一次说明才能完全理解。
- 记录单有 5 个字段，其中 4 个有默认值、说明可选，首次使用仍需确认“环境 / 结果 / 范围”的含义。
- “已发布 N 次”对进行中版本表示“有过成功生产事实”，不是“版本已结束”，需要状态与徽标一起读。

## 3. v2 优化清单

### 3.1 概览：先回答“计划是什么、实际发生了什么”

- 新增发布卡，左侧计划（环境/时间/状态/覆盖/查看计划），右侧实际（日期/结果/锁定/查看记录）。
- 计划为空时给“去排期”，实际为空时给“去记录”，两个出口都可用。
- 里程碑目标与达成状态并入发布卡标题右侧，删掉独立里程碑卡。
- 版本说明与参与人并排，首屏少一张整宽卡片。

截图：`detail-1440`、`mobile-detail-390`

### 3.2 列表：状态不再有歧义

- 进行中但已有成功生产记录：显示“进行中”+“已发布 N 次”。
- 只记录过预发/失败/回滚：显示“已记录 N 次”，不冒充已发布。
- “最近发布”列显示日期 + 环境；失败记录带结果。
- 行内主按钮随状态变化，避免出现不可用动作。

截图：`list-recorded-1440`

### 3.3 记录发布：一个入口，一次确认

- 头部、列表行、空态、`⋯` 统一打开记录单。
- 记录单包含环境、结果、实际范围、引用计划、说明；默认生产/成功/全量/不引用计划。
- 环境或结果改变时，提示实时切换：只有成功 + 生产 + 非回滚才锁定内容。
- 保存后仍保持“进行中”，Tab 切到发布记录并展示“第 N 次记录”。
- 预发成功、失败、回滚只留事实，不锁内容；成功生产才锁。

截图：`detail-record-sheet-1440`、`detail-releases-recorded-1440`、`mobile-record-sheet-390`、`mobile-releases-recorded-390`

### 3.4 发布计划：两个入口，一个计划 sheet

- 日程页“从版本创建计划”打开选择器；搜索版本/负责人，按项目分组，勾选多个，第一个为主版本。
- 选择器底部实时显示“已选 N 个 · 主版本 X”，未选时“下一步”禁用。
- 多版本日程行不再只打开主版本，而是打开计划 sheet：时间、环境、覆盖范围、负责人、覆盖版本数，以及每个版本的发布事实和“打开 →”。
- 单版本行仍直接进入版本详情，保持短路径。

截图：`picker-1440`、`picker-selected-1440`、`plan-multi-1440`、`schedule-multi-sheet-1440`、`mobile-picker-selected-390`

### 3.5 可用性与响应式

- 日程行支持 Enter/Space 打开；ESC 关闭最上层浮层。
- 手机端：版本选择器搜索框固定 34px，不再被响应式 flex 拉高；底部已选/主版本可换行；记录单字段单列堆叠。
- 详情子页桌面 1200、手机 390 满宽；列表页头隐藏、左导航在桌面保留。

截图：`mobile-picker-selected-390`、`mobile-record-sheet-390`

## 4. 原型边界与剩余风险

1. **发布工作区没有重画。** 记录单只覆盖“写一条事实”的主要字段；制品、SHA256、目标键、执行人、检查证据、实际工作项、偏差原因等完整字段仍在原发布工作台。原型里“编辑计划”“查看快照明细”是占位。
2. **计划完成没有接线。** 记录单可以选择“引用计划”，但原型不会自动把计划置为已完成；界面明确写“未接计划完成判断”。真实实现必须按 `VersionReleaseService` 的规则接。
3. **关闭版本的计划门禁没有接线。** 原型没有在关闭时检查草稿/就绪计划；只在说明里写了规则。实现时按 `ProjectVersionService` 第 286 行接。
4. **一页式交付说明只有摘要。** 交付说明 sheet 展示承诺与实际、需求兑现、质量、遗留问题，页脚保留“完整一页式”入口；变更说明、验收、支持、证据附件、口径附录仍在原页面。
5. **全链路仍是跳转。** 交付链路卡展示“需求 → 工作项 → 计划 → 发布 → 说明”，需求行、工作项行、快照明细是提示占位；单张“全链路视图”产品里不存在，不能对外说已有。
6. **权限未接线。** 只读项目、不可写版本、批量勾选在原型里没有判断；实现必须复用现有写权限。
7. **数据是内存 mock。** 记录、关闭、批量计划刷新后复原；没有后端、审计和并发处理。
8. **响应式只验证 1440 与 390。** 平板、横屏、超宽屏未走查。
9. **记录单不是最终表单。** 环境/结果/范围/引用计划/说明是产品语义字段，开发前需要与发布 DTO 做一次逐字段映射，避免“原型有、后端没有”或反之。
10. **原型只展示最近一次发布记录。** 多次尝试的完整列表、失败/回滚对交付偏差与准时统计的影响没有展开；真实实现必须按记录列表聚合，不能只看最后一条。

## 5. 建议的下一步

**P0（开发前必须定）**

1. 用真实发布 DTO 校准记录单字段，明确哪些必填、哪些默认、哪些由系统带入。
2. 接计划完成与关闭版本门禁，至少覆盖四个用例：未引用计划、预发成功、生产失败/回滚、多版本计划只完成一个。
3. 接权限与只读：只读项目禁选、不可写版本隐藏记录/关闭/编辑。
4. 把计划 sheet 的“编辑计划”换成真实发布计划工作区入口。

**P1（体验继续优化）**

5. 记录成功后给下一步引导：“继续处理工作项 / 关闭版本 / 查看计划”，而不是只弹 toast。
6. 日程增加按版本搜索、按“无计划版本”筛选，方便补排期。
7. 多版本计划 sheet 增加“哪些版本还没有成功事实”的聚合提示，减少逐个打开。
8. 平板与横屏补走查；记录单在窄屏考虑分步，而不是一次展示 5 个字段。
