## v2 优化版增量（2026-11-16 晚）

v1 的能力去向不变，v2 只改交互与表达，不新增业务概念：

- 概览新增“发布”卡，左计划、右实际，里程碑目标/状态并入卡头；独立里程碑卡移除。
- 列表状态旁增加“已发布 N 次 / 已记录 N 次”；进行中版本不再让人误读为“未发布”。
- 头部、列表行、空态、`⋯` 统一打开“记录发布”确认单；默认生产/成功/全量，预发/失败/回滚只写事实不锁内容。
- 发布日程“从版本创建计划”不再 toast，改为多版本选择器：搜索、按项目分组、多选、第一个为主版本。
- 多版本日程行改开“计划 sheet”，列出全部覆盖版本与各自发布事实；单版本行仍直接进详情。
- 记录/计划 sheet 都写明“计划 ≠ 事实”和计划收口口径；页面不假装已接自动完成。

v2 截图见本目录 `version-redesign-v2-*.png`，自检见评审文档最后一节。

## 结论

P0 五项已补进原型：需求 Tab、`⋯` 菜单三份说明、深链/刷新/同项目切换、日程状态细分与「本周前后」、全部项目勾选批量建计划。P1 不塞回详情页，改为「更多分析 → 版本档案」出口。

版本详情已从右侧抽屉改为**应用内子页面**：左导航保留，列表页的页头和视图页签让位，详情自己带「← 版本」返回、5 个 Tab 和独立滚动区。原产品 `version.js` 本来就是页面，抽屉只是上一版原型的简化，这次改回页面并放宽到 1120px 内容宽。

“入口少了、功能没少”只对产品成立，对原型不成立：列表把 11 个卡片动作收成一个主按钮 + `⋯`，详情把 8 类筛选、发布工作台和一页式交付说明收成入口/摘要。**原型不能当作功能已实现**，下面三处尤其要按原页面接：

- 版本档案只是原型里的承接页，**报表侧还没有模块/需求/阶段维度的透视视图**。现有报表按项目/成员/公司/角色/职能汇总，阶段与模块只在版本详情里出现过。
- 一页式交付说明、发布工作台、发布快照明细与需求/工作项全链路跳转**没有在原型里复刻全文**，只保留了入口、摘要和交付链路卡。实现时应继续使用原页面，不能让 sheet 取代。
- 权限与只读在原型里只有文案，**没有按项目可写性禁用勾选或隐藏动作**。实现时必须沿用 `phase.js` 现有的写入口判断。

## 记录发布与发布日程

两者不是同一张表：

| | 发布日程 | 记录发布 |
|---|---|---|
| 存什么 | 计划：草稿 / 就绪 / 已完成 / 已取消 | 事实：环境、操作、结果、目标键、制品与 SHA256、实际工作项、执行人、偏差原因 |
| 谁读 | 版本页「发布日程」页签、详情里的计划摘要 | 版本详情「发布记录」Tab、发布快照明细、一页式交付说明 |
| 能否改 | 草稿/就绪可改；完成后只读且不可复用 | 写入即不可变；失败与回滚也是事实 |
| 是否必填 | 可以先没有计划，直接记录 | 记录时可引用就绪计划，也可不引用 |

联动规则（`VersionReleaseService`）：

1. 记录引用的计划必须覆盖当前版本；**已完成计划不可复用**，只能新建计划或按“紧急记录”不引用计划。
2. 计划不是就绪状态也允许记录，但会提示“计划非就绪状态，受控记录已发生事实”；环境/覆盖范围/目标键与计划不一致会进入偏差提示。
3. 只有**成功、生产环境、非回滚**的记录，且计划覆盖的所有版本都已完成成功生产发布，计划才自动置为「已完成」（`VersionReleaseService` 第 859–866 行）。测试、预发、回滚、部分成功都不收口。
4. 日程页只读计划，不写事实；记录发布后日程里唯一的变化是相关计划可能变为「已完成」，实际记录本身不会出现在日程行里。

### 进行中版本怎么走

以支付网关 v2.2（进行中，目标 11-27）为例，一个发布批次的实际流转是：

1. **先有计划**。发布日程里有 11-27 20:00 的生产计划，覆盖 v2.2，状态「草稿」。这一步只写计划，不产生发布事实。
2. **在版本里记录**。进入 v2.2 → 发布记录 → 记录发布；选择生产、成功、实际范围与结果，可以引用上面这份计划，也可以不引用。
3. **写事实，不改状态**。保存后生成不可变的发布记录和范围快照。成功的生产记录会锁定版本内容（不能再改范围、说明），但**版本状态仍是「进行中」**，工作项也不会被自动置为已完成。原型里的「记录发布后」截图就是这个状态：`进行中` + `发布记录 1` + 计划仍是 `草稿`。
4. **计划是否收口**。只有记录引用了计划，且计划覆盖的每个版本都有成功、生产、非回滚的发布，计划才自动变「已完成」。未引用计划、测试/预发、失败/回滚、只覆盖部分版本，日程里的计划都保持原状。
5. **最后才结束版本**。发布完成不等于版本完成；需要人工「关闭版本」。如果还有草稿/就绪的发布计划，关闭会被拒绝（`ProjectVersionService.end` 第 286 行），要求先完成或取消计划。关闭后才进入终态，生命周期里补上「关闭版本」。

对应证据：成功生产记录才写工作项「已发布」并触发计划收口（`VersionReleaseService` 第 841–866 行）；内容锁定按正式成功发布派生，不按状态（`ProjectVersionService` 第 108–110 行）；关闭前检查未完成计划（第 286 行）。

## 已知缺口
