# 沙漏产品 UI/UX 体验审查 · 最终结论

> 审查日期：2026-11-07 ~ 2026-11-08  
> 审查对象：沙漏（本地运行实例，桌面 1440×1000、移动 390×844）  
> 证据基础：真实页面截图 + 前端/后端代码交叉核查  
> 完整报告：[产品UIUX体验审查与优化报告.md](产品UIUX体验审查与优化报告.md)  
> 设计参考：[产品UIUX优化设计参考.html](../audit/产品UIUX优化设计参考.html)  
> 证据截图：仅存本地，不随公开仓库分发

---

## 一、一句话结论

**沙漏不需要推倒重做，也不应先做视觉翻新。**  
产品骨架、信息架构和视觉基础已经成立，当前最值得投入的是三件事：**守住用户数据、让失败结果说真话、保持操作上下文连续**。完成这三类改造后，再谈效率与视觉密度。

---

## 二、整体判断

### 已经做得好，应当保留

| 能力 | 结论 |
|---|---|
| 视觉基础 | 颜色、语义色、圆角、阴影、动效、暗色主题、减少动画偏好均有统一令牌，风格一致 |
| 全局搜索 | Cmd/Ctrl+K 已支持项目、工作项、文档、需求、用例跨对象搜索，键盘可达，实测能直达文档 |
| 任务创建 | 默认项目按“当前项目 > 唯一筛选项目 > 最近使用”取值，具备上下文意识 |
| 任务表单 | 已有分组与折叠（基本信息、缺陷、归属、时间、人员、评论），不是无组织堆叠 |
| 未保存保护 | 任务抽屉关闭与路由切换会确认；文档返回列表提供取消 / 不保存 / 保存并关闭 |
| 测试闭环 | 创建用例 → 执行失败 → 填写备注 → 转缺陷 → 自动打开缺陷任务 → 覆盖矩阵统计，全链路真实可用 |
| 响应式 | 本次所测 7 个主视图在 390px 下无页面级横向溢出，列表转卡片、底部导航、抽屉固定底栏可用 |
| 业务视图 | 看板、列表、日历、甘特、项目总览、版本、成员负载、报表的信息层级总体清楚 |

### 真正的差距：三类“体验可信度”

1. **数据安全** — 文档离开与保存竞态、用例关联加载失败，都可能让用户丢掉已输入内容。
2. **结果可信** — 部分请求失败被渲染成“空态”或“全部成功”，用户无法判断数据是否真的写入。
3. **上下文连续** — 从项目进入文档不带项目筛选；不同表单的关闭、保存、键盘提交规则不一致。

这三类问题不会让页面“变丑”，但会让用户**不敢信、不敢用、重复操作**，优先级高于任何视觉优化。

## 三、问题结论与优先级

共确认 **18 项**问题：**P0 3 项、P1 8 项、P2 5 项、P3 2 项**。

### P0：必须优先修复（数据可能丢失或被错误覆盖）

| 编号 | 问题 | 难度 | 本质 |
|---|---|---:|---|
| UX-01 | 文档侧栏切换与刷新缺少完整未保存保护 | 中 | 侧栏直接清空 `reqDocDirty` 与编辑态，路由守卫未被文档模块完整接管 |
| UX-02 | 文档保存竞态与冲突恢复可能覆盖本地内容 | 中 | 保存无锁、无版本校验；409 后“查看最新内容”会用服务端内容覆盖本地 |
| UX-03 | 用例需求候选加载失败可能误清空原关联 | 中 | 候选接口失败返回空数组，保存时提交 `demandId: null` |

### P1：紧随其后（结果可信与权限一致）

| 编号 | 问题 | 难度 |
|---|---|---:|
| UX-04 | 项目与测试弹窗未保存保护不一致 | 中 |
| UX-05 | 任务评论、检查项、时间线失败被伪装成空态 | 低 |
| UX-06 | 批量删除和撤销可能虚报全部成功 | 中 |
| UX-07 | 测试提交缺少防重复，加载更多失败可能卡住 | 低 |
| UX-08 | 文档加载静默失败，导入失败可能遗留空文档 | 中 |
| UX-09 | 项目“管理文档”丢失项目上下文 | 低 |
| UX-10 | owner 被显示为管理员，权限说明与后端不一致 | 低 |
| UX-11 | viewer 部分设置控件形成可编辑假象 | 中 |

### P2 / P3：效率与视觉打磨（不阻塞上线）

- **P2**：任务保存后强制关闭（UX-12）、普通弹窗键盘提交不一致（UX-13）、移动首屏筛选与搜索入口（UX-14）、需求池/文档动作密度（UX-15）、日历对比度（UX-16）。
- **P3**：分支空态空间利用（UX-17）、分享无 token 时保留空甘特框架（UX-18）。

## 四、建议实施顺序

### 第一批：数据安全与真实反馈（先做，范围集中）

**UX-01、UX-02、UX-03、UX-05、UX-06、UX-07、UX-09、UX-10**

- 文档：统一 dirty 守卫到路由层；保存加锁 + 版本校验；冲突时保留本地草稿，提供对比/另存，不直接覆盖。
- 用例：候选加载失败时保留原关联并显式报错，禁止提交空值。
- 失败反馈：评论/检查项/时间线失败显示“加载失败 + 重试”，不渲染空态；批量操作按成功/失败分别计数，撤销同理。
- 测试：保存/执行/转缺陷增加 busy 与禁用；加载更多失败恢复按钮。
- 上下文：项目“管理文档”携带项目筛选。
- 权限：owner 不进入角色下拉；权限说明与后端 `requireWriter` / `requireOwner` 对齐。

### 第二批：表单、权限与一致性

UX-04、UX-08、UX-11、UX-13。统一弹窗 dirty 守卫、加载失败可重试、viewer 控件只读、Cmd/Ctrl+Enter 覆盖范围一致。

### 第三批：效率与视觉微调

UX-12、UX-14、UX-15、UX-16、UX-17、UX-18。只在第一、二批回归通过后开始，避免与安全性改动混在一起难以定位问题。

## 五、竞品借鉴边界

| 参考对象 | 可以借 | 不要照搬 |
|---|---|---|
| Linear | 命令面板、键盘优先、保存即生效的轻反馈 | 复杂快捷键体系、全键盘工作流 |
| 飞书 | 信息分层、文档协作、通知聚合 | 重型组织架构、审批流、多维表格 |
| 企业微信 | 消息触达与移动端习惯 | 部门/组织架构（沙漏当前无此能力） |
| Jira | 缺陷闭环、状态与版本概念 | 复杂工作流编辑器、字段级权限 |
| Trello | 看板拖拽的直观性 | 以卡片为唯一信息载体 |
| Asana | 项目总览与目标视图 | 多层目标/OKR 体系 |

原则：**只优化现有路径，不新增模块；不为视觉统一牺牲业务信息或操作效率。**

## 六、验收原则与回归底线

任何改动必须同时满足：

1. **现有功能不退化** — 原有入口、数据、权限行为保持可用。
2. **默认路径不增加步骤** — 安全确认只在“有未保存内容”时出现。
3. **失败可恢复** — 失败必须可见、可重试，不能伪装成空态或成功。
4. **权限前后一致** — UI 可操作项与后端校验完全对应。

最低回归集合：

- 项目：创建、编辑、误关闭、Enter、归档/删除、管理文档上下文。
- 任务：各入口默认项目、保存关闭/继续、深链、评论/检查项/时间线失败。
- 列表：批量全成功、部分失败、全失败、撤销部分成功、重复点击。
- 文档：保存中继续输入、409、侧栏/后退/刷新、导入各阶段失败。
- 测试：用例 dirty、候选失败、保存/执行/转缺陷双击、加载更多失败。
- 权限：owner/admin/member/viewer × 项目默认参与/只读/不可见。
- 响应式：1440 / 1024 / 390；移动文档编辑器、普通弹窗、横屏。

## 七、边界声明

- 本轮**未修改任何项目功能代码**，仅新增审查报告、设计参考与证据截图。
- 所有结论均来自页面实测或代码核查；未实测项已在报告第十一章标记 **“待验证”**，包括：有效邀请/分享、看板与甘特拖拽故障、批量操作真实部分失败、viewer 真实角色页面、通知与邮件实际送达、移动文档编辑器与横屏。
- 本地截图中出现的空间名/列名乱码，`/api/workspaces` 原始 JSON 即为乱码，判定为数据库或种子导入编码问题，**不计为 UI 组件缺陷**，需单独备份后核查。
- 当前产品**没有“测试计划”“部门/组织架构”能力**，本结论不建议为对标而新增。

## 八、最终建议

**先确认范围，再动代码。**  
建议以第一批 8 项作为一次独立迭代，完成后再评估第二、三批。若只能做一件事，优先做 **UX-02 文档保存竞态**——它直接决定用户是否敢在沙漏里写东西。
