# DevStudio 甘特图产品化优化开发文档

- 日期：2026-10-30
- 适用项目：`devstudio-server`
- 文档性质：交给开发 AI 的实施规格，不是现状说明
- 建议版本：甘特图 V1.1（产品能力）/ V1.2（数据规模）
- 关联文档：`docs/gantt-ui-optimization-2026-10-30.md`（甘特条、颜色、把手等纯视觉优化）

> 本文档不重复视觉文档中的 CSS 细节。两份文档可以先后实施，但不要两个会话同时改 `app.js` 的甘特图同一函数；若并行开发，合并时不得回滚另一批改动。

---

## 1. 背景与现状判断

当前甘特图已经具备：开始/截止日期排布、sticky 任务列和表头、今天线、三档密度、显示/隐藏已完成、整体拖动改期、两端调整日期、进度填充、未排期列表，以及加载/空态/失败处理。

当前定位仍然是“任务时间条视图”，主要差距是：

1. 任务一多缺少筛选、分组和折叠。
2. 时间轴只能改变像素密度，缺少时间窗口导航。
3. 逾期、阻塞、进度等风险信息不够醒目。
4. 未排期任务不能直接拖入时间轴，拖动也不能撤销。
5. 数据复用 `/api/tasks/list?sort=due`，最多 500 条，存在漏任务和大数据量渲染问题。

本次目标不是重做甘特图，更不是引入专业项目管理全家桶，而是优先补齐“找任务、看风险、调排期”三个高频闭环。

## 3. 现有代码约束

### 3.1 主要代码落点

- `src/main/resources/static/index.html`：甘特图工具栏、分组/范围控件、图例。
- `src/main/resources/static/js/app.js:3636-4043`：甘特图全部状态、渲染和拖拽。
- `src/main/resources/static/css/gantt.css`：甘特图样式。
- `tools/preview/preview-mock.js`：预览测试数据。
- `tools/shots/shot-gantt.mjs`：真实浏览器截图，可扩展断言。
- `docs/ui-redesign-spec.md`：前端口径变更必须追加附录。
- `docs/api.md`：只有接口变化时更新。

### 3.2 必须遵守的项目约定

- `app.js` 是 IIFE，顶层函数不是浏览器全局函数；自动化测试通过 `.nav-item[data-view="gantt"]` 或 `#/gantt` 进入。
- 请求继续使用 `window.API` / 当前 `API` 封装，不要绕过 `withWorkspace()`。
- 后端业务失败可能是 HTTP 200 + `ApiResult.code != 0`，不得只判断 HTTP 状态。
- 任务快捷改期必须使用 `taskPayloadWith(task, patch)`。当前后端是全量 PUT，漏字段会把关联需求、分支、预估工时等清空。
- 拖拽期间继续遵守 `ganttState.drag` 防刷新机制；不得让 SSE 或重复 render 打断拖动。
- 日期计算复用 `parseDate`、`iso`、`addDays`、`dayDiff`、`TODAY`，不要另写一套时区逻辑。
- 文本插 HTML 必须 `esc()`；不要引入内联事件处理器。
- 静态资源变化后，`static/sw.js` 的 `CACHE_NAME` 必须递增；当前基线为 `devstudio-shell-v34`，若视觉文档已先递增，则在最新值上再递增，不要机械写死 v35。
- 改完前端运行 `node tools/preview/gen-preview.js`。
- 不主动部署、不主动 Git 提交，除非用户另行明确要求。

## 4. G-01：筛选、分组与折叠

### 4.1 筛选口径

最低实现应复用当前 `state` 和 `boardParams()` 的筛选字段，不维护第二份相互不同步的筛选状态。

`loadGantt()` 的请求由：

```js
API.get("/api/tasks/list", { sort: "due" })
```

调整为携带当前有效筛选条件，例如：

```js
API.get("/api/tasks/list", boardParams({ sort: "due" }))
```

实施前检查 `boardParams()` 是否包含只适合看板的参数；如有则只挑选 `/api/tasks/list` 已支持的 `q/owners/pris/cats/reqs/tags/due/focus/blocked/noDue`。

工具栏至少提供：

- 项目筛选。
- 负责人筛选。
- 优先级筛选。
- 活动筛选数量与“清除筛选”。

如果完整筛选面板复用成本过高，可复用现有全局筛选状态，只在甘特图显示“已应用 N 项筛选”和清除入口；不得表现为无筛选，实际却沿用了隐藏条件。

### 4.2 数据一致性

- 已排期区、未排期区和顶部计数必须使用同一份筛选结果。
- “显示已完成”继续作为甘特图本地显示开关，不与全局状态筛选混为一谈。
- 筛选改变后重新请求并重算范围；使用 `ganttState.seq` 丢弃过期响应。
- 项目筛选沿用 `reqId` / `reqs` 口径，不要把 `reqDocId` 当项目 ID。

### 4.3 分组与折叠

新增 `groupBy`：

- `none`：不分组，保持当前按开始日期排序。
- `project`：按项目分组。
- `owner`：按负责人分组。

规则：

- 项目名通过 `reqNameById()` 获取；空值归入“未关联项目”。
- 负责人空值归入“未分配”。
- 分组头显示名称、已排期任务数、折叠图标；分组头不是任务，不生成甘特条。
- 组内按 `(startDate || dueDate, dueDate || startDate, id)` 稳定排序。
- 折叠状态在本次会话保留；建议按工作空间保存到 localStorage。
- “全部展开/全部折叠”可选，不阻塞验收。

### 4.4 验收

- 筛选项目后，其他项目任务和未排期任务都不再出现。
- 按负责人分组后，同一任务只出现一次，未分配有独立分组。
- 折叠只影响显示，不改变任务数据和时间范围计算结果。
- 快速连续切换筛选时，旧响应不能覆盖新结果。

## 5. G-02：时间窗口导航

### 5.1 状态建议

在 `ganttState` 增加：

```js
rangeMode: "auto",       // auto | month
anchorMonth: null,        // month 模式的当月 1 号，Date
```

不要持久化 `anchorMonth`，避免用户下次打开落到很久以前的月份。

### 5.2 自动范围

保留现有口径作为 `auto`：

- 覆盖全部可见已排期任务。
- 始终包含今天。
- 前后保留少量 padding。
- 首次渲染定位到今天，“适配全部”回到该模式。

### 5.3 月视图

- 时间轴为 `anchorMonth` 的自然月。
- 只显示与该月有交集的任务；未排期区不受月份影响。
- 与月份有交集的判定统一为：

```text
effectiveStart = startDate || dueDate
effectiveEnd   = dueDate || startDate
effectiveStart <= monthEnd && effectiveEnd >= monthStart
```

- 跨月任务的条必须按时间轴边界裁切，不能因 left/width 超出网格导致布局异常。
- 顶部显示“2026 年 10 月”和当前范围任务数。
- “上一月 / 下一月”移动 `anchorMonth`。
- “今天”：auto 模式滚动到今天；month 模式跳到当前自然月并滚动到今天。
- 月视图没有交集任务时显示“本月没有排期任务”，不要显示成整个工作空间没有任务。

### 5.4 本轮不做真正周/月刻度聚合

当前 20/28/40px 仍是“每天像素密度”，不是日/周/月时间粒度。真正的周/月聚合刻度放到后续，不要在同一批里半实现。

### 5.5 验收

- 跨月任务在两个月视图中都能看到，条的位置和宽度正确。
- 只有开始日期、只有截止日期、单日任务都能正确判断交集。
- 前后翻月不丢筛选、分组、显示已完成和缩放设置。
- 时间范围变化后，今天线只在今天处于范围内时显示。

## 6. G-03：风险状态与信息表达

视觉底色、边框、进度透明度和把手样式优先沿用 `gantt-ui-optimization-2026-10-30.md`，本节只规定产品语义，不重复指定一套冲突 CSS。

### 6.1 状态计算

```text
done    = boardColumn === "done"
overdue = !done && dueDate 存在 && dueDate < TODAY
blocked = blocked === true
```

显示优先级：

1. done：成功色。
2. blocked：警告色和阻塞标识。
3. overdue：危险色和逾期标识。
4. 其他：沿用优先级颜色。

“阻塞且逾期”不能只表达一个状态：底色可按 blocked，另保留逾期文字/图标。已完成任务即使截止日期早于今天，也不算逾期。

### 6.2 必须可见的信息

- 逾期：至少显示“逾期”或逾期天数，不能只把红色解释给用户猜。
- 阻塞：使用图标/文字 + 虚线，不只依赖颜色。
- 进度：宽条显示百分比；所有任务的原生 `title` 或自定义提示包含任务名、起止日期、进度、状态。
- 条宽足够时显示任务名；不足时省略，不挤压拖拽把手。
- 增加简短图例：进行中/逾期/阻塞/已完成。图例不得挤占工具栏主操作，可放入帮助浮层。

### 6.3 可访问性

- 甘特条增加 `tabindex="0"`、合适的 role 和 `aria-label`。
- Enter/Space 打开任务详情。
- focus 样式必须清晰，且不能仅沿用 hover。
- 状态不能只靠红/绿颜色区分。

### 6.4 验收

使用固定日期数据验证：昨天到期未完成、今天到期未完成、昨天到期已完成、阻塞且逾期、进度 0/45/100，每种状态均有不同且可解释的视觉与文本。

## 7. G-04：排期与拖拽闭环

### 7.1 未排期拖入时间轴

允许把 `.gantt-unplanned-row` 拖到时间轴某一天：

- 默认生成 `startDate = dueDate = 目标日期`。
- 保存成功后刷新甘特图、看板、列表和日历（沿用现有刷新方式）。
- 保存失败保留未排期状态并提示失败原因。
- 点击未排期行仍然打开详情；点击与拖动阈值建议 5px。
- auto 和 month 模式都可拖入；month 模式只能落在当前时间轴日期。

日期换算必须基于实际 `.gantt-axis` 的 `getBoundingClientRect()` 和当前 `dayW`，不要忽略 sticky 左列、scrollLeft 或浏览器缩放。

### 7.2 拖动边缘自动横滚

- 指针距时间轴可视区左右边缘约 32px 时启动。
- 使用 `requestAnimationFrame`，滚动速度随靠近边缘增加，设置合理上限。
- 自动横滚时按最新 pointer 坐标重算日期和条的位置。
- `pointerup`、`pointercancel`、Esc、组件重绘前必须取消 RAF 和临时状态。
- 不修改当前文档级 pointer 事件模型，不重写为 HTML5 drag/drop 两套并存。

### 7.3 Esc 取消

拖动过程中按 Esc：

- 不发送请求。
- 恢复原起止日期和条位置。
- 清理 tooltip、dragging class、监听器和自动横滚。

### 7.4 撤销

改期成功后使用现有 `toastAction()` 提供“撤销”：

- 保存旧 `startDate/dueDate`，撤销时通过 `taskPayloadWith()` 恢复。
- 撤销前读取该任务最新缓存；若日期已被后续操作再次改变，不强行覆盖，提示“任务已再次变更，未撤销”。
- 撤销成功与失败都要刷新相关视图或明确提示。
- 连续拖动多个任务时，每个 Toast 只能撤销自己的那次变更。

### 7.5 验收

- 整体拖动、左把手、右把手、未排期拖入均只发送一次保存。
- 小位移点击不会误改日期。
- Esc、pointercancel 后无请求、无残留 tooltip/RAF。
- 保存失败后 UI 恢复服务器数据。
- 撤销只恢复起止日期，不清空需求、分支、标签、预估工时等字段。

## 8. G-05：偏好、性能保护及测试

### 8.1 偏好保存

按工作空间保存：

- `showDone`
- `dayW`
- `groupBy`
- 分组折叠状态（可选）

key 示例：`ds.gantt.prefs.<workspaceId>`。读取时捕获 JSON 解析异常；无 workspaceId 时使用内存状态，不写入错误 key。

### 8.2 本轮性能保护

即使暂不做虚拟化，也应做到：

- 不在每行每天生成一个 DOM 单元格；继续使用 track 背景网格。
- 分组/折叠只重绘甘特图，不重新请求项目列表。
- `loadReqs()` 与任务请求保持现有增强关系，项目名加载失败不阻塞甘特图。
- 对异常超宽日期范围设置安全提示；不要无提示创建数万个日期表头。
- 仍显示“当前仅加载前 500 项”的明确警告，不得隐藏截断事实。

### 8.3 必测数据矩阵

| 场景 | 预期 |
|---|---|
| 无开始、无截止 | 只进未排期区 |
| 只有开始日期 | 单日条，可整体移动 |
| 只有截止日期 | 单日条，可整体移动，正确参与逾期判断 |
| 起止都有 | 可整体移动和两端调整 |
| startDate > dueDate 的异常旧数据 | 渲染不崩溃；保存前按既有口径处理，不扩散异常 |
| 跨月/跨年 | 月份表头、月视图和裁切正确 |
| 已完成且提前完成 | 不显示逾期 |
| 阻塞且逾期 | 两种状态都能被理解 |
| 全部完成且隐藏 | 出现正确空态，而非“还没有任务” |
| 项目名加载失败 | 甘特图仍可用，项目名称可降级 |
| 超过 500 条 | 明确提示截断；V1.2 后不得静默遗漏 |

### 8.4 自动化与真浏览器检查

至少执行：

```bash
node --check src/main/resources/static/js/app.js
node --check src/main/resources/static/sw.js
node tools/preview/gen-preview.js
node tools/shots/shot-gantt.mjs
```

建议扩展 `tools/shots/shot-gantt.mjs` 或新增 `tools/shots/check-gantt.mjs`，使用真实 Chrome/CDP 断言：

- 工具栏按钮在 1280/1440 视口内。
- sticky 左列、表头位置正确。
- 月视图上一月/下一月/今天有效。
- 筛选和分组数量正确。
- 拖动后保存参数正确；失败恢复；Esc 无请求。
- 未排期拖入后日期正确。
- 撤销只改回日期字段。
- 页面无 JS 异常，无意外的 document 级横向滚动。

预览 mock 的数组型接口必须返回数组，任务列表保持 `{items, total}` 结构，避免测试本身制造假故障。

## 9. G-06：后续专用接口与虚拟化设计建议

本轮不要顺手改后端；需要启动时按以下口径单独实施。

### 9.1 接口建议

```http
GET /api/gantt?workspace=<id>&from=YYYY-MM-DD&to=YYYY-MM-DD&includeDone=false&offset=0&limit=500
```

筛选参数尽量复用 `/api/tasks/list`。返回至少：

```json
{
  "items": [],
  "total": 0,
  "from": "2026-10-01",
  "to": "2026-10-31",
  "hasMore": false
}
```

区间交集：

```text
COALESCE(start_date, due_date) <= to
AND COALESCE(due_date, start_date) >= from
```

并要求：

- 只查当前工作空间、未删除任务，权限与现有列表一致。
- 排序必须稳定：`COALESCE(start_date, due_date), COALESCE(due_date, start_date), id`。
- 分页由服务端完成，不能先 `selectAll()` 再在内存中假装分页。
- 未排期任务使用明确的 `scheduled=false` 查询或独立接口，不能借用只检查 `dueDate IS NULL` 的 `noDue` 逻辑。
- 前端必须消费 `total/hasMore`，不得静默截断；未完成分页加载前显示真实加载状态。

### 9.2 行虚拟化

- 只虚拟化任务行，sticky 表头和左列仍保持同一滚动容器。
- 上下各保留 5–10 行 overscan。
- 分组头、折叠、拖动定位和打开详情必须按真实数据 index 计算。
- 拖动中的行即使滚出虚拟窗口，也不能销毁其拖动状态。
- 以 500/1000/3000 行做对比测试，记录首屏时间和滚动帧率，而不是只验证 DOM 数量。

## 10. G-07：后续依赖与里程碑边界

当前 `Task.blockedByTaskId` 表示“等待/阻塞我的任务”，不天然等价于标准 FS 依赖。

第一阶段只可：

- 画阻塞关系线。
- 点击关系线定位到阻塞任务。
- 当被阻塞任务计划早于阻塞任务结束时给出提示。

不得自动改期、自动级联或声称已经支持关键路径。里程碑需要独立产品口径和字段设计，不要用“单日任务”冒充完整里程碑能力。

## 11. 推荐实施顺序

1. 先合并/实施纯视觉文档，解决甘特条基础可读性。
2. G-01 筛选与分组，补测试数据。
3. G-02 时间窗口，统一 effectiveStart/effectiveEnd 和裁切逻辑。
4. G-03 状态语义与图例。
5. G-04 拖拽闭环，逐个验证成功、失败、取消、撤销。
6. G-05 偏好、可访问性、浏览器回归与文档。
7. 单独评审是否启动 G-06；不要为了“可能有很多任务”提前重写后端。

每一步保持可回滚的小改动，不要一次性重写整个 `renderGantt()` 和所有 pointer 逻辑。

## 12. 开发完成交付标准

开发 AI 完成后必须提供：

- [ ] 变更文件清单和每项功能对应位置。
- [ ] G-01 至 G-05 的完成/未完成状态，未完成项不得口头省略。
- [ ] 自动化命令及真实结果，不只写“已测试”。
- [ ] 1280、1440 下截图；逾期/阻塞/分组/月视图至少各一张。
- [ ] 拖拽成功、失败、Esc、撤销、未排期拖入的测试结果。
- [ ] 确认看板、列表、日历改期联动无回归。
- [ ] 更新 `docs/ui-redesign-spec.md`；接口变化时更新 `docs/api.md`。
- [ ] 静态资源变更后递增 SW `CACHE_NAME` 并重新生成预览稿。
- [ ] 明确说明未部署、未提交 Git；如存在 500 条限制或其他遗留风险，单独列出。

**最终验收原则：不仅要“页面看起来更像甘特图”，还要做到任务找得到、风险看得懂、排期改得准、误操作能撤回、失败不会弄坏其他任务字段。**
