# Hourglass 测试计划（2026-11-03）

> 角色：测试工程师｜范围：业务逻辑测试 + 界面测试验收
> 依据：本轮 P0 一致性修复（Epic 校验与生命周期清理、通知权限出口、文档跨项目移动清理、项目删除提示）及全模块回归
> 环境：本地服务 127.0.0.1:8080（运行中 jar 已含本轮修复）、MySQL hourglass 库（Xm 前缀模拟数据：4 空间/11 项目/163 任务）

## 1. 测试目标

1. 验证本轮 P0 修复的业务行为符合预期，无回归。
2. 按模块对核心业务链路做深度测试，发现并分级记录缺陷。
3. 给出界面验收结论（主流程 + 边界场景）。

## 5. 执行顺序与通过准则

执行顺序：业务逻辑层（全量单测 → 补 P0 用例）→ 界面层（主流程 → 边界）→ 汇总报告。

缺陷分级：**P0** 阻断（数据破坏/权限穿透/崩溃）｜**P1** 严重（核心流程错误）｜**P2** 一般（非核心流程/显示错误）｜**P3** 建议。

通过准则：P0 回归用例 100% 通过；新发现 P0/P1 缺陷修复后回归；P2/P3 记录进 backlog。

## 6. 风险与限制

1. 界面测试使用运行中的用户服务，测试数据一律新建 `Xt` 前缀临时空间，测试后清理，不污染 Xm 模拟数据。
2. 通知邮件为真实 SMTP 依赖，本环境仅验证到 outbox 入队层。
3. 已知遗留问题（备份字段缺口 P1、统计口径 P2）本次只回归不修复，修复另行排期。
