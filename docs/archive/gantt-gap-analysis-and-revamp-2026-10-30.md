## 4. 结论：五个真正的缺口

按“对日常使用的影响 ÷ 改造成本”排序：

1. **这张图讲不清“先后关系”**：没有依赖线、没有里程碑，任务之间只有上下文里的 `blocked` 一个标记。甘特图的核心价值一半在网络计划上。
2. **信息密度不够**：估时、实际工时、子任务进度都已经在接口里，但左边只有 4 行小字、条上只有百分比，看不出“这事要多久、花了多久、差多少”。
3. **500 条硬截断 + 全量重绘**：任务一多就会漏任务、卡顿；未排期区 50 条之后直接消失。
4. **批量操作与多步撤销缺失**：一次调 5 个任务的排期要拖 5 次，撤错一次只能撤最后一步。
5. **出不去**：不能导出、不能打印、不能分享只读视图。

## 5. 改造方案

### 5.1 目标与原则

- 目标：让甘特图从“任务时间条”升级到“能表达依赖、能看工时、能扛数据量、改错能回退”的排期台。
- 原则：
  - 不引入甘特框架、不改前端技术栈、不 Canvas 重写（与 V1.1 规格第 2.3 节一致）。
  - 每一期独立可回滚，不一次性重写 `renderGantt()`。
  - 先吃已有数据（估时/子任务/工时/视图），再考虑加表加字段。
  - 保持既有约定：`taskPayloadWith()` 全量 PUT、`esc()`、日期工具函数、SW `CACHE_NAME` 递增、`node tools/preview/gen-preview.js`。

### 5.2 P0：V1.3「看得懂、改得快、出得去」（约 6–8 人天）

> 全部纯前端 + 复用现有接口，零数据库变更，风险最低。
>
> **实施状态：2026-10-30 已完成**；口径、验收结果与已知边界见 [`ui-redesign-spec.md`](ui-redesign-spec.md) 附录 O。

| # | 功能 | 做法 | 验收 |
|---|---|---|---|
| P0-1 | 左列与条内信息增强 | 左列加一行 `估 Xh · 实际 Yh · 子任务 2/5`（`estimateMinutes/totalMinutes/subtaskTotal/subtaskDone` 已在返回里）；条内宽度 ≥150px 时在百分比旁显示估时偏差色（超估红/省时绿） | 1280/1440 截图；无数据时不留空占位 |
| P0-2 | 筛选补全 + 保存视图 | 甘特筛选菜单补齐关键词、标签、分类、到期、阻塞（`ganttTaskParams()` 已支持）；接 `/api/views` 做“保存当前视图/应用/删除” | 应用视图后筛选数、任务数、未排期数三者一致 |
| P0-3 | 依赖只读连线 | 用 `blockedByTaskId` 画折线（前驱右端 → 后继左端），冲突时线变红并加文字提示“后继早于前驱结束 N 天”；点击线定位两端 | 阻塞任务移动后线位置正确；循环引用不崩 |
| P0-4 | 画布新建任务 | 工具栏“新建”+ 时间轴空白双击：`start=due=点击日`，创建后打开抽屉；双击已有行空白不触发 | 双击位置换算正确（含 sticky 左列、scrollLeft、缩放） |
| P0-5 | 批量选择与整体平移 | Ctrl/Cmd 点选、Shift 连选；选中后拖动任意一条即整体平移（仅平移有日期的任务），批量保存失败整体回滚 | 5 条选中拖 3 天 → 5 次 PUT 或批量接口，全部成功/全部回滚 |
| P0-6 | 多步撤销栈 | 改期、批量改期、拖入排期统一入栈（前端内存保留 20 步），Ctrl+Z 与工具栏撤销按钮；撤销前仍校验“任务是否被再次修改” | 连续改 3 次能退 3 次；撤销不清空项目/标签/估时等字段 |
| P0-7 | CSV 导出 + 打印样式 | 导出当前范围（任务/起止/工期/负责人/项目/进度/状态/估时/实际/子任务）为 CSV（带 BOM）；加 `@media print` 隐藏工具栏、展开左列 | Excel 打开不乱码；打印 A3 横向不截断 |

**建议先做**：P0-1 → P0-2 → P0-6 → P0-4 → P0-3 → P0-5 → P0-7（先纯展示，再交互，最后导出）。

### 5.3 P1：V1.4「扛得住、连得起来」（约 14–18 人天）

> **实施状态：2026-10-30 已完成**（实现与验收见 [`ui-redesign-spec.md`](ui-redesign-spec.md) 附录 P；
> 偏差：分享页为独立只读页，未做视图共享；G-06 原计划的后端区间接口已在本轮直接落地（SQL 生成列 + 索引）

| # | 功能 | 做法 | 验收 |
|---|---|---|---|
| P1-1 | 甘特专用接口 | `GET /api/gantt?from&to&includeDone&offset&limit`，区间交集 `COALESCE(start,due) <= to AND COALESCE(due,start) >= from`，返回 `{items,total,from,to,hasMore}`；排序稳定 | 301 条任务只出 300 条时 `hasMore=true`；不静默截断 |
| P1-2 | 行虚拟化 + 未排期分页 | 只虚拟化任务行，表头/左列仍在同一滚动容器；上下 overscan 5–10 行；拖动中的行即使滚出窗口也保留状态；未排期列表改“加载更多” | 1000/3000 行首屏与滚动帧率记录；拖动跨越虚拟窗口不丢 |
| P1-3 | 依赖模型升级 | 新表 `task_dependency(from_task_id,to_task_id,type,lag_days)`；迁移现有 `blocked_by_task_id` 为 1 条 FS；拖拽条端点画线；冲突检测复用 P0-3 | 旧数据迁移后连线正确；删除任务级联清理依赖 |
| P1-4 | 里程碑 | `task.is_milestone`（或 0 工期约定）；菱形节点、完成态填充；新建任务可勾选 | 里程碑不参与逾期天数计算；与依赖线端点对齐 |
| P1-5 | 真实周/月刻度 | 缩放档位改为“日/周/月”，周档按周聚合表头、条仍按日定位；保留当前像素密度作为日档内部密度 | 跨年、跨月、闰年边界正确 |
| P1-6 | 左列列配置 + 多级分组/排序 | 列配置存 localStorage（按空间）；分组支持 项目/负责人/状态/分类，最多两级；排序支持起点/截止/优先级/工期 | 刷新后配置保留；分组折叠状态按组 key 稳定 |
| P1-7 | 资源负载面板（只读） | 按人 × 周汇总估时/实际，容量按 `WorkTime` 口径（跳周末、每天封顶 8h）；超载标红，不自动平衡 | 与周回顾工时数字一致；不改任何任务数据 |

**依赖顺序**：P1-1 → P1-2（先有接口再虚拟化）→ P1-3 → P1-4；P1-5/6/7 可并行。

- 业务失败可能是 HTTP 200 + `code != 0`，不能只看状态码。
- 改期必须 `taskPayloadWith(task, patch)`，避免清空项目/分支/估时。
- 日期只用 `parseDate/iso/addDays/dayDiff/TODAY`。
- 文本插 HTML 必须 `esc()`，不引入内联事件。
- 拖动期间保持 `ganttState.drag` 防重绘，SSE 不得打断拖动。
- 不主动部署、不主动 Git 提交。
