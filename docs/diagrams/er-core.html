关系清单 · 只画关键边，不画蜘蛛网

→task.demand_id → demand：需求评审通过后拆解为工作项，自动关联
→task.req_doc_id → requirement_doc：文档可拆任务草稿，方案与执行对齐
→task.branch_id → dev_branch：分支状态独立流转，从开发到已发布
↔version_task ↔ task / project_version：多对多，版本内容 ≠ 发布范围
→category.project_id → requirement：模块合计 + 未指定 = 项目合计
→version_release.plan_id → version_release_plan：计划可空，确认时冻结 plan_snapshot
→version_release_item.release_id → version_release：逐项处置与工时，构成发布偏差
⊸task.published_release_id ⊸ version_release：徽标由成功 production 记录派生，不人工写
→test_case_run.case_id → test_case：执行流水；失败可转出缺陷任务
⊸task_completion_record ⊸ task：完成时冗余快照，任务改名 / 删除后统计不失真
全库 56 张表 · 每张事实表都带 workspace_id —— 这是备份按空间导出/导入的物理基础；发布证据以 MySQL 备份为准
