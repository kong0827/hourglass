主状态只有 review / pass / plan / done / closed 五个；待开工、推进中、待发布、已交付都是派生展示，不能手工改。待开工 / 推进中由关联工作项的真实开工信号派生，计划开始日不算。

终止与回退

已关闭是未交付终止；已交付不回流，后续变更另开需求或缺陷

终止路径：已关闭 人工 · 原因必填

关闭只收未交付终止：评审不通过、中途取消、重复需求；记录关闭前阶段，恢复时回到原阶段。
待评审 / 已通过 / 已排期 关闭 已关闭 恢复 待评审 / 已通过
关闭原因：rej 评审不通过 / cancel 中途取消 / dup 重复需求；从已排期关闭，恢复回到已通过，须重新排期。

回退路径：证据变化 系统派生

回退不靠人工改状态，而是证据变化后自动退回；每次变化写需求日志与证据表。
已完成 · 已交付 发布记录撤销 已完成 · 待发布 工作项重开 / 用例失败 推进中
已排期 撤销排期 已通过 撤回评审 待评审
撤销排期与撤回评审是人工动作；其余回退由工作项、用例、发布记录自动触发。

派生依据：看任务，但不只看“关联”

关联了工作项不等于已开工；只有真实执行信号才进入推进中
待开工 → 推进中 看关联工作项有没有真实开工 首次移出 backlog、首次计时、直接创建在执行列，三者取最早日期；不读计划开始日。所有任务都还在 backlog 且没计过时，仍然是待开工。
推进中 → 已完成 · 待发布 看工作项完成 + 用例结果 至少 1 个关联工作项，且全部关闭；最新用例结果全部通过，0 个用例按通过处理；同时没有生产发布记录。
已完成 · 待发布 → 已交付 看生产发布记录 存在 result=success + environment=production + disposition=published 的发布条目；没有真实记录时才允许管理者人工判定，并标记来源。
一句话：任务“关联上了”只说明拆解完成；任务“动了 / 计时了 / 直接建在执行列”才算开工；任务“全关了 + 用例全过”才算完成；发布记录“成功了”才算交付。

触发事件清单

谁触发、满足什么条件、落到哪个状态
评审通过 人工待评审 → 已通过；项目写权限成员可操作，写 demand_log。撤回评审则回到待评审。
评审不通过 人工待评审 → 已关闭，closeReason=rej；需求保留，WSJF 分数与历史不丢。
排期 / 调期 人工已通过 → 已排期；空间主、管理员或项目负责人可选目标版本与计划起止；目标版本不能是已发布。
撤销排期 人工已排期 → 已通过，须填写原因；不自动改任务版本、日期或状态。
首次真实开工 系统待开工 → 推进中；取首次移出 backlog、首次计时、直接创建在执行列的最早日期，不读计划开始日。
完成条件满足 系统推进中 → 已完成 · 待发布；至少一个关联工作项且全部关闭，最新用例结果全部通过，0 个用例按通过。
生产发布 系统已完成 · 待发布 → 已完成 · 已交付；须有 success + production + published 发布记录，真实证据优先。
人工交付判定 例外没有发布记录时，管理者可判定已交付并填写依据；标记来源，发布证据到位后以真实记录为准。
关闭 / 恢复 人工任意未交付态 → 已关闭，原因必填；恢复回到 closeStage，从已排期关闭的回到已通过，须重新排期。
回退 系统工作项重开或用例失败：已完成 → 推进中；发布记录撤销：已交付 → 待发布；不提供手工改回入口。
归档 人工已交付后从默认视图收起，不改主状态；已交付需求不回流，后续变更另开需求或缺陷。

完成 ≠ 发布：已交付只是已完成下的发布标记；关闭 ≠ 完成：已关闭只收未交付终止。 发布事实只认成功的生产发布记录
