⏳
沙漏 Hourglass

面向 10–50 人研发团队的私有化协作工作台。把需求、评审、文档、任务、版本、回顾跑在同一套数据上，让进度、工时与交付报表从日常操作里自然产生。

一个 jar + MySQL，无需 Redis / MQ / 对象存储
小团队常见困境
1
需求是断的
想法在聊天、方案在文档、任务在看板，彼此不关联。
2
管理者看不见全局
延期、负载、风险散落在每个人脑子里，不问就不知道。
3
时间说不清
记录里只有「做完了」，事后答不出到底花了多久。
4
回顾靠拼凑
周报月报翻聊天记录，写的人痛苦，看的人也未必信。
沙漏的解法
1
需求-任务-版本串联
以工作项为执行主线，每个统计数字都能回溯到具体操作。
2
项目健康度实时可见
逾期、负载、阻塞、风险集中呈现，可下钻到具体工作项。
3
移动任务即记录工时
拖入「进行中」自动开表，拖入「已完成」自动停表并接力。
4
周回顾与月度清单自动生成
从 time_log / task_log 自动汇总，无需二次录入。
→
◎
统一数据
需求池、文档、任务、版本、工时共用一套数据模型，看板、日历、度量、报表看到的是同一个数字。
◈
自动度量
燃尽图、累积流图、成员负载、流程体检等全部从日常移动任务的操作中自动产生。
⌂
私有化部署
单实例自托管，数据留在本地；无需 Redis、MQ 或对象存储，一台服务器即可跑起来。
协作主链路
需求池
→
评审排期
→
文档沉淀
→
工作项
→
版本发布
→
周回顾
核心事实表 time_log + task_log 驱动工时、燃尽、负载与回顾，补记或作废后自动重算
