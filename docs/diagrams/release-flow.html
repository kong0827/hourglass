沙
发布三步计划 → 预览 → 确认
计划只是预期；只有成功的生产发布记录，才形成不可变的发布证据
1
建计划
谁能发、发哪些
覆盖版本可跨版本、跨项目，当前版本固定包含
计划信息计划时间 · 负责人 · 环境 · 说明
工作项范围取所选版本内容的并集
草稿→ 就绪 需时间、负责人与至少 1 个工作项
→
2
预览核对
三个范围分开看
版本内容这个版本计划交付的工作项
计划范围本次计划选中的工作项
实际范围本次真实要发布的工作项

未完成、晚于事件完成、需求已取消或跨范围的工作项都会显式列出，不静默排除。

→
3
确认留证
不可变记录
失败只留一次不可变尝试
成功记录 + 条目 + 快照
归属实际记录始终归属当前版本
成功 · 发布证据 失败 · 仅尝试
四条护栏
完成 ≠ 发布test / staging、回滚与部分成功都不计为有效生产发布。
计划完成有前提覆盖的全部版本都完成成功生产部署 / 重部署，计划才完成。
成功事实冻结内容冻结的是内容关联，不锁任务完成、回退与计时。
响应未知先查询保留原请求与幂等键，先查记录再决定重试，不换键重发。
仅空间主 / 管理员或项目负责人且项目可写；任务负责人没有整版本发布权，发布人固定为当前登录者
