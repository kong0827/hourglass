工作项由看板列驱动，需求 / 发布计划 / 分支各自独立流转 · 判定只看留痕，不靠人工口头同步

工作项主链

默认五列可自定义 · 判定只认语义标记：起始列 / 完成列
待处理backlog 开始计时 进行中doing 提测 待测试test 开始验证 测试中testing 测试通过 已完成done
待确认 · 派生态 进度 100% 但尚未归入完成列 → 进入周回顾「待确认完成」分区；完成时写一条 task_completion_record 快照用于月度统计
计时拖入「进行中」自动开表；一人同一时刻只计一个任务，开始新的会自动停掉旧的。
接力计时中的任务完成后，若原列还有任务，自动接上第一个；仅本人无运行中计时时生效。
提测 / 验证进入「待测试」或「测试中」记录 test_started_at；离开时写 test_finished_at，测试通过不等于发布。
回退已完成可拖回任意列，task_log 记录 from_column → to_column；工时按区间重算。
阻塞任意状态可标记阻塞，填原因与可选等待任务；集中出现在「逾期与阻塞」视图。
逾期判定只看截止日与当前列：未进完成列且已过截止日即逾期，看板 / 日历 / 度量同一口径。
删除软删除进回收站（deleted_at），可恢复；完成快照不随任务删除而丢失。
不改口径自定义列不参与语义判定；工作项类型（故事 / 任务 / 缺陷 / 史诗）与列状态相互独立。

需求池状态机 空间主评审

评审流转仅空间主可执行；排期 / 调期 / 撤排 / 取消 / 恢复由管理角色执行，全部动作写 demand_log。
待评审 通过 已通过 排期 已排期 拆解 工作项
已拒绝 重开 待评审 需求不消失，WSJF 分数保留
已取消 恢复 已通过 回到已通过，须重新排期；关联任务不变

发布计划状态机 完成由事实推进

计划只是意图。状态只允许草稿 / 就绪 / 已取消手动设置；完成由全部包含版本的生产发布自动推进。
草稿 满足条件 就绪 全部成功 已完成
草稿 / 就绪 取消需理由 已取消 就绪 → 草稿等调整也须填原因
就绪必须填写计划时间、负责人与任务范围；已完成计划不可修改，后续另建计划。

分支状态机 时间线留痕

分支状态在分支模块维护，每次变更写 dev_branch_log；计划里的分支汇总只读，不作为发布证据。
开发中 提交测试 待测试 测试通过 待合并 合并上线 已发布
发布周期 = 已发布时间 − 创建时间；负责人与目标分支在分支上维护，工作项只做关联。
分支「已发布」只表示合并上线，不等于版本已完成生产发布。
列名可以自定义，判定只认语义标记（起始列 / 完成列） —— 自定义列不会破坏统计口径；发布事实只认 production 记录
