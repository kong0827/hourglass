# 沙漏 · 页面设计理念

> **不配置、不填表、不跳页。**
>
> **一屏一判断**：打开就能用，判断不用先配置，记录不靠填表。

界面层配套：[UI 设计理念](UI设计理念.md) —— 一屏一焦点，一色一语义。

---

## 一、这份理念要解决什么

沙漏服务的是没有专职 PMO 的小团队。他们不用工具来管理项目，而是希望工具替他们省事。三条底线：

1. **交互简单** —— 常用动作两步内完成，路径不绕层。
2. **页面简洁** —— 一屏只有一个主任务，其余收进工具条。
3. **少介入、少填写** —— 数据优先由系统派生，人只给无法推导的判断。

反向判断标准：如果一条设计要求用户「先去配置 → 再去看 → 再回来录」，它就违背了理念。

---

## 二、三条口号

| 口号 | 含义 | 反例 |
| --- | --- | --- |
| **默认即答案** | 页面初始状态就回答「现在该做什么、它到哪了」 | 进来先选项目、先设筛选、先建视图才能看到数据 |
| **数据只录一次** | 同一条事实只在一处产生，其余全部引用或派生 | 工时表另填一遍、进度手工刷百分比 |
| **组合代替页面** | 视图 × 分组 × 筛选 × 范围任意组合，不新增菜单 | 每个视角做一个独立页面，菜单越加越长 |

---

## 三、五条原则

| 原则 | 含义 | 落地机制 | 验收标准 |
| --- | --- | --- | --- |
| **默认即答案** | 打开页面不需要任何前置操作 | 默认范围取当前项目/我的；默认排序按「需关注优先」；空数据给下一步动作而不是空表格 | 新用户进入 5 秒内知道该点哪里 |
| **同一份数据，多种切法** | 视图是呈现方式，不是数据副本 | 看板 / 列表 / 时间轴共用一套查询；切换视图不重新取数、不丢筛选与分组 | 切三次视图，筛选条件一次没变 |
| **能派生就不让人填** | 状态、进度、逾期、交付结论由事实推导 | 拖看板即改状态；计时随流转开关；发布状态读实际记录；只有不可推导的判定才留人工入口，且可撤销、留痕 | 新页面上需要人工填写的字段 ≤ 3 个 |
| **少一跳就完成** | 编辑不离开当前上下文 | 行内改状态、行内补记；详情用侧滑抽屉，不跳页；批量操作用勾选 + 一次提交 | 改一个字段不超过 2 次点击 |
| **一条主线，次级收起** | 每屏只有一个主区 | 筛选、分组、密度压成一行工具条；统计以行内数字呈现，不单独堆卡片 | 首屏主区至少占 60% 高度 |

## 四、多维度模型：页面数不变，维度做乘法

四个维度相互正交，组合使用，**任何组合都不对应一个新页面**。

| 维度 | 作用 | 可选值 |
| --- | --- | --- |
| **范围 Scope** | 看谁、看哪段时间 | 我的 / 项目 / 空间 / 时间窗 |
| **视图 View** | 怎么看 | 看板 / 列表 / 时间轴 |
| **分组 Group** | 怎么归堆 | 状态 / 负责人 / 优先级 / 模块 / 项目 |
| **筛选 Filter** | 看哪一部分 | 多字段、多值、可叠加 |

四条正交约束：

1. 切换任一维度，其余维度保持不变。
2. 切换视图只重排，不重新请求，不闪烁。
3. 组合可分享（状态写进 URL）且可记住（本机保留上次选择）。
4. 新增一个维度 = 新增一个选项，不是新增一个菜单或页面。

组合示例：

| 组合 | 回答的问题 |
| --- | --- |
| 看板 × 按负责人 × 我的 × 未关闭 | 我手上还有什么、卡在哪 |
| 列表 × 按模块 × 项目 × 本周 | 这一周交付范围覆盖了哪些模块 |
| 时间轴 × 按项目 × 空间 × 本季度 | 排期是否撞车、哪些版本要到期 |
| 列表 × 按状态 × 项目 × 全部 | 积压在哪一环 |

同一组数据，四种问法。这是「少做页面、多做组合」的具体含义。

## 五、少填：字段分三级

| 级别 | 来源 | 例子 | 交互方式 |
| --- | --- | --- | --- |
| **L0 事实派生** | 系统计算 | 进度、逾期、有效工时、交付状态、发布徽标 | 只读展示，点击可看来源 |
| **L1 顺手产生** | 动作的副产物 | 拖看板产生的状态变更、开计时产生的工时、评论产生的时间戳 | 不单独设表单 |
| **L2 必须人给** | 人的判断 | 标题、归属项目、评审结论 | 只阻塞创建，不阻塞后续完善 |

配套规则：

- L2 字段控制在 3 个以内，其余全部选填、可后补。
- 默认值取当前上下文（当前项目、当前负责人、当前状态），减少选择。
- 保留「未指定」桶：模块、负责人空着也能成立，不逼迫选择，不静默补人。
- 空值不占位：拼接文案中可选字段为空时整段省略，不显示「-」或 null。
- 人工判定必须可撤销、可追溯，不做只能单向前进的状态。

## 六、页面骨架

所有业务页面共用一套骨架，减少学习成本。

```
┌──────────────────────────────────────────────┐
│ 页面名   范围              [看板|列表|时间轴] │  页头
├──────────────────────────────────────────────┤
│ 🔍 搜索   筛选(3)   分组:负责人   密度  更多  │  唯一工具条
├──────────────────────────────────────────────┤
│                                              │
│                 主内容区                      │  唯一主区
│                                              │
├──────────────────────────────────────────────┤
│ 共 128 条 · 已显示 100           加载更多     │  底部状态
└──────────────────────────────────────────────┘
                        详情/编辑以侧滑抽屉打开
```

约束：

- 一屏只有一个主区，不允许并列两个同等权重的数据区。
- 工具条单行平铺，宁可折叠也不换行堆两排。
- 详情用抽屉，保留列表上下文；抽屉内可编辑，关闭即回到原位。
- 统计数字放在标题旁或工具条，不单独做摘要卡片区。
- 移动端只保证「能看」，不为其增交互分支。

## 七、映射到沙漏现有页面

| 页面 | 主判断 | 主区 | 可用维度 |
| --- | --- | --- | --- |
| 需求池 | 哪些想法值得排期 | 单板四列（待评审/已排期/进行中/已完成） | 视图固定、按状态分列、可按项目筛选 |
| 需求工作页 | 这个需求走到哪了 | 阶段驾驶舱 + 聚合明细 | 卡片/列表切换、按时间轴看过程 |
| 工作项列 | 谁在做、卡在哪 | 看板或列表 | 视图切换、按负责人/优先级/模块分组、多字段筛选 |
| 我的工作 | 我今天先做哪个 | 两行式列表 | 密度切换、按状态/项目分组 |
| 分支与发布 | 哪些改动已上车 | 分支列表 | 按状态筛选、按项目分组 |
| 报表 / 周回顾 | 投入是否合理 | 图表 + 下钻列表 | 时间窗、按项目/成员维度 |

## 八、明确不做

- 不为每种视角新增菜单页或二级导航。
- 不要求先建视图、先配筛选才能看到数据。
- 不在列表页堆统计卡片、公告、摘要侧栏。
- 不用模态框做常规编辑（模态只用于确认与危险操作）。
- 不做多层嵌套抽屉与面包屑迷宫。
- 不在表格里做合并单元格，分组靠分组行或行内重复字段。
- 不新增无法删除、无法撤销的人工状态。

---

## 九、自检五问

评审任何页面前先过这五问，任一条答「否」就需要改：

1. 新用户不看说明，5 秒内知道该点哪里吗？
2. 不配置任何筛选，能判断「到哪了、谁卡住」吗？
3. 最常用的动作，两步之内能完成吗？
4. 增加一个观察维度，需要新增页面吗？
5. 关掉页面再回来，视图、分组、筛选还原了吗？

---

## 十、怎么用

- **需求评审**：新增需求先问「这是新维度还是新页面」。能落在现有组合里的，不批新页面。
- **设计评审**：用第九节五问逐条打分，答否的条目对应到具体原则修改。
- **开发实现**：维度状态统一进 URL 与本机存储，避免各页各写一套。
- **文档写作**：描述功能时按「范围 × 视图 × 分组 × 筛选」四段说明，而不是逐个页面描述。
