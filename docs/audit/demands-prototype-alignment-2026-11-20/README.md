# 需求池 × 2026-11-19 改版原型 · 逐页对齐检查

日期：2026-11-20　范围：需求池主页面的看板 / 列表 / 甘特、显示浮层、评审工作台、需求详情抽屉、新建需求表单，1440 与 390

数据：运营研发中心（SXk01），187 条需求，admin

## 结论

- 需求池主页面（看板）的核心元素与原型**一致**：页头 H1 19/700 + 计数胶囊 20/r5/10.5/600、副标题 11.5、页级「导出 + 新建需求」32/12.5/r8、工具条 48、视图分段 30/26、5 列看板（列间距 10）、列头 30/12/650 + 计数 10.5、组头 22 灰带、卡片 padding 10。
- 本轮统一了 8 类可见偏差：页头计数与双操作、看板列头去主色胶囊、列间距与列头规格、列内组头、卡片密度与标签、工具条重复计数、创建文案统一「新建需求」、工作页创建入口与手机页头溢出。
- 列表 / 甘特 / 评审工作台 / 详情 / 新建表单在原型里没有对应 section（原型只画看板单视图），按同一套壳层令牌收敛，不逐像素对标；差异见「有意保留」。
- 1440 与 390 全部视图横向溢出 0、控制台错误 0；尚未提交、未部署，Service Worker 仍 `hourglass-shell-v287`。

- 工具：`tools/e2e/demands-proto-audit.mjs`。真 Chrome（CDP），1440×900 逐视图点击截图并读计算样式，最后追加 390×844 三张；产物 `metrics.json`、`shots/*.png`。只读，不触发保存、导出与流转。

## 有意保留的差异（K1–K5）

| ID | 差异 | 原因 | 何时反悔 |
|---|---|---|---|
| K1 | 工具条两行（视图 / 项目 / 帮助 / 全屏 + 搜索 / 筛选 / 阶段 / 显示），原型单行 | 站点多出甘特、全屏、更多筛选、阶段筛选与项目下拉；压成一行会藏掉高频控件 | 若按原型把次要项收进「更多」 |
| K2 | 卡片携带描述、来源、提交人、证据与快捷动作；标题 13/600，标签 11 | 卡片信息密度高于原型；12px 会让两行描述反压标题层级 | 若卡片改为「标题 + meta + 状态」三行 |
| K3 | 显示默认「按类型 / 不分组 / 默认排序」，原型「类型 / 项目 / 优先级」 | 站点默认不叠加二级分组与优先级排序，避免列内切得过碎；三个选项都在 | 若产品要求默认按优先级 |
| K4 | 列表有保存视图页签、显示字段与行内「更多」 | 站点既有能力，原型只画看板 | 若收敛为原型单视图 |
| K5 | 列计数未筛选时只显示单值（如 28），原型恒显「3 / 32」 | 看板一次加载全部，显示数与总数相同；筛选后才显示「匹配 X / Y」 | 若统一恒显「X / Y」 |
