# 写操作与活动轨迹覆盖审计

- 审计日期：2026-11-11
- 审计对象：`backend/src/main/java` 全部 `@PostMapping / @PutMapping / @PatchMapping / @DeleteMapping` 路由，以及前端「空间活动」「任务时间线」和各实体详情轨迹的读取入口
- 审计方式：静态代码追踪（Controller → Service → Mapper → 日志表），未修改任何代码
- 结论口径：
  - **宽口径**：只要进入任意一处用户可见轨迹（空间活动、任务时间线、项目/文档/需求/分支/版本详情轨迹、管理员审计），即算「有轨迹」
  - **窄口径**：只算「空间活动流」和「任务操作时间线」

---

## 一、结论摘要

**不是所有写操作都有轨迹。**

本次共识别 **140 个写路由**。剔除 10 个只做预览/生成/测试、不落库的 POST，以及 9 个纯个人状态写入后，实际业务写操作约 **121 个**：

| 结果 | 数量（约） | 说明 |
|---|---:|---|
| 至少进入一处轨迹 | 69 | 其中约 30 个只进入项目/文档/需求/分支/版本的**实体专属轨迹**，不在空间活动流，也不在任务时间线 |
| **完全没有轨迹** | **52** | 删除、配置、测试、甘特、邀请、账户安全、平台设置是重灾区 |
| 只在任务时间线/空间活动流 | 约 40 | 任务域主链路 + 少量空间配置事件 |

核心任务域覆盖相对完整：工作项创建、编辑（部分字段）、移动、批量移动、取消完成、删除、恢复、子任务、评论（新建）、附件、计时、版本/需求绑定都会写入 `task_log`。

但有六个系统性问题：

1. **空间活动流不是全空间统一流**：`ActivityService` 只查 `task_log`，项目、文档、需求、分支、版本的日志表完全没有并入。
2. **删除常常连自己的日志一起删**：彻底删除任务、删除需求、删除文档、删除分支、删除版本后，原轨迹无法回查；其中任务彻底删除、版本删除连管理员审计也没有。
3. **配置类写操作大多不记**：看板列的创建/改名/排序、状态流转矩阵、模块创建/排序、优先级配置均无记录。
4. **测试、甘特、邀请、账户安全、平台设置基本裸奔**：测试用例/计划、甘特依赖/基线/分享、邀请创建/撤销/加入、自助改密/改资料、邮件与 AI 配置均无任何轨迹。
5. **级联 SQL 绕过任务日志**：删列、删模块、删需求、删文档、删分支时直接批量改任务字段，任务时间线看不到这些变化。
6. **工作项编辑的字段差异不完整**：类型、Epic 归属、缺陷字段、里程碑、阻塞前置任务等单独变更时，可能一条日志都不写。

> **修复进展（2026-11-11）**：彻底删除任务、需求/文档/分支/版本删除、级联改任务字段、工作项字段差异、空间创建/更新、邀请创建/撤销/加入、直接添加成员、评论删除、版本创建、甘特分享创建/撤销、测试用例删除与导入、测试计划删除与状态变更、自助改密/改资料/改工作时段、邮件服务器与 AI 配置，均已补轨迹。仍未覆盖：看板列/状态流转矩阵/模块/优先级配置、甘特依赖与基线、测试域其余写操作、AI 批量建用例、管理催办、空间活动聚合视图。详见第七节勾选与附录 C。
>
> **修复进展（2026-11-14，批次 3/4 收口）**：看板列新建/改名改色/排序、状态流转矩阵保存/重置、模块新建/排序、优先级修改/重置、甘特基线拍下/清除，补写空间活动流（`task_log` 的 `CFG` 哨兵，仅空间主/管理员可见，文案带列名/模块名与新值）；测试用例新建/编辑、测试计划新建/编辑、计划加入/移出用例、必测标记、批量执行补写 `audit_log`（`test_case_create` / `test_case_update` / `test_plan_create` / `test_plan_update` / `test_plan_cases_add` / `test_plan_cases_remove` / `test_plan_required` / `test_plan_run`），管理端审计页同步补标签与筛选项。测试执行本身仍只写 `test_case_run` 业务流水（谁、何时、结果都在），不再重复写审计；AI 批量建用例逐条走 `caseService.create`，因此也会逐条留下 `test_case_create`。甘特依赖的新建/编辑/删除同批补写空间活动（两端任务名、类型、延后天数，编辑只记变化项）。管理催办补写批次审计（`manager_nudge`）与实际发出任务的任务时间线（`nudge`）；版本工作区「历史」页新增「版本操作记录」，展示 `version_log`。仍未覆盖：空间活动聚合视图、测试域逐条实体时间线。

## 二、现有轨迹面盘点

| 轨迹面 | 存储表 | 读取入口 | 内容范围 | 写入方式 |
|---|---|---|---|---|
| 空间活动流 | `task_log` | `GET /api/activity` | 任务域事件 + `task_id='CFG'` 的配置事件；非空间主/管理员看不到 CFG | 各 Service 手工写 |
| 任务操作时间线 | `task_log` | `GET /api/tasks/{id}/logs` | 单任务事件（含列移动、计时、评论、附件、子任务） | 各 Service 手工写 |
| 项目活动 | `work_activity`（`entity_type='project'`） | `GET /api/projects/{id}/activities` | 项目创建/编辑/归档/首版上线 | `WorkActivityService` |
| 文档活动 | `work_activity`（`entity_type='requirement_doc'`） | `GET /api/req-docs/{id}/activities`、文档动态流 | 文档创建/正文/标题/状态/负责人/分享/排序 | `WorkActivityService` |
| 需求池日志 | `demand_log` | `GET /api/demands/{id}/logs` | 需求创建/编辑/评审/排期/取消/恢复 | `DemandService` |
| 分支日志 | `dev_branch_log` | `GET /api/branches/{id}/logs` | 分支创建/编辑/状态流转 | `BranchService` |
| 版本历史 | `version_log` | `GET /api/versions/{id}/release-history`（版本工作区「历史」页已调用） | 版本创建/编辑/开始/发布计划/发布结果 | `VersionReleaseService` |
| 管理员审计 | `audit_log` | `GET /api/admin/audit/logs` | 登录、成员/权限、导入导出、账号管理、删空间/项目 | `AuditService` |
| 测试执行流水 | `test_case_run` | 用例详情执行记录 | 每次执行结果；**不是活动轨迹** | `TestCaseService` |
| 工时记录 | `time_log` | 任务详情/统计 | 计时与补记；**不是活动轨迹** | `TimeLogService` |

关键实现：

- `ActivityService.activity()` 只调用 `TaskLogMapper.countByWorkspace/selectByWorkspace`（`service/ActivityService.java:64`），没有 union 其他日志表。
- `TaskLogMapper.xml` 的空间活动查询只 join `task` 和 `app_user`，不涉及项目/文档/需求/分支/版本。
- 没有全局 AOP、拦截器或数据库触发器统一记录写操作；`grep` 未发现 `CREATE TRIGGER`。
- 各日志写入失败策略不一致：任务审计/需求/分支日志失败会抛异常回滚；空间活动、管理员审计、业务活动失败只 warn（`ActivityService.java:46`、`AuditService.java:60`、`WorkActivityService.java:56`）。
