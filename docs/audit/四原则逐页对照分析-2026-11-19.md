# 沙漏 · 四原则逐页对照分析

- 日期：2026-11-19
- 范围：30 个路由视图 + 全局壳 + 任务详情抽屉 + 登录 / 加入 / 分享三个独立页
- 方法：静态代码审阅（逐个读取视图的交互、请求与反馈代码），未启动服务、未跑浏览器
- 证据：路径相对 `frontend/`，格式 `文件:行号`；标注「需实测」的结论需要在浏览器里复核
- 性质：只做审计，不改产品代码

对照的四条原则：

| 编号 | 原则 | 本次落到代码上的检查点 |
|---|---|---|
| 1 | 可见性 | 状态与能力是否可见；主操作是否显眼；加载/空/错误是否有明确形态；关键功能是否被藏 |
| 2 | 反馈 | 每次点击是否有即时态、进度、结果；错误是否说明原因与下一步；有没有沉默失败 |
| 3 | 映射 | 控件与作用对象是否对应；操作后的结果是否符合直觉；范围与数字是否对得上 |
| 4 | 一致性 | 同类操作同形态；同一概念同一个词、同一个算法；跨页同一状态同一颜色 |

评级：**优 / 良 / 有风险 / 不合格**。严重度：**P0 破损**（本周可改）、**P1 结构**（一个迭代）、**P2 打磨**（随功能迭代）。

---

## 1. 结论先行

**总体判断：局部达标，成体系不足。**

共享反馈能力其实已经建好了：`UI.toast` / 8 秒撤销（`js/core/ui.js:74-76`）、骨架屏与空态组件（`js/core/ui.js:502-544`）、错误态带重试按钮（`js/core/ui.js:523-527`）、弹层焦点陷阱、看板与甘特的乐观更新 + 失败回滚。正常路径上的核心任务（拖拽流转、文档自动保存、测试执行）是可靠的。

但四条原则在四类问题上同时失守，而且都是同一个模式重复出现：

1. **错误被伪装成空态或健康态**——失败与「真的没有数据」长得一模一样。
2. **主操作靠悬停或藏进「更多」**——触屏与键盘用户拿不到，新用户也找不到。
3. **范围与口径不可见**——导出、全选、统计、筛选各有一套没说出口的边界。
4. **只读靠隐藏**——按钮直接消失，用户不知道是没权限还是没功能。

### 三条最硬的证据

**证据一：失败渲染成「没有数据」和「状态良好」。**
分支接口失败后清空并显示「还没有分支」（`js/views/branches.js:337-338,862-881`）；通知加载失败把 `items` 置空，页面显示「还没有通知」（`js/core/notifications.js:434-441,309`）；截止提醒接口失败同样置空，摘要显示「节奏健康」（`js/core/notifications.js:454-466,402`）。前两处让用户以为数据被删了，第三处直接给出与事实相反的健康结论。这是本次最严重的一类问题。

**证据二：大量「重试」按钮没有绑定任何处理函数。**
测试模块全域 9 处错误态（`js/views/testcases.js:1457,1656,1809,2238,6071,6312,6690,8565,9014`）、项目列表（错误态由 `js/views/board.js:398-401` 注入，`js/views/projects.js:1544-1632` 无 `data-empty-action` 处理）、交付说明的项目选择器（`js/views/delivery.js:60-63`）、报表估算误差（`js/views/analysis.js:604`）都是死按钮。根因是公共函数 `setPageError` 只给第一个按钮绑定事件（`js/core/utils.js:12-22`）。按钮可见、点了没反应，同时违反原则 1 和原则 2。

**证据三：同一个词在不同页面算出不同的数。**
「通过率」有四种算法：覆盖矩阵 `passed/(total-skipped)`（`js/views/testcases.js:1567`）、测试报告同一公式但含未执行（`:1891`）、执行统计 `passed/(passed+failed+blocked)`（`:1762`）、测试计划直接用后端 `d.passRate`（`:6380`）。「剩余工时」在成员负载里有三种范围（`js/views/workload.js:378,426,465`）。周回顾「进行中」有两处不同定义（`js/views/review.js:414` vs `167-170`）。同名不同数直接摧毁原则 4 建立的可信度。

### 最需要优先处理的五个体验断点

1. 交付说明叙述**失焦即自动确认**，并写入 `confirmed`（`js/views/delivery.js:680-689,587-590`）——用户只是点开别的字段，系统就记成「已确认」。
2. 文档「发布」**不先保存**（`js/views/requirements.js:6097-6121`，入口 `:6680`），而关闭弹窗的发布路径会先保存（`:6659-6663`）——同类动作两种结果。
3. 重试按钮死链（见证据二）。
4. 测试通过率四口径（见证据三）。
5. 通知与分支把失败显示成空态（见证据一）。

## 4. 逐页分析

### 4.1 全局与外壳

#### 1. 全局壳：导航、搜索、空间切换

主任务：知道自己在哪个空间/哪个视图，快速到另一个视图或找到一条工作项。

评级：可见性 良 / 反馈 良 / 映射 有风险 / 一致性 有风险。

做得好的：子导航在「工作项 / 项目 / 测试 / 报表」域内切换，不用回侧栏；移动端 Tab 与侧栏一级分组同源；lazy 视图加载有统一的忙碌态。

- **G-01 · P2 · 原则3** 全局搜索按钮与作用域内搜索输入框相邻（`index.html:255-271`）。输入框占位只写「搜索工作项…」，实际只筛当前视图，区别只写在 `title` / `aria-label` 里。成本：用户在输入框里找全局内容，得到「无结果」。改：占位改为「筛选当前视图…」，或合并为一个搜索带作用域切换；验证：在两个入口各搜同一关键词。
- **G-02 · P2 · 原则1/2** 离线徽标只依据 `navigator.onLine`（`js/main.js:188-193`），接口 5xx 或超时仍显示在线；恢复后无「已恢复」提示。成本：用户以为数据是最新的。改：叠加接口失败指示与重连 toast；验证：DevTools 断网后再放开，应出现「网络已恢复」。
- **G-03 · P2 · 原则4** 移动端把「分支」归到工作项 Tab（`js/core/router.js:146`），侧栏把它放在「交付」（`:140`）。成本：同一入口两套位置记忆。改：以侧栏分组为准；验证：手机宽度下从「交付」进分支，底部 Tab 高亮应与侧栏一致。
- **G-04 · P2 · 原则1** 首次进入 lazy 视图的加载是整块 `chunkBusy`（`js/core/ui.js:572-575`），没有「正在加载某模块」的文字。成本：慢网下像卡死。改：加模块名文案；验证：限速 3G 首次进「影响链」。

主任务：看全一条工作项，并就地改状态、改期、计时、取消/恢复。

评级：可见性 良 / 反馈 良 / 映射 有风险 / 一致性 良。

做得好的：所有写操作都有成功/失败 toast，权限拒绝说明原因；计时互斥会自动暂停并告知；412/422 冲突有二次确认。

- **D-01 · P2 · 原则2** 详情里点关联实体（分支 / 需求 / 文档 / 测试用例）时，懒加载失败被 `.catch(function(){})` 吞掉（`js/core/task-actions.js:486,605,617,621-631`）。成本：点击没有任何反应。改：失败 toast「关联内容加载失败」；验证：断网后点关联 chip。
- **D-02 · P2 · 原则2** 项目状态规则加载失败静默（`js/core/task-actions.js:341`），状态下拉可能缺项。成本：用户以为没有这个状态。改：失败时保底用默认规则并提示；验证：拦截 `/api/rules` 返回 500。
- **D-03 · P2 · 原则2** 抽屉打开失败只 toast「工作项不存在或你没有访问权限」（`js/core/task-actions.js:30-36`），无重试或跳转。成本：链接失效后到此为止。改：toast 带「返回列表」动作；验证：打开一个已删除 ID 的深链。

## 7. 需要产品决策的点

这些不是实现问题，需要先定口径再改：

1. **列表导出范围**：导出当前筛选全量（推荐）还是当前已加载？决定后 UI 才有一致的文案。
2. **只读用户能否导出/分享**（交付说明、文档）：现在没有门禁；需要按角色给明确规则。
3. **「我的工作」的计时是否常驻**：常驻会提高可见性但增加视觉噪音；建议常驻图标、菜单收纳文字。
4. **交付说明的「确认」语义**：是「我写完了」还是「我核对过内容」？前者可以失焦自动存，后者必须显式点。
5. **通过率分母**：是否计入「未执行」与「已跳过」？建议分母为「已执行」（passed+failed+blocked），未执行单列，报告里另给「执行率」。
6. **「剩余工时」是否含测试**：成员负载与我的工作必须同一个答案。
