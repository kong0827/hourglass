## 一、结论（直接回答）

**1. 能否跨空间访问？不能。**
所有带 `workspace` 的接口都会先解析空间成员身份；不是成员一律返回 `404 空间不存在`。按 ID 直接读取其他空间的工作项、文档、任务、附件也返回 404；跨空间写请求在“实体所属空间 ≠ 当前空间”处被拦截。跨空间的唯一合法入口是用户本身就是两个空间的成员，通过切换 `workspace` 参数访问——这是设计预期。

**2. 能否跨项目访问？默认可以，显式收紧后不能。**
空间角色为 `member` 的用户，对没有配置记录的项目**默认可见且可写**；管理员把某项目配成 `none` 后，该项目的需求、任务、文档、需求条目、测试、版本、分支、附件、统计、搜索、甘特、看板、导出、通知都会被过滤，详情接口返回 404；配成 `read` 后可见但所有写操作返回 403。

**3. 有三类“例外”需要产品明确认知：**
- `viewer`（查看者）是**全空间只读**，项目级 `none` 对它不生效，能看到所有项目；
- `owner/admin` 天然全量，不受项目范围限制；
- 甘特公开分享是**整空间**的只读快照，包含被项目级隐藏的工作项，凭链接即可访问（30 天有效，可撤销）。

**4. 未发现“非成员读取任意空间数据”的漏洞。** 发现 1 处跨空间引用校验缺失（测试计划可引用其他空间的项目 ID），但该路径不返回对方项目内容，属于数据完整性缺陷而非信息泄露。

## 二、权限模型

| 层级 | 载体 | 规则 |
|---|---|---|
| 平台管理员 | `app_user.role='admin'` | 可访问 `/api/admin/**`：账号管理、全空间审计日志、系统信息 |
| 空间角色 | `workspace_member.role` | `owner` / `admin` 全量；`member` 受项目范围约束；`viewer` 全空间只读 |
| 项目可见范围 | `project_member.access` | 仅持久化 `none` / `read`；`pm/dev/qa` 为历史值，统一按“默认参与”处理；**无记录 = 默认参与** |
| 公开凭证 | `gantt_share.token`、`req_doc_share.token`、`invite.id` | 无登录，凭 token/邀请码只读或加入 |

关键实现：

- `ProjectAccessService.canView/canWrite`：`backend/src/main/java/com/hourglass/service/ProjectAccessService.java:92,110`
- 不可见按“不存在”处理（404，不泄露存在性）：同文件 `:133,139`
- SQL 级范围过滤：`viewerScope` 仅对 `member` 返回 userId，`hiddenProjectIds` 返回显式 `none` 项目（`:193,268`）
- 空间成员校验：`WorkspaceService.requireMember/requireOwner/requireManager/requireWriter`（`:143,160,169,179`）
- 查看者写拦截：`WorkspaceArgumentResolver` 对所有带 `WorkspaceCtx` 的 POST/PUT/PATCH/DELETE 统一 403
- 认证放行面：`SecurityConfig` 仅放行健康检查、`GET /api/invite/**`、`GET /api/share/**`；`/api/admin/**` 要求平台管理员

> 设计口径提示：项目范围只限制 `member`。这不是遗漏，代码注释明确“owner/admin/viewer 不做项目级隐藏”；但对“外部只读用户”场景存在风险，见问题 P2-2。

## 三、空间隔离审计

### 3.1 入口层

- 每次请求通过 `?workspace=` 解析空间并校验成员身份（`WorkspaceService.requireMember`），非成员 404。
- 未显式传 `workspace` 时回落到个人空间 `W{userId}`，不会“默认全空间”。
- `GET /api/invite/**`、`GET /api/share/**` 是仅有的匿名接口，均要求有效凭证，且只读。

### 3.2 资源层（按 ID 直取）

所有实体读取遵循同一模式：先按 ID 取实体 → 比对 `workspace_id` → 再做项目可见性校验。审计覆盖：

| 模块 | 跨空间行为 | 证据 |
|---|---|---|
| 项目/需求 | 404 | `RequirementService` 每个读写方法先比对 `workspaceId` |
| 任务深链 | 404 | `TaskQueryService.forDeepLink` 只在“我参与的空间”内查，再叠加项目范围 |
| 任务列表/看板 | SQL 限定 `workspace_id` | `TaskMapper.xml` 所有查询带空间条件 |
| 需求文档/文档活动 | 404 | `RequirementDocService.getVisible`：空间 + 项目范围 + 草稿可见性 |
| 需求条目/测试用例/测试计划 | 404 | `DemandService`、`TestCaseService`、`TestPlanService.requirePlan` |
| 版本/阶段/发布计划 | 404 | `VersionPhaseService.requireProject`、`VersionReleaseService.requireVersion` |
| 分支 | 404 | `BranchService.get(workspaceId,id)` + `assertView` |
| 附件 | 404 | `AttachmentService.ensureTarget` 校验目标实体空间；下载接口实测 HTTP 404 |
| 评论/计时/子任务/关注 | 404 | 均先校验任务空间，再 `assertViewTask`/`assertWrite` |
| 通知中心 | 只返回本人通知 | 查询固定 `user_id`，并排除已离开空间（成员移除通知除外） |

### 3.3 跨空间引用（写路径）

`TaskCommandService.applyRequest` 对每个外键做“同空间 + 同项目（必要时）”校验：项目、分类、需求文档、分支、阻塞任务、需求条目、Epic、版本、负责人。跨空间 ID 无法写入任务。

唯一缺口：**测试计划创建**（见 P3-1）。

### 3.4 批量与导出

- `GET /api/export`（JSON 全量备份）仅空间主；`GET /api/export/csv` 对成员按 `hiddenProjectIds` 过滤。
- `/api/my-tasks` SQL 直接 `JOIN workspace_member`，并按项目 `none` 排除（`TaskMapper.xml:226,336`）。
- 全局搜索只聚合已按空间/项目/草稿范围过滤的结果（`SearchService:51-120`）。
- 管理驾驶舱、移动端总览、统计、完成记录均以 `viewerScope` 或 `hiddenProjectIds` 收口。

### 3.5 事件广播

`ChangeBroadcastFilter` 在写成功后广播 `changed` 事件；`SseService.projectBlocked` 会按接收者的项目范围丢弃不可见项目的事件。缺少 `workspace` 参数时会向所有订阅者发送一条**空载荷**刷新事件，属噪音，不泄露数据（P3-3）。

## 四、项目级可见范围审计

### 4.1 生效范围

对 `member` 显式配置 `none` 后，以下位置均验证为不可见（详情 404、列表中剔除）：

- 项目列表与项目任务
- 任务列表 / 看板 / 甘特 / 统计 / 完成记录
- 需求文档列表、文档详情、文档活动
- 需求条目、测试用例、测试计划
- 版本、阶段统计、发布计划
- 分支看板与列表
- 附件下载/预览
- 全局搜索
- CSV 导出
- 通知与 @提及候选
- 管理驾驶舱、移动端团队视图

配置为 `read` 后：读取正常，任务创建、评论、计时、文档分享等写操作统一 403「你对该项目只有查看权限」。

### 4.2 配置入口的保护

`PUT /api/workspaces/{id}/project-access` 的校验顺序：

1. 空间成员 → 2. 空间主/管理员 → 3. 必须共享空间 → 4. 目标成员必须是 `member` → 5. 项目必须属于当前空间 → 6. `access` 只能是 `none` / `read` / 空。

实测：查看者被拒 400、空间主被拒 400（天然全量）、普通成员被拒 403、外空间项目 404、非法取值 400。

### 4.3 默认参与是当前最大暴露面

`canView`/`canWrite` 对“没有配置记录”的成员返回可读/可写。邀请加入的新成员只写 `workspace_member`，不会生成任何 `project_member` 记录，因此**加入即获得全部项目（含敏感项目）的读写权限**，直到管理员逐格收紧。

这不是代码缺陷，而是产品选择；但对“临时外包 / 外部顾问”场景风险偏高，建议至少在前端明确提示，或提供“新成员默认只读”的空间级开关（见 P2-1）。

## 五、公开分享与邀请

### 5.1 甘特公开分享

- 创建/查看/撤销仅空间主；token 为 24 字节随机数的 URL-safe Base64（32 字符），有效期 **30 天**，可随时撤销。
- 公开响应包含**整个空间**的任务：内部 ID、标题、负责人显示名、优先级、列、计划/到期日、进度、里程碑、阻塞、预估分钟、实际分钟、依赖、基线、优先级配置。
- **不应用项目级可见范围**：被 `none` 隐藏的项目同样出现在公开链接里。
- 实测：75 个任务（含隐藏项目任务 1 个），撤销后立即 404。

判断：这是“空间主主动把整个空间公开”的能力，本身可控；但若团队用项目级隐藏隔离敏感项目，公开分享会绕过该隔离，且链接一旦外流，30 天内任何人可读。建议至少在产品文案中写明“分享包含空间内全部项目”，并提供“按项目分享 / 隐藏工时与负责人”选项（P2-3）。

### 5.2 需求文档分享

- 只有**已发布**文档可分享；创建/查看/撤销要求对该项目有写权限。
- 响应仅包含空间名、标题、类型、格式、正文、状态、负责人、更新时间。
- 30 天有效、可撤销；草稿不可分享；收回发布后公开链接立即 404。
- 实测：只读成员创建分享被拒 403；撤销后 404。

### 5.3 邀请链接

- 空间主/管理员创建；10 位邀请码（31 字符表，约 49.5 bit），7 天有效；个人空间不可邀请。
- 公开 `GET /api/invite/{code}` 只返回空间名、邀请人显示名、到期时间；加入需登录，已是成员时返回 `already=true`。
- 撤销后 404。未发现可枚举或越权加入其他空间的路径（未做限流验证）。

## 七、问题清单与修复建议

| 编号 | 级别 | 问题 | 影响 | 建议 |
|---|---|---|---|---|
| P2-1 | 中 | 新成员/无配置成员默认可见且可写全部项目 | 外部协作、外包、临时成员获得超出预期的读写范围 | 邀请页明示“默认获得全部项目权限”；增加“新成员默认只读”空间开关；提供一键全员设为默认参与的批量操作 |
| P2-2 | 中 | `viewer` 绕过项目级 `none`，全空间可见 | 若把查看者当作“外部只读访客”，会看到本应隔离的项目 | 明确产品口径；或允许对 viewer 也应用项目范围（只读子集） |
| P2-3 | 中 | 甘特公开分享 = 整空间快照，含隐藏项目、负责人、实际工时、内部 ID | 链接外流后 30 天内可读全部项目；与项目隔离策略冲突 | 分享时可选项目范围；可选隐藏负责人/工时；缩短有效期或支持自定义；记录访问审计 |

| P3-2 | 低 | `canView/canWrite` 对 `userId == null` 返回 `true` | 当前无调用方传 null，但属 fail-open，未来新代码可能误用 | 改为抛异常或返回 false；在 Service 入口断言当前用户 |
| P3-3 | 低 | 写请求缺少 `workspace` 参数时向所有订阅者广播空事件 | 仅造成无意义刷新，无数据泄露 | 无 workspace 时跳过广播，或要求写接口必须带 workspace |
| P3-4 | 低 | 业务 403 多数以 HTTP 200 返回；附件下载失败返回 HTTP 404，风格不一致 | 网关/WAF/监控难以按状态码识别越权尝试 | 保持现有前端契约的前提下，增加审计日志与响应头标记，便于检测 |
| 信息 | - | 平台管理员可跨空间查看审计日志、管理全部账号 | 符合平台运维预期，但属最高信任边界 | 限制平台管理员数量；开启操作审计；生产环境单独保管账号 |
| 信息 | - | 分享 token 明文存库 | 数据库泄露时 30 天内可直接使用 | 可改为存哈希；支持按空间一键重置全部分享 |

## 九、一句话总结

**空间边界是硬的，项目边界是“默认软、配置后硬”的；当前没有发现非成员跨空间读取数据的通道。真正需要产品拍板的是三件事：新成员默认权限、查看者是否应受项目隔离、以及甘特公开分享的暴露范围。**
