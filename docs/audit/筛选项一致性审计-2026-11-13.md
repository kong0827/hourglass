# 筛选项一致性审计（2026-11-13）

结论：**不统一**。问题不只是「选项名称不同」，而是工作项、测试用例、缺陷、分支四类页面用了三套筛选范式：富筛选栏、原生下拉条、弹层。同一维度（项目 / 状态 / 负责人 / 优先级 / 清空）在位置、单选或多选、计数、默认值上各不相同。

本次只做代码审计，未改代码。截图见 `docs/audit/prototypes/filter-consistency-2026-11-13/`。

## 1. 基线：工作项筛选栏

- 四个高频维度平铺在独立筛选栏：项目、状态、负责人、优先级；均为多选，带计数、列表内搜索、选中值回显（`frontend/index.html:283`、`frontend/js/core/filters-ui.js:241`、`:322`）。
- 「更多筛选」为两级面板：模块、标签、类型、版本、截止日期、开始日期、完成情况、其他（`filters-ui.js:424`）。
- 选项零计数隐藏；空值项保留（无负责人 / 未指定模块 / 待规划）；已选条件可单维清除；有「清空筛选」「视图」；手机为摘要 + 底部面板（`filters-ui.js:25`、`:1473`）。
- 甘特另用弹层，但维度与主栏一致：状态、负责人、优先级、类型、版本、项目、模块、标签、到期、完成、其他、关键词（`frontend/js/views/gantt.js:1919`）。

## 3. 需要调整的问题

### P0：误导或明确缺口

1. **缺陷表有「优先级」列，却筛不了优先级。**（批 1 已修）
   表头与行都展示优先级（`frontend/index.html:1492`、`frontend/js/views/testcases.js:517`），抽屉也可编辑；缺陷筛选条只有严重度、状态、负责人、发现版本（`index.html:1458`）。缺陷是任务，模块、标签同样存在但未暴露筛选，优先级是最明显的一处。

2. **用例优先级筛选不跟随空间自定义名称。**（批 1 已修）
   筛选项直接渲染 `P0–P3`（`testcases.js:1414`），而列表、抽屉、主筛选栏都用 `priName()`（`testcases.js:882`、`:1063`；`filters-ui.js:136`）。设置里改过 P0–P3 显示名后，筛选下拉与结果列显示两套叫法。

3. **搜索占位符与实际范围不一致。**（批 1 已修）
   - 缺陷默认就是「全部项目」（`testcases.js:93`），输入框仍写「搜索本项目缺陷…」（`index.html:1459`）。
   - 用例切到「全部项目」后仍写「搜索本项目用例…」（`index.html:1426`），只在单项目下正确。
   - 分支搜索标题写「在全部项目（或左侧所选项目）中…」（`index.html:1800`），但分支页已经没有左侧项目列表，项目筛选在工具条右侧。

4. **分支页没有清空筛选入口。**（批 1 已修）
   三个下拉只能逐个恢复；空状态文案却写「清掉状态/负责人/项目筛选再试」（`frontend/js/views/branches.js:449`、`:462`）。只有从「我的工作」深链进来时才有「清除来源 ×」。主栏、用例、甘特、需求池都有清空入口。

### P1：交互与口径不一致

5. **项目范围控件位置不一致。**（批 2 已修）
   主栏在筛选区第一位（`index.html:314`），缺陷在筛选条第一位（`:1458`），分支在工具条（`:1786`），用例却放在操作栏、夹在「筛选 / AI 生成 / 导出 / 新建」之间（`:1443`）。同一个「全部项目 / 单项目」控件出现三种位置。

6. **「清空筛选」与「重置」语义不同。**（批 2 已统一语义；缺陷保留「恢复默认」）
   主栏、用例、甘特都叫「清空筛选」，但主栏和甘特会把项目筛选一起清掉（`filters-ui.js:1091`），用例保留当前项目；分支没有；缺陷的「重置」会把范围也拉回「全部项目」，并恢复「未关闭」默认（`testcases.js:718`）。按钮名称和后果都没有说明，用户无法预判。

7. **分支负责人候选是全体成员，不是实际有分支的人。**（批 2 已补计数并隐藏零结果；「未指派」待批 3）
   下拉来自成员花名册（`branches.js:1094`），因此会出现零结果选项；没有「未指派」，而分支行本身会显示「未指定」（`branches.js:307`）。主栏隐藏零计数并保留「无负责人」，缺陷保留「未指派」（`testcases.js:413`）。

8. **保存视图只覆盖部分页面。**（批 2 已补缺陷、分支）
   主栏、用例、甘特、需求池有视图；缺陷、分支没有（用例视图作用域见 `filters-ui.js:715`、`testcases.js:1452`；分支只记住看板/列表，`branches.js:32`）。刷新后缺陷条件全部丢失，分支只保留视图形态。

9. **测试计划没有任何筛选。**（批 2 已补搜索与状态筛选）
   计划页只有一个容器（`index.html:1501`），全部项目下逐项目拉取并平铺（`testcases.js:2709`），没有搜索、状态、负责人或版本筛选；计划多时只能滚动查找。

10. **移动端三套形态。**（批 2 已补用例筛选角标；批 3 分支改为折叠面板）
    主栏是摘要 + 底部面板（`frontend/css/mobile.css:120`）；用例折叠且按钮带「已筛 N 项」角标（`mobile.css:755`、`testcases.js:3333`）；缺陷平铺两列（`mobile.css:767`）；分支折叠面板与用例同形（`mobile.css` 分支段）。

### P2：可选优化

11. **选项计数不统一。**（批 2 分支负责人；批 3 用例/缺陷/分支全部就位） 主栏每个选项都有计数；缺陷按当前条件做前端 facets；分支负责人、版本按当前项目范围计数；用例由后端 GROUP BY 返回计数（`TestCaseMapper.xml`），零结果档位隐藏。
12. **空值词汇不统一。**（批 3 统一常用四类） 分支与用例执行人统一为「未指派 / 未指定执行人」，缺陷为「未指派 / 未指定模块 / 未填写 / 未设置 / 无标签」，甘特分析为「未指派」；其余历史写法保留在各自领域。
13. **分支卡片显示版本标签，却没有版本筛选。**（批 3 已补，`branches.js:563`） 后端新增 `version` 查询参数，经 `version_task` 反查任务所属版本；候选接口 `/api/branches/versions` 只列当前项目内真有分支的版本并带计数。
14. **归档项目处理不一致。**（批 3 已统一） 分支项目下拉不再列出归档项目，仅在已选中该项目时保留；与用例、缺陷「默认排除、已选保留」口径一致。
15. **维度顺序不同。**（批 3 已统一） 用例、缺陷、分支均按「项目 → 状态 → 负责人 → 优先级 → 版本 / 严重度 → 模块 → 标签 → 搜索」排列；用例状态为执行结果 chips，缺陷默认「未关闭」，保留领域语义。

## 4. 不宜强行统一的地方

- **项目两态 vs 多选。** 用例、缺陷、分支的「全部项目 / 单个项目」是浏览与写入范围，不是多选条件；主栏的项目多选是跨项目筛选。此前已明确不做复选，应保留两态，只统一控件位置与文案。
- **缺陷默认「未关闭」。** 这是缺陷页的默认口径，不是异常筛选；保留默认，但应标明「默认未关闭」并说明「重置」会回到这个状态。
- **领域状态不合并。** 用例执行结果、缺陷修复/回归状态、分支状态是三套业务状态，不应塞进同一个状态选项表；需要统一的是控件形态与反馈，不是枚举值。
- **「执行人」不是「负责人」。** 用例的执行人来自最近一次执行记录（`TestCaseMapper.xml:129`），不是指派关系，不宜直接改名。
