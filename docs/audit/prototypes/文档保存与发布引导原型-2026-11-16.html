文档保存与发布 · 引导设计原型

可交互：改动正文会出现「有未保存的修改」；点击 保存 走当前方案；点 发布 直接发布； 点 ← 返回 触发关闭链路；右上角可切换 草稿 / 已发布 与明暗主题。

链路与提示位置

① 编写 / 保存→ ② 草稿 · 仅负责人与管理员可见→（保存后提示 / 关闭兜底） ③ 发布→ ④ 项目成员可见（编辑即时生效）

方案对照

方案保存草稿后关闭编辑器（仍是草稿）发布入口主要代价
现状仅 toast「文档已保存」直接关闭，无提醒工具栏中部 ghost 按钮，与 AI/大纲混排问题持续：作者以为保存即发布
A1 轻提示（推荐）toast「已保存为草稿 · 暂不可见」+「发布」动作，不打断弹窗「仍是草稿」：留在草稿 / 发布并关闭（未保存时三选一）移到保存左侧 + soft 底；已发布变绿色「已发布」chip提示可能被无视（非阻断）
A2 保存后确认弹窗「是否发布？」暂不发布 / 发布；可勾选本次编辑不再提醒同 A1同 A1每次保存多一步确认，长文写作易疲劳（首保弹一次可缓解）
B 保存并发布主按钮即「保存并发布」；「仅保存草稿」为次按钮三选一：不保存 / 存为草稿关闭 / 发布并关闭主按钮即发布（已发布后回退为「保存」）易误发布半成品；主按钮语义随状态变化

设计说明

  • 发布是一次性状态迁移（草稿 → 项目可见）：已发布的文档再保存即时生效，无需重复发布。因此引导按「首次进入可见」设计，而不是每次保存都加确认。
  • 问题根因有两个：一是保存后没有任何「仍是草稿」的反馈；二是发布入口混在 AI / 大纲等 ghost 按钮中间且离保存很远。A 系列同时修这两点。
  • 保存后提示用不打断的 toast（带「发布」动作），长文反复保存时不制造弹窗疲劳；关闭是作者认为「做完了」的时刻，此时兜底问一次。
  • A2 的弹窗仅本次编辑首次保存触发，勾选「本次编辑不再提醒」后降级为 toast —— 兼顾「不想被打断」和「别忘发布」。
  • 已发布后不再提示：发布按钮变绿色「已发布」chip（状态展示，非按钮）；收回发布低频且会失效分享链接，收进「更多」菜单。
  • 发布提示文案沿用现有可见范围口径（团队共享 / 指定成员 / 仅自己），不新造概念；列表与左树的「草稿 / 已发布」徽标不变。
  • 自动保存的本地草稿恢复（#reqDocAutoDraft）不触发任何发布提示；导入 / 模板新建的文档首次保存走同一口径。
  • 若团队更希望「保存即对团队可见」，选 方案 B：默认动作改为发布，但需接受误发布半成品的风险（可收回，代价可控）；推荐 A1。
