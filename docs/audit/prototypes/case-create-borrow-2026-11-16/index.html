借鉴清单 逐条对照工作项 / 文档创建，只借现有能力能承接的部分

来源可借的做法用例新建现状新案怎么借结论理由
工作项除标题外都有默认值（类型 / 优先级 / 列 / 负责人）优先级默认「不设置」默认 P2，保留「不设置」借少一次决策；覆盖矩阵里大多数用例至少有优先级。
工作项「更多设置」收起时摘要显示当前值摘要固定为字段名显示「未填 / 已填 N 项」借收起后仍能知道填没填，不用展开确认。
工作项歧义字段就地解释（负责人 vs 测试负责人）模块只有「继承自需求」标签模块下补一句「项目内目录，不改所属项目」借与详情编辑态已落地的说明同口径。
工作项
（详情）		「保存并继续」留在原地继续补保存即关闭「保存并再建一条」，保留需求 / 模块 / 优先级借借的是「不打断当前上下文」的心智；新建场景改成再建一条。该按钮在工作项新建态默认隐藏，属于平台既有惯例的延伸。
工作项创建页写明「新建后可继续补充」脚注泛化「保存后可继续记录执行与转缺陷」「保存后可在详情补步骤、记录执行」借只改文案，告诉用户下一步在哪。
文档只有名称必填，其余按默认创建实际只有标题必填，但页面没写出来头部写明「只有标题必填」借降低「不敢点保存」的犹豫。
文档标题回车即创建回车无动作标题内回车 = 保存借连续录入时少一次挪鼠标。
文档「位置：归属 › 分类 › 上级」路径回显模块在需求支线里，看不到完整路径模块下加「位置：项目 › 目录 › 子目录」借只借回显，不另起「存放位置」段，避免和需求继承打架。
文档「从哪里开始」空白 / 模板 / 导入无用例模板体系；导入已在列表工具栏不加不借无对应能力，且会与列表导入形成重复入口。
文档「新建并编辑」保存即关闭，详情是阅读态不加，用「保存并再建一条」替代不借用例详情不是编辑器；批量编写比立刻进详情更常见。
文档归属项目可改项目由入口决定保持只读，在头部显示项目不借放开等于「搬项目」，模块与工作项候选都会失效。
其他草稿后端无草稿态不做不借属于新能力，不是布局问题。
其他创建时选分组详情归类里可改；创建接口无分组字段不加不借需创建后二次写入，失败会留下「建了但没进组」的半成功。
其他用例类型 / 适用阶段数据模型无这两个字段不加不借不能为了填满表单虚构字段。

不借不等于永远不做。草稿、创建时分组、用例类型 / 阶段都需要先有数据模型或接口，属于另一个议题；本次只做前端可承接的改动。
