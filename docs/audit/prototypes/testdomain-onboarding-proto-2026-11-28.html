测试域新手友好重设计 · 交互原型

2026-11-28 · 参照「版本发布全流程」原型形制 · 覆盖 工作台 / 用例 / 测试计划 / 报告 四块，缺陷列表结构不动只接新手条。截图用 #hash 直达各画面。

问题（现状截图证据）

① 测试计划页空态是一句话+右上角小按钮，新手到这是死胡同；② 「报告」藏在测试计划的页签里，IA 上报告不属于计划；③ 用例页工具条四层、左栏+列表+批量条同屏，新手没有从哪开始的叙述；④ 报告零数据时一排 0% KPI，无决策价值还误读为健康；⑤ 测试域完全没有接入全局已有的引导机制（首屏引导卡 / 空态动作 / 示例项目先例）。

方案：一条工作流、一个家、每步有动作

核心模型照发布原型：「准备用例 → 圈选成计划 → 执行记录 → 报告导出」四步流程条常驻工作台，进度由真实数据派生（用例数/计划数/执行数），点任意一步直达对应页面。测试域新增「工作台」子导航并设为默认落地：新手任务清单卡（5 项，做了自动勾掉）、我的待办（待执行/待复测）、进行中计划、最近报告一屏收齐。熟练用户不受打扰：清单可关，子导航一格直达用例。

决定 1：新增工作台落地页（替代：仅强化三页签空态）｜代价：多一个入口；反悔点：熟练用户嫌多一跳时加「默认落地页」本机设置。
决定 2：引导用常驻清单卡+可关提示条（替代：分步遮罩 tour）｜理由：遮罩打断工作流，与「干活即记录」冲突；清单由真实数据自动勾选，成就感驱动。
决定 3：计划创建走向导四步（替代：单页大表单）｜照搬已批准发布计划形制，每步只回答一个问题。
决定 4：用例空态三入口——AI 生成 / Excel 导入 / 示例用例包（照 showSampleOnboarding 先例，标注合成、一键删除）。
决定 5：报告零数据用「如何生成报告」三步引导卡替换 0 值 KPI。
