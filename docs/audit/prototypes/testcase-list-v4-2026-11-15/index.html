1左侧只回答“我把它归到哪”

分组是用户自建的多归属分类：一条用例可同时进「冒烟」「支付核心」，不影响所属目录。左侧只保留分组树、未分组与动态分组，不再和目录抢同一棵树。

2自定义分组不是我们发明的

竞品里对应物叫法不同：禅道「测试套件」、飞书「用例集」、Azure Test Plans「Static suite」、Xray「Test Sets」（官方明确一条用例可进多个 Set）；云效旧版直接叫「用例分组」，新版改为目录树 + 标签。

3目录收到顶部是取舍

云效、禅道的官方文档里目录树在左侧；PingCode 是模块树、飞书是视图，都在导航内。把目录放进顶部筛选会少“一眼看到层级”，用树形浮层、行内目录路径与保存视图补偿——这一条需要你确认。

4看的方式在表头，不在筛选里

「分组展示」支持状态、优先级、项目、负责人、目录、主需求六个维度，组头吸顶可折叠并显示计数；切换维度不改变筛选结果，也不改变左侧分组选择。

依据 · 分组禅道 测试套件 / 公共用例库；飞书 用例集管理；Azure test suites；Xray Test Sets（一个用例可属多个 Set，只能属一个文件夹）。
依据 · 目录位置云效 用例库左侧目录树、旧版 用例分组；禅道 用例场景树；PingCode 模块树、飞书视图在导航/视图内。
依据 · 按字段分组飞书 按字段分组（最多三级）；Azure query-based suite；Xray 用 JQL 圈选。云效、禅道未见官方按字段分组的说明。
