方案说明 · 用例详情与执行

改哪一层：用例列表保持现状。点开用例不再进编辑弹窗，而是进入一页阅读态详情；执行不再弹「记录执行结果」弹窗，而是把右侧辅助栏切换成「本次执行」表单。编辑仍走现有表单弹窗。

页面结构

  • 顶部返回条：返回用例列表，列表的筛选与滚动位置保留。
  • 标题与元信息行：状态、优先级、标题、只读标记；编号、负责人、最近执行、更新于、关联需求、验证工作项、模块。
  • 正文式分区：前置条件、测试数据、执行步骤（操作 / 预期结果两列表格），按阅读顺序从上往下。
  • 右上操作组：执行 / 重新执行、记录 N、缺陷 / 转缺陷、编辑、删除、更多。
  • 右侧辅助栏：执行记录、缺陷、变更三个页签；执行时整栏切换为表单，正文步骤保持可见。

执行态怎么放

正文不动步骤与预期留在左侧，对照填写结果，避免在弹窗里滚动找步骤。
表单进右栏结果四选一、执行人、环境、备注、失败证据，与现有弹窗字段一一对应。
上一轮上下文表单顶部显示本次为第几轮、上轮结果 / 执行人 / 时间 / 备注。
提交即回归记录后状态、最近执行人、执行记录、变更记录同步更新，页面回到阅读态。

与现有功能对齐

现有能力新页面
执行结果 / 执行人 / 环境 / 备注 / 证据右栏「本次执行」，字段与校验不变
执行历史与失败证据右栏「执行记录」页签，不再单独弹窗
查看 / 转出缺陷右上操作组 + 「缺陷」页签
编辑用例仍打开现有编辑弹窗，本轮不改
批量勾选、筛选、排序、导出列表保持现状

响应式

  • ≥1240：正文 + 322px 辅助栏两栏，辅助栏吸顶。
  • 760–1240：辅助栏收到正文下方，正文全宽；1024 平板即此档。
  • ≤760：单列；执行态表单提到步骤上方，先填结果再对照步骤；步骤表转两列，预期结果以「预期：」子行保留。

代价与残留

  • 详情从弹窗变页面，关闭改用「返回用例列表」，浏览器的返回键行为需要在实施时接上。
  • 执行态在窄屏需滚动；1440 下步骤与表单可同屏。
  • 本轮不动后端：执行、证据、缺陷接口沿用现有契约。
  • 原型为静态演示数据；分步结果、批量执行等现有不支持的能力没有新增。
