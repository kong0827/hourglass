## 0. 设计简报

| 项 | 结论 |
|---|---|
| 谁 | 项目负责人、空间管理员（看投入与偏差）；开发 / 测试 / 产品成员（看自己所在阶段）；只读成员（只看） |
| 任务 | 在项目内、版本内判断「产品 / 开发 / 测试各花了多少」，并下钻到具体工作项 |
| 决策 | 哪一段投入最高、是否超预估、哪个分类或版本拉高了某段 |
| 成功标准 | ① 项目页 10 秒内读出一屏三段占比；② 任一阶段两跳内看到工作项明细；③ 版本之间可直接横向比较三段 |
| 范围 | 项目驾驶舱新增阶段投入面板；版本列表新增阶段列与页头汇总；版本详情新增阶段卡；跨版本表换列；下钻抽屉。不改发布、工作项、计时本身 |
| 约束 | 不新增字段与接口：前端用已有工作项（预计 / 测试预估 / 计时 / 测试窗口 / 类型）派生；沿用 `--plum` / `--primary` / `--palette-6`；史诗不计 |

一句话：**阶段不是新数据，是把同一批工作项的工时换一种拆法**。测试先取测试窗口内计时，剩余按工作项类型拆（需求类归产品 / 设计，任务 / 缺陷归开发），三段互不重叠、合计等于实际工时。

## 1. 对象与状态模型

| 对象 | 字段 | 说明 |
|---|---|---|
| 阶段 | key / 名称 / 口径 / 颜色 | 产品 / 设计（plum）、开发（primary）、测试（palette-6） |
| 阶段汇总 | 条目数 / 预估 / 实际 / 占比 / 偏差 | 条目不可相加（同一工作项可跨阶段）；预估按字段拆；偏差只取已完成且有预估 |
| 工作项 | 标题 / 类型 / 分类 / 负责人 / 阶段工时 / 总实际 | 下钻行；史诗不出现 |
| 版本 | 名称 / 状态 / 工作项 / 预估 / 实际 / 三段 / 偏差 | 版本列表与跨版本表 |

状态：正常（有计时）、无产品计时（产品行 0，中性灰）、无任何计时（条空，文案「还没有已结束的计时」）、加载中（骨架）、加载失败（原因 + 重试）。0 值不着色、不显示 0%。

## 2. 信息架构与入口

```
项目 → 项目驾驶舱
  KPI 四卡 → 阶段投入（新）→ 分类 → 工作项内容 → …
版本与发布（列表）
  页头「阶段投入 · 当前筛选范围」（新）→ 版本行「阶段构成」列（新）→ 版本详情
版本详情 → 概况
  工时 → 阶段投入（新）→ 范围 / 进度 …
首版 / 迭代分析
  阶段工时汇总 → 全部版本：跨版本阶段列（改造）
```

入口不新增菜单；同一任务只有一个主入口。版本详情的阶段数据从「工时构成弹层」上移到概况页内联；弹层保留类型 / 窗口分组，不再重复三段卡。

## 3. 页面骨架与组件

### 3.1 项目驾驶舱 · 阶段投入

顺序：面板头（标题 + 范围 + 实际/预估切换 + 口径）→ 三张阶段卡 → 三段条与图例 → 阶段表（阶段 / 条目 / 预估 / 实际 / 实际占比 / 偏差）→ 脚注。

- 卡片：主数字为当前模式的工时，副行「预估 x · 占 y%」，第三行「N 项有计时」；整卡可点，下钻该阶段。
- 条与图例：8px 三段条，图例逐段可点；读屏 aria 给出三段百分比。
- 表：行可点；下钻列展示该阶段小时数，不伪造「全工时」。
- 位置：KPI 与分类之间；分类表保留窗口外 / 内，不重复阶段拆分。

### 3.2 版本与发布 · 列表

- 页头汇总：范围「当前筛选的 N 个版本」、三段卡、条、跨版本重复计提示；卡可下钻（跨版本）。
- 版本行新增「阶段构成」列：三段细条 + `产品 10.5h · 开发 45.5h · 测试 13.5h`，产品为 0 时显示「产品 —」并不着色；列头写「阶段构成 · 点色块下钻」，色块与 390 的三段 chip 都可下钻到「该版本 × 该阶段」。行本身仍进版本详情。
- 断点：<1280 只留条；<1100 整列收起（详情仍完整）。390 改为三段 chip（30px 高，实现时补足 44px 触控区），未开始时显示一个「尚未开始计时」的禁用 chip。

### 3.3 版本详情 · 阶段投入

- 概况页「工时」卡之后新增面板，结构与项目页一致；范围写明「本版本 N 个工作项」。
- 工时构成弹层：去掉重复的阶段卡，改成一行「阶段拆分见上方『阶段投入』」+ 跳转按钮。

### 3.4 首版 / 迭代分析 · 跨版本

- 「全部版本（跨版本对比）」列改为：版本 / 状态 / 工作项 / 预估 / 实际 / 产品 / 设计 / 开发 / 测试 / 偏差。去掉窗口外 / 内两列（窗口口径仍在下钻与口径说明里）。
- 每个阶段单元格可点，进入该版本 + 阶段明细；行尾偏差保留。0 实际显示「—」，不出现 -100%。
- 390 不压缩整张 9 列表格，改为版本卡：名称 / 状态 / 偏差、完成数与预估实际、三段 chip（可下钻）。
- 页脚保留「一个工作项绑定多个版本会各计一次，跨版本合计不等于项目合计」。

### 3.5 下钻抽屉

桌面从右侧滑出，宽 900（`modal-layer.side`），保留左侧页面上下文；标题「阶段投入明细」，副标题「资金通 · 开发 · 45.5h / 69.5h（65%）」；筛选芯片「项目 / 版本」「阶段」「分类」可单独移除，也可全部清除；搜索框；表格：工作项 / 类型 / 分类 / 负责人 / 阶段工时 / 总实际。行点开工作项（原型为提示）。390 改为全屏抽屉 + 工作项卡（标题、版本 / 类型 / 分类 / 负责人、阶段工时与总实际），避免 560px 宽表格横向溢出。空态：原因 + 一个动作（如「该范围还没有需求类工作项」→「新建需求」）。

## 4. 文案

- 阶段名：产品 / 设计、开发、测试；副注：需求类工作项的计时（近似）、任务 / 缺陷 · 测试窗口外、测试窗口内（提测 → 测完）。
- 范围：全部工作项 / 本版本 / 当前筛选的 N 个版本。
- 口径（同现有汇总）：测试窗口内先归测试；剩余按类型；产品 / 设计是近似，不做摊派；自然日边界；史诗不计；预估按字段；条目不可相加。
- 空态：`还没有已结束的计时，产品 / 开发 / 测试拆分要等第一条计时产生。`
- 产品为 0：`暂无需求类工作项，产品 / 设计计 0，不做摊派。`

## 5. 令牌与断点

- 颜色：产品 `--plum`、开发 `--primary`、测试 `--palette-6`；0 值 `--text-3`；不改语义色。
- 尺寸：条 8px、圆角 `--r-pill`；卡片 `--r-lg`；表格数字右对齐 + `tabular-nums`。
- 1440：三卡一排、表全列；1100：卡片仍一排，表收「条目 / 偏差」；900：单列；390：卡片改为三行、阶段表只留「阶段 / 实际 / 占比 / 明细」，下钻全屏，触控区实现时补足 ≥44px。

## 6. 设计决策记录

| 决定 | 替代方案 | 代价 | 何时反悔 |
|---|---|---|---|
| 阶段放在独立面板，不改分类表列 | 分类表加三段六列 | 分类表不能直接按阶段切；但避免 16 列横向滚动 | 用户常问「哪个分类的开发最高」时，再加面板内「按分类」视图 |
| 版本行新增阶段列 | 只做页头汇总 | 行变宽，<1100 收起 | 版本行信息再增加时，改为点击展开行 |
| 版本详情去掉弹层阶段卡 | 两处都保留 | 少一个快捷入口；概况页更长 | 概况页需要折叠时，恢复弹层只读卡 |
| 跨版本表用三段替换窗口两列 | 三段 + 窗口四列并存 | 窗口口径不再一眼可见 | 财务/交付要求窗口口径常驻时，加列或视图切换 |
| 下钻用抽屉 | 跳工作项列表页 | 不能直接复制 URL | 需要分享筛选时，补 hash 深链 |

## 8. 原型覆盖与残留

- 已覆盖：1440 与 390 的项目页、版本列表、版本详情、跨版本表、下钻抽屉；产品为 0 的项目页与下钻空态；版本列表与跨版本在 390 的卡片化。
- 未覆盖：1100 / 900 断点、加载中与加载失败、无任何计时的整个项目、版本筛选后汇总重算、下钻深链分享。实现时按第 3、5 节补齐，不把原型当实现。
- 数据口径：演示库没有需求类工作项，真实产品段必为 0；正常场景中的产品工时是合成数据，原型右上角标注「原型示意 · 合成数据」，不冒充线上结果。
- 原型交互：筛选、记录发布、新建版本、打开工作项为提示反馈；下钻筛选与搜索可用；不改任何业务数据。
