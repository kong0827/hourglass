# 「我的工作 · 团队」项目维度原型说明

日期：2026-11-20　原型：[prototype.html](prototype.html)

把「团队」从「空间级只读看板」改成「按项目范围查看」：空间主 / 管理员看全部项目，项目负责人只看自己负责的项目。个人页签（待我处理 / 我发起的 / 我关注的）不变。

---

## 1. 谁能看到

| 角色 | 是否显示「团队」页签 | 能看到的项目 |
| --- | --- | --- |
| 空间主 owner / 管理员 admin | 显示 | 当前空间全部项目，可任意多选 |
| 项目负责人（`requirement.owner_user_id` = 我，且对项目可写） | 显示 | 只有自己负责的项目，默认全选 |
| 普通成员 member | 不显示 | — |
| 只读 viewer | 不显示 | — |
| 项目成员但非负责人 | 不显示 | — |

判定直接复用已有的 `ProjectAccessService.canManageProject(workspaceId, userId, projectId, ownerUserId)`（owner/admin 恒真；普通成员要求是负责人且可写）。不新增「项目管理员」角色。用户已确认：**项目管理人就是项目负责人**。

- 前端入口：`mine.js` 的 `canTeam()` 从「空间主 / 管理员」扩展为「空间主 / 管理员，或至少负责一个项目」。
- 后端兜底：团队相关接口由「空间成员」改为「空间主 / 管理员，或所选项目都是自己负责的项目」，越权项目 ID 一律裁剪后忽略；全部越权时 403。

## 2. 页面结构（与原型对应）

1. 结论条：`本周团队 · 完成率 57% · 计划 21 项` + 区间与更新时间。
2. 项目范围条：`我负责的 3 个项目` / 单项目 chips + 区间段（本周 / 本月 / 近 30 天）+ 起止日期。
3. 概览卡：完成率进度、完成 / 计划、已逾期、被阻塞，底部一行口径说明。
4. 待处理：待评审 / 待验收 / 待合并三块，下面补「最久等待」Top 3（项目 · 类型 · 标题 · 天数）。
5. 风险工作项：逾期与阻塞任务 Top 4，每条带项目标签、负责人、原因与天数。
6. 成员负载：按人合并计时，容量 = 每日容量 × 区间工作日，>100% 红、90–100% 橙。
7. 脚注：谁能看、区间口径、快照口径。

原型右上角有调试面板（角色 / 区间 / 正常·空·错误），URL 可直接预置：

```
?role=admin|pm&range=week|month|d30&state=data|empty|error&projects=pay,trade&clean=1&shot=1
```

`clean=1` 隐藏调试面板；`shot=1` 隐藏移动端固定底栏与 FAB，便于整页截图。

## 3. 指标口径

| 指标 | 口径 | 时间 | 范围 |
| --- | --- | --- | --- |
| 完成率 | 完成数 ÷ 计划数 | 区间 | 所选项目 |
| 完成 | `completedAt` 落在区间内 | 区间 | 所选项目 |
| 计划 | `completedAt` 或 `dueDate` 落在区间内的任务，按任务去重（现有 `periodStats`） | 区间 | 所选项目 |
| 已逾期 | 未完成、`processingRule != ended`、`dueDate < 今天` | 当前快照 | 所选项目 |
| 被阻塞 | 未完成且 `blocked = true` | 当前快照 | 所选项目 |
| 待评审 | `status = review` 的需求数（团队视角，不是「待我评审」） | 当前快照 | 所选项目 |
| 待验收 | 分支 `status = testing` | 当前快照 | 所选项目 |
| 待合并 | 分支 `status = merging` | 当前快照 | 所选项目 |
| 最久等待 | 上述三类待办按等待天数倒序取前 3（需求按进入评审时间，分支按进入 testing/merging 时间） | 当前快照 | 所选项目 |
| 风险工作项 | 逾期与阻塞任务，带项目标签 | 当前快照 | 所选项目 |
| 成员负载 | 区间内计时 ÷（成员每日容量 × 区间工作日数） | 区间 | 所选项目 |

要点：

- **区间类**（完成率、完成 / 计划、成员负载）随「本周 / 本月 / 近 30 天」变化；**快照类**（逾期、阻塞、待处理、风险、最久等待）不随区间变化。原型里两组数字同时出现，必须在界面上写清楚，否则容易被读成「换了区间风险也变了」。
- 多项目合并时：完成率按合计完成 ÷ 合计计划重新计算，不是各项目百分比求平均；成员负载按人去重后相加计时（一个人跨两个项目只出现一行）。
- 成员范围 = 所选项目内出现过的任务负责人并集；不是空间全部成员，因此 PM 看到的负载只覆盖自己项目上的人。
- 待评审沿用团队视角「全部待评审需求」，与个人页「待我评审」是两个队列：后者只看派给我或可写且未指派评审人的需求，数字不应互相对照。

## 4. 项目范围的计算

- 接口参数：`projectIds=pay,trade`（逗号分隔）。缺省 = 调用者可见且可管理的项目。
- 服务端先把 `projectIds` 与「可管理项目集合」求交：
  - owner/admin：可管理 = 空间全部项目；
  - 项目负责人：可管理 = `owner_user_id = 我` 且可写的项目。
- 过滤顺序：项目范围 → 可见范围（`project` 不可见仍隐藏）→ 区间 → 聚合。先项目后区间，避免先算全空间再剔除导致分母错误。
- 响应带回 `scope`：`{ projects: [{id, name, owned}], allSelected: bool, truncated: [ids] }`，前端 chips 与服务端实际生效范围同源，避免「页面上勾了 3 个、服务端只算了 2 个」。

## 5. 接口改动（实施清单）

现有端点（`MobileController`）：

| 端点 | 现在 | 改为 |
| --- | --- | --- |
| `GET /api/mobile/team-overview?from&to` | `requireMember`；空间全量；返回 role/health/pending/risks | 加 `projectIds`；权限改为 `requireTeamView`；health/pending/risks 按项目过滤；返回 `scope`；pending 增补「最久等待」Top 3 |
| `GET /api/mobile/workload?from&to` | `requireManager`；空间全量 | 加 `projectIds`；同一 `requireTeamView`；`ManagerService.workload` 支持项目过滤后再按人合并 |
| `GET /api/mobile/risks?type` | `requireManager`；空间全量 | 加 `projectIds`；同一 `requireTeamView`；按项目过滤 |

- `requireTeamView(workspaceId, userId, projectIds)`：owner/admin 直接通过；否则逐个项目 `canManageProject`，全部不通过时 4030；部分不通过时裁剪并在 `scope.truncated` 返回（不泄露项目名）。
- 「最久等待」需要后端补一份「每类最早 3 条」的明细；推荐并入 `team-overview`（本来就要查需求与分支），避免新增请求。
- 前端项目列表已有缓存（`/api/projects`，含 `ownerUserId`），chips 直接用「我负责的项目」过滤，不必新增接口。

## 6. 交互与状态

- 多选：点单项目加入选择，点「我负责的 N 个项目」回到全选；PM 至少保留一个项目，取消最后一个自动回到全选。
- 切换区间保留项目选择；切换角色/空间重置为全选。
- 加载中保持上一次数字并显示轻提示，不整块清空，避免切换 chips 时页面跳动。
- 空态：保留项目范围条可继续切换，隐藏结论条（避免「完成率 57%」和「还没有数据」同时出现），正文说明数据在哪一步产生。
- 错态：同样保留范围条；只影响团队页签，个人页签不受影响；提供重试。
- 权限变化：负责人被移除时下次请求 `scope` 不再包含该项目，chips 自动对齐；全部失去时退回空态/403 提示，不残留上一个项目的数字。

## 7. 移动端

- 布局单列；chips 横向滚动，区间段全宽 40px 高；起止日期居中放在区间段下方。
- 成员负载单列；底栏与 FAB 沿用现有壳。
- 390 宽实测无横向滚动（截图 `mobile-pm-390.png`、`mobile-pm-full-390.png`）。

## 8. 验收点

1. 管理员看到全部 5 个项目，项目负责人只看到自己 3 个；页签数字与个人页签不冲突。
2. 任选单项目，hero、待处理、风险、成员负载四块同步变化，且数字等于该项目单独打开时的数字。
3. 多选 2 个项目时，完成率 = 合计完成 ÷ 合计计划；同一成员跨项目只出现一行。
4. 构造越权 `projectIds`（选一个别人负责的项目），服务端裁剪且不泄露名称；只传越权项目时 403。
5. 切换本周 / 本月 / 近 30 天：完成率与负载变化，逾期 / 阻塞 / 待处理不变。
6. 空态与错态下仍可切换项目与区间；结论条不显示。
7. 390 宽无横向滚动，底栏与 FAB 不遮挡最后一行内容。
8. 普通成员直接请求团队接口返回 403；页面上看不到团队页签。

## 9. 需要你定的三点

1. **待评审口径**：团队视角看「全部待评审需求」（当前原型），还是只看「我可评审」（与个人页一致）？前者适合负责人治理，后者适合个人待办。建议团队保留前者，并在卡片上写「全部待评审」。
2. **最久等待**：本期是否要后端补 Top 3 明细？不做的话，待处理卡片只留三个数字，卡片会偏空（原型已补齐）。
3. **成员负载下钻**：项目负责人点成员后，是只看本项目下的计时明细（推荐、权限内），还是不给下钻（当前原型只读）？
