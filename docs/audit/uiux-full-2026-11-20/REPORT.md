# 沙漏 · 全站 UI/UX 评审

日期：2026-11-20
范围：30 个路由 + 测试域 / 报表域 6 个子页签；1440 / 1280 桌面，390 手机；浅色 / 暗色
证据：168 张截图（`shots/` 31 张关键图 + 4 份 metrics JSON）、代码核查、样式漂移扫描
角色：管理员（admin，空间主视角）
环境：本地 8081 静态预览 + 8080 后端（旧 jar，缺 `/api/my-work/test-plans`）

---

## 1. 结论先行

- **总体判断**：**局部达标**。视觉语言（浅色冷静、卡片化、六类状态色、暗色主题）已经统一，空态/错误态大多可读，桌面端主路径成立；短板集中在**移动端降级不完整**、**容器与主操作层级失控**、**单点失败拖垮整页**三类结构问题，而非基础交互。
- **最硬的 3 条证据**：
  1. **移动端测试域少 4 个入口**：390 下 `#tcModeSeg` 为 `display:none`（`views-analysis-branches.css:1325`），`.subnav` 被隐藏（`mobile.css:88`），移动端只剩 `概览 / 工作项 / 测试用例 / 分支`（`index.html:1829-1834`）。缺陷、测试计划、覆盖矩阵、测试报告在手机上不可达；从直链进入缺陷页时，高亮页签仍是「测试用例」（`shots/390-defects.png`）。
  2. **一个接口失败，整页不可用**：`/api/my-work/test-plans` 404 时，`Promise.all`（`mine.js:487`）拒绝，整页替换为「我的工作 加载失败」，30 项待处理不可见；而文案仍写「已保留上次成功加载的数据」（`mine.js:1080`、`shots/1440-mine-error.png`）。
  3. **风险列放完成态**：项目分类表的「风险」列在无风险且全部完成时输出绿色「已完成」（`project.js:908`），与「—」混排；同页还有「新建」「+ 添加分类」两个实心主按钮（`shots/1440-project.png`、`1280-project.png`）。
- **主要短板**：移动端只做了「缩窄」没有「重排」；主操作/批量/危险动作都用了主按钮样式；筛选器没有预算（缺陷页 9 个、成员负载 8 行）；同一功能保留了两处入口（设置、消息、恢复默认）；10–11px 小字使用面过大。
- **无 P0 破损**：全站 168 次采集无横向溢出、无 console 异常；桌面主路径可完成任务。

## 2. 做得好的地方

- **状态色有单一来源**：`format.js:5-12` 定义 待处理灰 / 进行中蓝 / 待测试紫 / 测试中粉 / 已完成绿，与六类状态色规则一致；全站徽标颜色不漂移。
- **暗色主题覆盖到位**：`tokens.css:177-192` 覆盖外壳、卡片、文本；1440 与 390 暗色实测无白色泄漏，次要文本对比约 4.7:1（`shots/1440-dark-project.png`、`390-dark-testcases.png`、`390-dark-settings.png`）。
- **空态与错误态带下一步**：已取消工作项、文档空目录、发布工作台空态、我的工作错误态都给了说明与操作按钮（`shots/1440-release-empty.png`、`390-docs.png`）。
- **响应式外壳成立**：1280 自动收为图标侧栏（`shots/1280-project.png`），390 用底部 Tab（52px）+ 抽屉菜单，列表页在 390 无横向溢出（`shots/390-workitems.png`）。
- **统计口径敢写清楚**：测试报告同时给出「通过率 按本轮 100%」与「执行统计 按全部执行流水 50%」，并注明分母算法；这不是矛盾，是可核对的口径（`shots/1440-test-report.png`）。
- **识别优于回忆的局部实现**：树形视图显示「已加载 100 / 共 429 项 · 24 个分组」并保留「隐藏已完成」开关，分组头给出项目/版本双层级（1440 树形视图采集，metrics 截断 0）。

## 4. 跨页共性问题

1. **主操作 / 批量 / 危险动作都穿主按钮外衣**：项目、版本、逾期、投入结构四处。工具栏动作本应中性，批量催办尤其应降级。建议建立「一页一主按钮」检查项，工具栏按钮默认 `ghost`。
2. **筛选器没有预算**：缺陷 9 个、工作项 6 个、成员负载 8 行、文档范围混入状态。桌面两行、手机整屏。建议统一「搜索 + 3 个常用筛选 + 更多」四段式，移动端折叠为抽屉。
3. **移动端是缩窄而不是重排**：测试域缺 4 个入口、甘特挤压、筛选占首屏、空态仍写左右分栏、设置操作条贴边。建议以 390 为准重排 5 个高频页（工作项列表、缺陷、测试报告、甘特、设置），而不是只做 `display:none`。
4. **同一功能保留两处入口**：设置双导航、消息双类型过滤、缺陷双「恢复默认」。建议一条规则：同一维度只保留一处可见控件，另一处删除或改为只显示当前值。
5. **小字与令牌漂移叠加**：10–11px 文本在 portfolio/projects/report 均值 60+ 处，同时 font-size 硬编码 2182 处。建议先收敛字号阶梯（12/13/14/16/20/28），再谈密度。

## 5. 关键体验断点

1. **测试同学在手机上想看缺陷**：进入「测试」只看到用例；域内页签没有缺陷，直链进入后页签还高亮「测试用例」。他会以为「缺陷没同步」，实际是入口缺失。影响整个测试域移动可用性（IA-1）。
2. **早上打开「我的工作」**：一个测试计划接口失败，30 项待处理全部消失，文案却说已保留数据。他会以为数据丢了，去重试、去别处找。影响每日第一屏的信任（FB-1）。
3. **负责人扫月历排期**：同一天 5 条事件全显示「外接客户季...」，必须逐条点开才能知道是哪条。影响排期决策效率（VIS-5）。
4. **管理员看项目健康**：分类表「风险」列对已完成分类显示「已完成」，对真正逾期显示「—」，风险信号被完成态稀释（CON-1）。

## 7. 需要确认的决策

1. **移动端测试域范围**：现状 4 个子页。选项 A（推荐）：补「缺陷 + 测试报告」两个高频入口，计划/覆盖留桌面，成本 1 天；选项 B：5 个全补，页签溢出需横向滚动，成本 2 天；选项 C：只保留用例，其余明确「桌面查看」，成本最低但移动端测试闭环不成立。
2. **设置导航去留**：推荐删全局二级（`index.html:274`），保留页内 tab——页内 tab 可深链、可滚动、可放角色提示；删除全局二级的代价是侧栏一致性略降（其他模块有二级）。
3. **甘特移动端**：推荐明确「桌面查看」并保留只读排期列表，不在 390 复刻甘特；若要复刻，需接受横向滚动 + 标签折叠的复杂度（约 3–5 天）。
4. **风险列定义**：推荐「风险」只放逾期/阻塞，完成态回进度；若业务确实想在一列看「健康度」，应改名为「健康」并给出三档（正常/风险/已完成），而不是混排。
