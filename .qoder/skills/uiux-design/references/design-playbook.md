# 设计执行手册

本文件是 `uiux-design` 的执行层。原则判断见 `uiux-review`，这里只写「怎么把需求推成一页可实现的界面」。顺序不要跳：简报 → 建模 → IA → 骨架 → 控件 → 文案 → 视觉 → 状态 → 响应式 → 验收。

---

## 1. 设计简报

先写六项，再动手。缺「谁 / 任务 / 决策」任意一项必须先问；缺「成功标准 / 范围 / 约束」可以给默认值，但要在规格里标「假设」。

```markdown
- 角色：<管理员 / 负责人 / 成员 / 只读>，使用频次 <每天 / 每周 / 偶尔>
- 任务：<动词开头，一句话>
- 决策：这一屏帮用户判断 <什么>
- 成功标准：<3 条以内，可验证>
- 范围：<页面 / 子页 / 弹框 / 抽屉>，断点 <1440 / 390>；不做什么：<…>
- 约束：现有组件 <…>、接口字段 <…>、权限 <…>、数据量级 <…>
```

判断简报是否成立：

- 任务写不出动词（「让他更好管理」）→ 需求还没想清，先拆任务。
- 决策写不出（「展示所有数据」）→ 这一屏应做成报表或下钻页。
- 成功标准只有「好看」→ 改成「3 步内完成 X」「空/错/只读三态齐全」。

## 2. 对象与状态建模

**实体与字段**

先列这个页面出现哪些对象、每个对象哪些字段、字段从哪来。字段分四类：标识（名称/编号）、归属（项目/分类/版本）、责任与时间（负责人/起止/优先级）、关系与描述（关联/附件/说明）。

**主状态**

- 3–5 个，互斥，终局明确。
- 只描述对象自身的生命周期；过程位置归执行对象，发布/交付归记录。
- 写一张表：`状态 | 含义 | 进入条件 | 可执行动作 | 颜色`。

**派生状态**

发布、测试进度、审核结果等外部事实，用只读胶囊/徽标展示，不参与主状态、不参与拖拽与筛选主口径。派生状态必须注明来源与更新时间。

**权限矩阵**

`角色 × 动作`，每格三选一：可见可用 / 可见禁用（写原因）/ 不可见。禁用原因要能落到一句话，例如「已发布版本不可改排期」。

**口径**

同一指标只定义一次：分子、分母、统计范围（是否含已取消/未执行）、刷新时机。页面显示分母，或至少在 `?` 里给一句。

## 3. IA 与入口

五个问题定入口：

1. 用户从哪来？（导航、项目内、通知、深链、搜索结果）
2. 到这一页要几层？（目标 ≤2：列表 → 详情；详情内的 Tab 不算新层级）
3. 同级还有哪些视图？能否用页内 Tab/分段收敛，而不是加导航项？
4. 返回去哪？用真实历史还是父级？面包屑写到哪个对象？
5. 同一任务是否已有入口？有就复用，不新增菜单。

**角色分叉**

同一数据源，不同默认范围与默认视图：

| 角色 | 默认首屏 | 关注点 |
|---|---|---|
| 管理员 | 配置与异常 | 权限、成员、失败项 |
| 负责人/管理者 | 结果与偏差 | 版本进度、阻塞、负载 |
| 成员/执行者 | 我的任务 | 今天到期、下一步、阻塞原因 |
| 只读/查看者 | 结论与导出 | 状态、范围、能否导出 |

角色可切换，口径不能变：切的是视图与筛选，不是数据定义。

**命名**

入口用用户词，不用内部模块名。一个概念全站一个词；「版本/发布/计划/记录」这类近义词先定表，再写进界面。

## 4. 页面骨架与密度

默认四段：

```text
[面包屑]
[标题]                                    [唯一主操作]
[范围｜筛选｜显示｜操作]        （≤1 行，每段 ≤3 控件）
[统计 / 结论条]                （可选，一行，只出现一次）
[内容：列表 / 看板 / 表单 / 图表]
[辅助：口径 ? / 更新时间]       （不占正文）
```

**首屏预算**

- 工具条不超过 2 行；超出就收进筛选面板或「更多」。
- 1440×900 下，第一条数据必须在折叠线以上。
- 统计、说明、时间放在对象附近，不单独占一块。
- 页面只允许一个 H1；区块标题降一级。

**密度**

- 表格默认中等密度，行高 40–44px；提供紧凑/宽松切换时，默认值固定。
- 卡片内边距 12–16px，组间距 16–24px，组内 8–12px。
- 说明文字最多一行；口径进 `?`、空态或确认框。

## 5. 控件选型矩阵

**新建/编辑容器**

| 场景 | 选择 | 理由 |
|---|---|---|
| ≤3 个字段、无上下文 | 弹窗 | 快，不打断 |
| 4–10 个字段、需看背景 | 右侧抽屉 | 保留列表上下文 |
| >10 个字段、多步、需对照 | 全页 | 可分区、可草稿、可深链 |
| 单字段修改 | 行内编辑 | 一步完成 |

选择规则：能在抽屉完成就不要全页；能在行内完成就不要抽屉；确认类才用弹窗。

**浏览形态**

| 需要 | 形态 |
|---|---|
| 比较多个字段、批量操作 | 表格 |
| 看流转与阻塞 | 看板 |
| 看时间与依赖 | 甘特 |
| 看层级与归属 | 树 |
| 看单对象全貌 | 详情页 |
| 移动端首屏 | 卡片列表 |

同一数据允许两种视图时，视图切换用分段/Tab，默认视图按角色与设备定，且记住上次选择。

**切换控件**

- 2–4 个稳定选项：分段控件。
- 5–7 个：Tab。
- >7 个或低频：下拉 + 搜索。
- 视图偏好（密度/字段/分组）：收进「显示」，不占主工具条。

**筛选**

常驻只留 2–3 个高频条件（状态、负责人、时间），其余进筛选面板/抽屉；已选条件 reset 后常驻可见，显示条数与范围。

**批量**

选择后出现浮动操作条：`已选 N 项 · 范围：当前筛选`，主操作与危险操作分色分栏；默认不选结果值。

## 6. 表单设计

**顺序**

身份（名称/类型）→ 归属（项目/分类/版本）→ 责任（负责人/优先级）→ 时间（起止/截止）→ 关系（关联/依赖/里程碑）→ 描述与附件。

**布局**

- 单列，标签在左或在上，全页统一一种。
- 分组用区块标题，组内不超过 7 个字段。
- 宽字段（描述、备注）占整行；短字段可两列，但不要混排到破坏扫描。
- 底部固定操作条：取消（次）｜保存（唯一主操作）。

**规则**

- 必填标 `*` 并在提交前汇总；选填不写「选填」除非容易被误解。
- 依赖用显隐，不用置灰堆叠；隐藏字段的值要清空或说明保留策略。
- 校验时机：失焦校验格式，提交时校验必填并聚焦第一处错误。
- 错误文案：什么错了 + 怎么改，给例子；不用「输入有误」。
- 关闭前脏检查；长表单给本地草稿与恢复。
- 提交中禁用按钮并显示状态；写操作幂等。

## 7. 视觉与令牌

**取令牌，不发明**

颜色、字号、间距、圆角、阴影、层级（z-index）一律引用现有令牌。缺令牌时先在规格里提议变量名与值，评审通过后再进 tokens。

**默认风格**

白/极浅灰底；单一主色承担「当前/主操作」；语义色只用于状态；卡片化、细边框、轻阴影、统一圆角；留白充足。拒绝重渐变、发光、拟态、装饰性大色块、3D 图表、装饰性动画。

**层级**

用字号/字重/颜色三层建立主次：标题、正文、辅助。不要靠加更多颜色做层级。数字列右对齐 + `tabular-nums`。

**占比**

功能色（红绿黄橙）占屏约 ≤15%；一屏一个强调色；0 值中性。

**图标**

统一线性/面性一种；纯图标只用于高共识动作（关闭、搜索、更多），其余配文字或 tooltip；尺寸与位置全站一致。

## 8. 状态规格

每个页面/弹框逐项写「长什么样 + 能做什么」：

| 状态 | 规格要点 |
|---|---|
| 首次加载 | 骨架或进度；超过 300ms 必须可见；不得永久骨架 |
| 刷新 | 保留旧数据 + 顶部细条/局部 pending；不闪空 |
| 空数据 | 图标 + 一句原因 + 一个动作；区分「本来没有」与「筛选没有」 |
| 筛选无结果 | 保留筛选条，给清空入口与命中数 |
| 错误 | 原因 + 重试；保留旧数据；不整页替换；不伪装空态 |
| 部分失败 | 成功的保留，失败的逐条列出并可重试 |
| 只读/无权限 | 横幅或禁用 + 原因；不靠隐藏；导出/分享按权限禁用 |
| 提交中 | 按钮禁用 + 进行中文案；防重复提交 |
| 冲突 | 二选一：重新加载 / 用我的覆盖 |
| 长文本 | 截断 + tooltip；关键列不截断；正文允许换行 |
| 大数据 | 增量加载 + 计数；滚动位置不丢 |
| 窄屏 | 重排而非缩放；底部安全区；浮层不叠放 |

设计评审时至少截：默认、空、错误。实现前补齐只读与窄屏。

---

## 9. 文案

- **按钮用动词**：保存、创建、发布、删除；「确定」只用于确认框。
- **空态**：为什么空 + 下一步；不写「暂无数据」了事。
- **错误**：原因 + 动作 + 重试；技术错误码放到次要位置。
- **确认框**：对象 + 后果 + 可否撤销；不可逆时要求输入名称。
- **权限**：说清「谁能改」，不只写「无权限」。
- **单位与日期**：单位与数字分离；当年 `MM-DD`、跨年 `YYYY-MM-DD`、时间 24 小时制；悬停给完整时间。
- **不承诺系统做不到的事**：文案与实现一致，「自动保存」就真的自动保存。

---

## 10. 响应式

| 断点 | 行为 |
|---|---|
| ≥1200 | 完整布局，表格全列 |
| 1100 | 次要列进「显示」；工具条收「更多」 |
| 900 | 两列转单列；侧栏收窄或抽屉化 |
| ≤430 | 表格转卡片；筛选进底部抽屉；行操作进「更多」；触控目标 ≥44px；底部留安全区 |

移动端不是缩小的桌面：首屏先给结论与第一条内容，控件不超过一行；浮动按钮只留一个，且不遮挡列表。

---

## 11. 可访问性

- 所有交互可聚焦，`:focus-visible` 有明确焦点环；不用 `outline:none` 了事。
- Tab 顺序与视觉顺序一致；Esc 关闭浮层；弹窗焦点陷阱，关闭后焦点回原位。
- 图标按钮有 `aria-label`；状态不只靠颜色，配文字或图标。
- 正文对比度 ≥4.5:1；禁用态也要能读。
- 表格有表头关联；图表提供数据表或文字摘要。

---

## 12. 设计验收清单

- [ ] 简报六项齐全；假设已标注。
- [ ] 主状态 3–5 个且互斥；派生状态只读。
- [ ] 每屏一个主操作、一个 H1；工具条四段式。
- [ ] 首屏第一条数据在折叠线以上；工具条 ≤2 行。
- [ ] 空、加载、错误、只读、窄屏五态有设计。
- [ ] 筛选无结果与空数据文案不同。
- [ ] 危险操作分离；批量默认安全且有影响预览。
- [ ] 表单单列、单保存、失焦校验、脏检查。
- [ ] 所有颜色/字号/间距来自令牌；无硬编码新增值。
- [ ] 日期、数字、单位格式统一。
- [ ] 键盘可走完主路径；触控目标 ≥44px。
- [ ] 页面规格与原型一致；未覆盖项与假设已列出。
