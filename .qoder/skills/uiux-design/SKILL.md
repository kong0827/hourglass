# UI/UX 设计

## 概述

设计不是画得好看，而是把需求变成一组可验证的界面决定：谁用、要完成什么、看哪几个结论、能做哪些动作、出错怎么办。产出物固定为三件：页面规格（结构、字段、状态、权限）、1440/390 原型、验收清单。评审已有页面用 `uiux-review`，本 skill 负责从需求向前推。

## 一句话模型

先定对象与决策，再定布局；先定状态，再定样式；先用现有令牌与组件，再谈新视觉。任何一步跳过，原型都会在「看起来像」和「能用」之间漏东西。

## 工作流

**0. 设计简报。** 必须回答六项，缺关键项先问，最多问 3 个问题；其余假设写进规格，不默默猜。

| 项 | 要写清 |
|---|---|
| 谁 | 角色、频次、熟练度（管理员 / 负责人 / 成员 / 只读） |
| 任务 | 用户要完成的动作，动词开头 |
| 决策 | 这一屏帮用户判断什么；答不出就说明该页只是报表 |
| 成功标准 | 3 条以内，可验证（几步完成、哪些状态必须成立） |
| 范围 | 页面/子页/弹框/抽屉/断点；明确不做什么 |
| 约束 | 现有组件、接口字段、权限、数据量级、品牌与令牌 |

**1. 对象与状态建模。** 先列实体与字段，再定状态。主状态 3–5 个且互斥；派生事实（发布、测试进度、审核）只读展示，不进入主状态。同步列权限矩阵：角色 × 动作 × 可见/可写/禁用原因。

**2. IA 与入口。** 回答入口从哪来、用户在几层内能到达、返回路径是什么。首页按角色分叉；同任务一个入口；层级不超过「列表 → 详情 → 子页」两级；深链可用，面包屑写到当前对象。

**3. 页面骨架与控件选型。** 先画区块顺序，再选控件。骨架默认四段：页头（面包屑 + 标题 + 主操作）、工具条（范围｜筛选｜显示｜操作）、内容、辅助（统计、口径、更新时间）。控件选择见 `references/design-playbook.md` 的选型矩阵。

**4. 内容与文案。** 先写真实字段名、按钮动词、空态与错误句，再画控件。禁止 lorem ipsum；数据量级按真实上限设计（如 400 行、20 列、8 个状态）。

**5. 视觉与令牌。** 颜色、字号、间距、圆角、阴影一律取项目令牌；没有令牌时先提议令牌值再使用。默认白/极浅灰底、单一主色、六类语义色、功能色占屏 ≤15%，拒绝重渐变、发光、拟态、3D 与装饰性动画。

**6. 状态与反馈。** 每个页面/弹框/空态都要有：首载、空、筛选无结果、错误、部分失败、只读、提交中、冲突、长文本、大数据、窄屏。设计时逐项写「长什么样 + 能做什么」，不是只说「要有」。

**7. 响应式。** 1440 为主，1100 收次要列，900 转单列，390 转卡片 + 底部抽屉筛选。不是把桌面缩小：表格→卡片、工具条→筛选面板、行操作→更多菜单。

**8. 原型与交付。** 固定画布 1440/390，只做目标范围；至少截默认、空、错误三态；写页面规格（模板见 `references/design-spec-template.md`）；交付时列出未覆盖项与假设。

## 硬性约束

设计阶段就按这些定，别等评审再改：

1. **每屏一个主操作**，固定在标题行右端；每页一个 H1；视图切换、分组、导出用中性样式。
2. **工具条四段式**：范围｜筛选｜显示｜操作；每段常驻 ≤3 个控件，其余进「更多」。
3. **语义色六类**：蓝=当前，绿=完成/健康，红=逾期/失败/危险，橙=阻塞/风险，紫=等待/流转，灰=中性。颜色必须配文字，0 值中性。
4. **状态徽标两种形态**：淡底深字=只读状态；实心=当前选中。可操作加 caret。
5. **统计只出现一次**，放在对象旁；比率给分母或 tooltip；不能下钻就不做成可点。
6. **空态=原因+一个动作**；错误=原因+重试；失败不得伪装成空态或健康态。
7. **表单单列、分区、一个保存**；字段类型匹配数据，必填/选填显式，依赖显隐，失焦校验，关闭前脏检查。
8. **批量默认安全值**（不默认通过/成功），执行前显示影响数量与范围，结果逐项可见。
9. **危险操作分离**：删除/清空远离编辑，二次确认写清后果，可逆优先「乐观更新 + 撤销」。
10. **权限**：永远没有的隐藏；当前不可用的禁用并写原因；只读给横幅，导出/分享按权限禁用。
11. **识别优于回忆**：默认值、最近使用、已选条件常驻；切换视图保留筛选、排序、滚动与列偏好。
12. **数据是活的**：看板/甘特/统计显示更新时间；状态变更通知下一环节，关键操作留「谁、何时、前后值」。
13. **表单与规模**：重复配置给批量、模板、只看例外；扩展靠配置，不靠重做页面。
14. **日期与数字统一**：数字右对齐 + `tabular-nums`；单位与数字分离；同一场景一种格式。
15. **可访问性**：焦点可见、Esc 关闭、弹窗焦点陷阱、图标按钮有标签；触屏目标 ≥44px。
16. **原型不造数据**：用真实量级与真实文案；合成内容必须标注，不能冒充实现。

## 设计决策记录

每个非显然的选择写一行：`决定 | 替代方案 | 代价 | 何时反悔`。典型需要记录：表格还是看板、抽屉还是全页、默认视图、主按钮位置、状态拆分方式、批量默认值。评审与实现都以此为准，避免口头约定。

## 交付契约

交付给实现方的页面规格至少包含：目标与成功标准、角色与权限、对象与字段、主/派生状态、入口与层级、区块顺序（含空/错/只读）、组件与交互、文案、令牌、断点行为、验收清单。

原型命名：`<页面>-<状态>-<视口>-<v1|v2>.png`，例如 `versions-empty-1440-v1.png`。

## 与评审的关系

设计完成后按 `uiux-review` 的六层透镜自审一遍，再交给独立评审。不要在设计阶段复制评审流程；本 skill 只保证「设计时就把问题挡掉」。
