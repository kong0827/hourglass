# 原型先行与实现对照

结构类 UI 改动的默认闭环：

`定范围 → 截当前态 → 出原型并确认 → 实施 → 对照原型逐项审计 → 修偏差 → 汇报与留痕`

跳过任何一步，都会在「看起来改完了」和「真的可用」之间留下差距。

---

## 1. 定范围

- 明确改哪些页面/组件，不改哪些。
- 明确是「视觉微调」「结构调整」还是「交互语义变化」；三者不要混在一批。
- 明确目标视口：桌面 1440、移动 390；涉及布局时补 900/1100。
- 明确成功标准：哪几条用户成本被消除，哪几个状态必须成立。

---

## 2. 截当前态

先截「改之前」，否则事后无法证明改了什么。

- 用真实登录、真实数据；演示数据要标注来源。
- 桌面 1440 全屏 + 关键区域局部放大；移动 390 全屏。
- 截默认态；如问题只在筛选后/空态/错误态出现，也一并截。
- 记录当前颜色、字号、间距的运行时值，不要只凭截图目测。

命名约定：`<页面>-<状态>-<视口>-<before|after>.png`，例如 `projects-table-group-row-1440-before.png`。

---

## 3. 出原型

**保真度选择**

- 只改 CSS/布局 → 在真实页面上注入样式覆盖，截 before/after；最快且最接近实现。
- 需要改结构 → 固定画布 HTML 原型（1440 宽 / 390 宽），只做目标区域，不追求全站可点。
- 需要多方案 → 2–3 个候选并排，标明推荐、代价、适用条件。

**原型必须包含**

- 真实文案与真实数据量级，不用 lorem ipsum。
- 设计令牌值（颜色、字号、间距），而不是凭感觉。
- 关键状态：默认、空、加载、错误、只读、窄屏。
- 前后对照图；只给「改后」无法判断收益。

**原型不是产品代码**

- 未获批准前不改产品代码。
- 注入式原型要说明「仅运行时覆盖」。
- 固定画布原型要说明「不可直接当实现」。

---

## 4. 批准与实施

- 用户确认方向后再动手；有多个方案时等选择，不自行拍板。
- 先改令牌/共用组件，再改单页；避免每页各写一套。
- 不做未批准的范围扩张；发现同类问题先列清单，等确认。
- 改动跨文件时记录清单，便于审计与提交。

---

## 5. 对照审计

按原型逐项核对，不要只看主路径：

| 维度 | 核对内容 |
|---|---|
| 布局 | 区块顺序、宽度、断点、堆叠、是否溢出 |
| 层级 | 标题/正文/辅助字号与字重、主次按钮 |
| 间距 | 分组间距、卡内边距、行高 |
| 颜色 | 主色、语义色、分组带、hover/focus/disabled |
| 文案 | 标签、空态、按钮、提示、单位、标点 |
| 组件 | 徽标形态、状态点、图标尺寸与位置 |
| 状态 | 空/加载/错误/只读/长文本/大数据 |
| 交互 | 点击、键盘、焦点、关闭、撤销、重试 |
| 响应式 | 1440/1100/900/390，横向滚动，底部遮挡 |

发现偏差：

1. 先判断是「实现错」还是「原型本身没考虑」。
2. 实现错 → 直接修，重截。
3. 原型没考虑 → 说明取舍，必要时补原型再修。
4. 无法对齐 → 标注「有意保留/缺陷/未覆盖」，不要静默略过。

---

## 6. 汇报与留痕

汇报至少包含：

- 改了什么（文件/模块）。
- 验证了什么（视口、状态、角色、断言数）。
- 没做什么、为什么。
- 已知残留（具体到元素/场景）。
- 未提交/未推送/未部署状态。

不要用「全部完成」「没有问题」替代证据。没有验证的部分就写「未验证」。

---

## 7. 截图与环境的常见坑

- **Service Worker 缓存**：改了前端但截图仍旧版，先确认缓存版本/绕过 SW。
- **隐藏面板**：未激活的 Tab/抽屉元素 `getBoundingClientRect()` 为 0，先切到可见再测。
- **视口高度**：无头浏览器可视区常比窗口矮，底部会多出空白或截断；按内容高度截图。
- **合成数据**：临时插入的 DOM/接口 mock 要标注「合成」，测试后清理。
- **多会话并发**：同仓库可能有他人未提交改动，提交时只带本批文件。
- **旧截图残留**：改完后覆盖同名截图，避免报告引用旧图。
- **演示数据污染**：临时空间/账号/附件要删除并核对数据库无残留。

---

## 8. 失败模式

- 原型只做入口/摘要，却宣称功能没少。
- 用户否定一版后整体回退，而不是保留被认可的视觉语言再叠加新诉求。
- 只截桌面，移动端靠「应该没问题」。
- 只测主路径，不测空/错/只读/长文本。
- 审计时只看「有没有这个元素」，不看位置、层级、文案、状态。
- 把「代码已改」当成「体验已改」。
- 报告只写成功项，不写残留与边界。
