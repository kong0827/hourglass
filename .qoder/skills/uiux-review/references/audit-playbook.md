# 审计手册

本文件是执行层：如何准备、取证、逐页审、跨页审、按角色走查、定级和验证。原则定义见 `principles.md`。

---

## 1. 准备

先建清单，避免「看了一部分就说全站」。

**页面清单**

- 一级视图、子视图、Tab、抽屉、全屏弹层、二级详情页。
- 弹框：新建/编辑/确认/批量/导入导出/分享。
- 特殊页：登录、空空间、无权限、404/失效链接、分享页。
- 移动端：主视图 + 底部 Tab + 筛选面板 + 浮层。

**代码与设计清单**

- 设计令牌文件（颜色、字号、间距、圆角、阴影、断点）。
- 路由与导航配置、权限判断、菜单定义。
- 共用组件：页头、工具栏、表格、卡片、徽标、空态、错误态、toast、弹窗、抽屉。
- 状态映射：`STATUS_META` 或等价文件；找出内联映射。

**素材清单**

- 桌面 1440、移动 390 截图（真实登录、真实数据）。
- 需要时补 900/1100 断点、深色模式、长文本、大数据量、只读角色。
- 当前线上/本地版本、账号、空间、数据来源，写进报告边界。

## 2. 取证标准

每条结论至少有一种硬证据：

- 截图（标注页面、视口、状态）。
- 运行时取色/尺寸（计算样式、像素取样、元素 `getBoundingClientRect`）。
- 代码位置（`file:line`）。
- 计数（「同屏 2 处共 187 条」「13 个控件同一行」）。
- 接口结果或控制台错误。

禁止：

- 只凭记忆说「某页也有」。
- 把目测像素写成精确值；用「约 / ±2px」。
- 把合成状态说成真实状态。
- 没打开页面就评价交互与响应式。

## 3. 单页检查（每页 16 问）

1. **定位**：我在哪？空间/项目/对象/作用域是否可见？
2. **主任务**：这一页最重要的一件事是什么？主操作是否唯一、显眼、在固定位置？
3. **层级**：标题、说明、工具栏、内容、辅助信息是否一眼分层？
4. **密度**：首屏是否被控件占满？内容是否被压到折叠线以下？
5. **分组**：一行是否混了多种语义？相关元素是否靠近？
6. **对齐**：卡内正文与标题、左右卡顶边、数字列、工具栏锚点是否齐？
7. **对比**：是否多个实心主按钮？0 值是否被强调？禁用/可用是否分得开？
8. **重复**：统计是否重复？同一功能是否多形态？同一图标是否漂移？
9. **状态**：加载、空、错误、只读、已完成、筛选无结果是否都有交代？
10. **反馈**：点击、保存、删除、批量、导出是否都有即时与结果反馈？
11. **恢复**：误操作能否撤销？未保存能否恢复？失败能否重试？批量默认值是否安全？
12. **边界**：长文本、大数据量、窄屏、深色、键盘是否成立？
13. **决策**：这个组件能触发什么决定？同角色是否看到合适的信息层？
14. **诊断**：看板/列表是否显示任务卡在哪一环？阻塞能否一眼定位到人，而不只是看到完成数？
15. **搜索**：能否用一次搜索在 3 秒内找到对象？支持模糊匹配、组合条件（项目+状态+负责人）与最近访问？
16. **新鲜度**：数据上次更新是什么时候？状态变更后看板/甘特/统计是否同步？操作是否有留痕？

输出时不要 16 条都写。只写有问题的，按「证据 → 成本 → 改法」组织。

## 4. 跨页检查（一致性站点）

先列「同类站点」，再对照。至少覆盖：

| 站点 | 对照项 |
|---|---|
| 页头 | 标题层级、副标题、面包屑、主操作位置 |
| 工具栏 | 段数、控件顺序、更多菜单、置灰策略 |
| 搜索 | 全局/页内、作用域、占位文案、快捷键 |
| 视图切换 | 位置、形态（Tab/分段/下拉）、是否记忆 |
| 筛选 | 位置、空值文案、计数、清空/恢复语义、保存视图 |
| 表格 | 列头、行高、数字对齐、空列、行操作 |
| 卡片 | 信息顺序、标签、状态、下一步、删除入口 |
| 状态 | 词表、颜色、徽标形态、可操作性 |
| 空态/错误 | 组件、图标、文案、下一步、重试 |
| 日期/数字 | 格式、单位、对齐、等宽 |
| 弹窗/抽屉 | 宽度、关闭方式、脏检查、焦点、按钮顺序 |
| 深页返回 | 返回位置、面包屑、历史语义、深链 |

跨页结论要区分：

- **真不一致**：同一功能不同形态/位置/词。
- **有理由的差异**：如工作项六视图用 Tab，因为数量多；写明理由，不算问题。
- **待确认**：需要产品决策的差异。

## 5. 角色走查

同一页面至少从四类角色看：

- **管理员/空间主**：能否配置？入口是否存在？权限说明是否准确？
- **管理者**：能否看到版本计划、分配、负载、进度、阻塞？下钻是否到位？
- **成员/执行者**：能否快速看到自己的任务、优先级、截止时间、下一步？
- **查看者/只读**：是否只读？是否有说明？导出/分享是否被正确禁用？

同时检查：不同角色的首页是否分叉（结果层/过程层/执行层），还是所有人靠手筛同一套仪表盘。

额外：

- 新成员（无项目授权）。
- 跨项目/跨空间成员。
- 被归档项目的成员。
- 无数据的新用户（首屏是否有引导）。

只读检查重点：**隐藏 vs 解释**。按钮消失但没有任何说明，是问题；禁用+原因，或只读横幅，才是答案。

## 6. 状态矩阵

每个关键页面至少抽查以下状态，不能只截默认态：

| 状态 | 看什么 |
|---|---|
| 首次加载 | 骨架/进度，是否永久骨架 |
| 切换筛选/分页 | 是否保留内容、是否有 busy、是否闪空 |
| 空数据 | 图标、原因、下一步、是否与筛选空区分 |
| 筛选无结果 | 清空入口、文案、是否保留筛选条 |
| 错误 | 原因、重试、是否保留旧内容、是否整页替换 |
| 部分失败 | 批量结果、失败行、是否虚报成功 |
| 只读/无权限 | 说明、禁用、是否仍可触发写操作 |
| 保存中 | 按钮状态、是否可重复提交、离开是否拦截 |
| 冲突 | 409 二选一、是否丢输入 |
| 长文本 | 截断、tooltip、换行、是否撑破布局 |
| 大数据量 | 增量加载、计数、性能、滚动位置 |
| 数据新鲜度 | 上次更新时间、状态变更后是否同步、快照是否标注 |
| 批量执行 | 默认值是否安全、影响数量预览、部分失败结果 |
| 移动端 | 堆叠、触控、溢出、底部遮挡 |
| 深色模式 | 背景、文字、状态色、边框对比 |

## 7. 量化方法

**颜色**

- 用运行时 `getComputedStyle` 取实际值，不要只看源码。
- 统计同屏主色实心按钮数量、语义色种类、0 值染色数量。
- 像素取样得到近似色值时标注「近似」；同时给出占比或出现次数。

**尺寸**

- 间距、字号、圆角、触控目标用 `getBoundingClientRect` 或计算样式。
- 对齐问题用元素左边界/顶边差值说明（如「相差 2px」）。
- 截断用 `scrollWidth > clientWidth` 判断，不只靠肉眼。

**布局**

- 看 1440、1100、900、390 四个宽度；记录是否横向溢出（`document.documentElement.scrollWidth > innerWidth`）。
- 检查固定定位元素是否遮挡内容（底部 Tab、FAB、吸顶栏）。

**样式漂移**

运行：

```bash
node scripts/scan-style-drift.mjs <css-dir> --tokens <tokens.css>
```

关注：

- 令牌外硬编码颜色/字号/圆角的高频值。
- 同一色值多文件重复。
- HTML 内联样式。
- `var(--...)` 与原始值比例。

## 8. 定级与分批

| 级别 | 判定 | 例子 | 节奏 |
|---|---|---|---|
| P0 | 破损、错误、不可完成 | 图表轴错乱、关键文案截断、按钮无响应、浮球重叠、卡片被裁切 | 本周 |
| P1 | 结构、主次、跨页一致 | 双搜索、工具栏过载、状态色过载、主操作颠倒、说明常驻 | 一个迭代 |
| P2 | 打磨 | 对齐、字号、空列、图标位置、文案 | 随功能 |

分批原则：

- 一批只做一类改动（安全/交互/视觉不要混）。
- 前一批回归通过再做下一批。
- 跨后端或改变语义的改动单独成批。
- 用户只说「优化」时，范围是已登记的那条，不扩大。

## 9. 验证清单

实施后至少验证：

- [ ] 逐项对照原型：布局、标签、列头、空态、文案、按钮、脚注。
- [ ] 1440 / 1100 / 900 / 390 无横向溢出，堆叠顺序正确。
- [ ] 深色模式主视图无对比问题。
- [ ] 键盘：Tab 顺序、Esc、Enter、焦点环、弹窗焦点陷阱。
- [ ] 加载/空/错误/只读/长文本/大数据量状态。
- [ ] 真实浏览器控制台零应用错误；接口无非预期 4xx/5xx。
- [ ] 权限：管理员/成员/查看者各走一遍关键路径。
- [ ] 跨视图联动：两个方向的新增/修改/删除/回显。
- [ ] 截图更新，旧截图不残留。
- [ ] 测试数据清理，数据库无残留。
- [ ] 报告写明未提交/未推送/未部署与已知残留。

---

## 10. 报告边界

必须写清：

- 覆盖了哪些页面与状态，哪些没覆盖。
- 截图/数据来自哪个环境、哪个账号、哪个空间。
- 哪些结论是实测，哪些是代码推演，哪些待确认。
- 哪些是产品决策项，不是设计缺陷。
- 未验证的假设与风险。

评审的可信度来自边界，而不是「全都看过了」。
